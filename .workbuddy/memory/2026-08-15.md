- nucleo `matched_items` returns `Item` with only `data`/`matcher_columns` — no `score` field
  (score lives on the private `Match`). Encode relevance as `(max - pos)` from the item's position
  in the matched list; that position IS nucleo's score order.
- frecency `rank()` takes `Vec<(AppEntry, f32)>` now: empty query → frecency primary (+name
  tiebreak); typed query → nucleo score primary, frecency secondary tiebreak (never inverts relevance).

  `chronos_services::applications::frecency::*` is reachable from the app crate.

## T281 gate 8 — restore last valid session on startup (DONE, committed 23bf89f)

Scope narrowed by user to ONLY gate 8 of T281 (live Hyprland acceptance for Slice A):
"restart восстанавливает последнюю валидную session каждого проекта".

### What was broken
- `ChatTab::restore_project_thread` existed but was only called from
  `switch_project` (manual project switch). On every launch `SidePanelLeftState_.active_project_path`
  started as `None`, so a restart opened an empty Chat with a fresh ACP session instead of
  restoring the last valid thread.

### Fix
- New reducer `side_panel_left::restore_active_project_on_startup(cx)` (called from `init`)
  seeds `active_project_path` from persisted `ProjectsConfig.active` (written by
  `project_switcher::set_active` on every project switch). No-op when no active project.
- `ChatTab::new` now calls `restore_project_thread(&active_path, cx)` on construction, so the
  first panel open after restart loads the active project's last valid thread.
- Validation is already in `ThreadStore::active_thread` (id + project_path + archived=0), so
  stale/archived/deleted/cross-project active ids → empty Chat. Covered by
  `threads.rs::active_thread_rejects_stale_archived_deleted_and_cross_project`.

### Test notes (reusable)
- `ChatTab` is UNREACHABLE in `TestAppContext` (spawns async ACP connect) — so test the
  SoT-level reducer (`restore_active_project_on_startup` sets `active_project_path`), not the
  chat load. Added `set_cached_for_test` (cfg(test)) to `project_switcher` to seed the
  in-memory `CONFIG_CACHE` WITHOUT writing `projects.toml` (writing it would clobber the user's
  real config). That OnceLock cache is process-wide, so seed BEFORE `init` in each test.
- Pure reducer tests pass; `cargo test -p chronos --lib --bins` 472+667 green; release build ok.
