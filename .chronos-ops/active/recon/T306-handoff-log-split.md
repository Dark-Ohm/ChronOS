# T306 — RECON: разрезать `checkpoint/log/handoff.log` на несколько файлов

**Роль: RECON** (архив и документы, не продуктовый код). Прецедент —
T299 (разметка 167 архивных тикетов), та же природа работы: читать,
классифицировать, аккуратно двигать, ничего не потерять.

**Приоритет:** P3. Никого не блокирует, но чем дольше тянем, тем дороже.

## Контекст

`.chronos-ops/checkpoint/HANDOFF.md` был журналом-кирпичом на 3973 строки —
файл, объявленный «первым чтением каждой сессии», который физически никто
не читал целиком. 2026-08-18 он разрезан архитектором на два:

- `.chronos-ops/checkpoint/HANDOFF.md` — **состояние** (191 строка,
  переписан с нуля, живёт в пределах ~200 строк);
- `.chronos-ops/checkpoint/log/handoff.log` — **журнал** (3995 строк,
  старое содержимое дословно + архивная шапка).

Журнал по-прежнему нечитаем: 3995 строк, порядок внутри — обратно-
хронологический сверху и мешанина ниже, записи за 2026-07-16…2026-08-18.
Твоя задача — разложить его на файлы, по которым можно ориентироваться.

**Структура исходника, замерено:**
- 57 маркеров записей вида `**Обновлено: <дата> …**` / `**Чекпоинт #NN …**`
  (строка начинается с `**`);
- 54 заголовка уровня `##`/`###` (датированные разделы вроде
  `## Живая приёмка 2026-07-19`, `### Где стоим (2026-07-30, вечер)`);
- 31 разделитель `---`;
- строки 1–~1310 — плоский блок без заголовков, режется только по
  `**Обновлено:` / `**Чекпоинт`;
- ниже — разделы с заголовками, датированные в самих заголовках.

## Задача

Разрезать `handoff.log` на файлы **по месяцу записи** и собрать индекс.

### Целевая раскладка

```
.chronos-ops/checkpoint/log/
├── INDEX.md                 ← новый, навигация
├── handoff-2026-07.log      ← записи июля
├── handoff-2026-08.log      ← записи августа
└── handoff-undated.log      ← только если есть блоки без даты (см. ниже)
```

Исходный `handoff.log` после разрезки **удаляется** (`git rm`) — дубля не
держим. Все три-четыре файла остаются в `checkpoint/log/`.

### Правила разрезки

1. **Единица переноса — блок целиком.** Блок = маркер записи (`**Обновлено:`
   / `**Чекпоинт`) или заголовок `##`/`###` плюс весь текст до следующего
   маркера/заголовка того же или высшего уровня. Не резать блок пополам,
   даже если внутри упомянуты две даты.
2. **Дата блока — из его собственной шапки**, а не из соседей и не из
   упоминаний внутри текста. `### Где стоим (2026-07-30, вечер)` → июль.
   `**Чекпоинт #35 (2026-08-17) …**` → август.
3. **Если даты в шапке нет** — взять дату ближайшего вышестоящего
   датированного блока и **пометить это в INDEX.md** («дата унаследована»).
   Если и так не определяется — в `handoff-undated.log`. Не угадывать по
   содержанию.
4. **Текст блоков не править вообще.** Ни опечатки, ни пути, ни
   форматирование, ни «протухшие» ссылки. Это исторический слепок; правка
   истории — отдельное решение архитектора. Единственное разрешённое
   изменение — шапка файла (п.5).
5. **Шапка каждого файла** — 5–8 строк: что это, за какой период, что
   правки истории запрещены, что при расхождении побеждает
   `checkpoint/HANDOFF.md`. Архивную шапку исходного `handoff.log`
   (первые ~25 строк, от `# handoff.log —` до первого `---`) не
   размазывай по файлам — её содержание переезжает в `INDEX.md`.
6. **Порядок внутри файла — хронологический, от старого к новому.** Сейчас
   в исходнике он перевёрнут и местами перемешан; выпрямление — часть
   задачи, но только перестановка целых блоков, без правки текста.

### INDEX.md

Точка входа в каталог. Содержит:
- одну строку о том, что это архив и первое чтение — `checkpoint/HANDOFF.md`;
- таблицу файлов: файл | период | строк | о чём (одна фраза);
- **карту T-ID → файл**: для каждого T-номера, упомянутого в журнале,
  строка `T265 → handoff-2026-08.log`. Собери грепом
  (`grep -oE '\bT[0-9]{3}[A-Za-z-]*\b'`), не руками; если T-ID встречается
  в обоих месяцах — перечислить оба файла;
- список сквозных тем с указанием файла: «системный баг `remove_window`»,
  «ACP live smoke», «лаунчер T265», «кухня/миграция», «блюр и surface».

## Верификация (обязательна, без неё отчёт не принимается)

1. **Ни строки не потеряно.** Сложи содержимое всех результирующих
   `.log`-файлов **без их новых шапок**, отсортируй, сравни с
   отсортированным исходником без его архивной шапки — diff пустой.
   Команду и её вывод приведи в отчёте дословно.
2. **Счётчик строк** сходится: сумма строк файлов минус сумма шапок =
   строки исходника минус его шапка. Числа в отчёте.
3. **T-ID не потерялись:** `grep -oE '\bT[0-9]{3}' | sort -u` по исходнику
   и по объединению результата — списки идентичны. Если что-то разошлось,
   это баг разрезки, а не «мелочь».
4. Ни один блок не разорван: в результирующих файлах нет висящих кусков
   без шапки/заголовка.

## Зона файлов

Только `.chronos-ops/checkpoint/log/`. **Не трогать**
`checkpoint/HANDOFF.md`, остальной канон, тикеты, отчёты, код. Ссылки на
`checkpoint/log/handoff.log` в других файлах (`CLAUDE.md`, `.rules`,
`.chronos-ops/README.md`, `checkpoint/ARCHITECT.md`,
`checkpoint/HANDOFF.md`) **перевешивает архитектор после приёмки** — сам
их не правь, просто перечисли в отчёте, что найдено грепом.

## Коммит

Один коммит, поимённый `git add`. Сообщение в стиле репозитория:
`handoff : журнал разрезан по месяцам, добавлен INDEX`. Без AI-трейлеров
(ни `Co-Authored-By`, ни `Assisted-by`).
