# T349 — BACKEND: диспетчер обоев на пять движков (HOLD до T348)

**Статус:** HOLD — не выдавать, пока T348 (RECON) не принят. Этот бриф
специально написан без точных команд движков: их даст T348, не гадать
заранее.
**Роль:** BACKEND. **P2.** Родитель T338/T339, канон —
`.chronos-ops/checkpoint/ARCHITECTURE.md` §19 (2026-08-22).
**Зона:** `crates/services/src/wallpaper/mod.rs`,
`crates/services/src/wallpaper/types.rs`. Вероятно `wallpaper_ctl.rs`
(T339 `next()`/`is_video` теперь должны реально уметь video через
mpvpaper, не только сообщать «videos skipped») — зона уточнится по факту
T348.
**Не трогать без явной причины:** `FOREIGN_BACKEND_BINS`/`ensure_daemon`
startup-guard (T338) — детект «чужого» процесса на старте остаётся
нужен независимо от диспетчера (не спавнить awww поверх уже
управляемого нами же mpvpaper).

## Зачем

`Backend` enum (`types.rs:13`) с 2026-08-22 не «awww + плейсхолдеры», а
контракт: все пять движков реально поддержаны. Сейчас управляется
только awww; остальные четыре только детектятся по имени процесса
(T338), но не driveable — ни Set, ни Next, ни query.

**Конечная цель (владелец, 2026-08-22): отказаться от `waytrogen` как
внешнего приложения.** Этот тикет — не финал, а фундамент: после него
заводится FRONTEND-тикет на собственный компонент галереи в
Display-вкладке (превью, выбор монитора, переключение движка), который
заменит кнопку «Open waytrogen» (`display.rs:455-480`) и снимет
зависимость `WAYTROGEN_BIN`/`waytrogen_available`/
`open_waytrogen_gallery*`/CTA «yay -S waytrogen» (`wallpaper_ctl.rs`,
`display.rs`, `system.rs`) целиком. Не делать этот вынос здесь — только
диспетчер, на который та галерея потом ляжет.

## Что сделать (уточнить после T348)

1. Command builder per-backend: `apply_command`-эквивалент для каждого
   из hyprpaper/swaybg/mpvpaper/gslapper, используя ТОЧНЫЕ команды из
   отчёта T348 (не изобретать заново).
2. Выбор активного бэкенда: либо конфиг (`[wallpaper] backend = "..."`,
   паттерн `theme_config`/`bar` config), либо автодетект живого движка
   при старте (расширение той же логики, что уже даёт `daemon_alive`/
   `foreign_backend_alive` из T338) — **архитектору согласовать который**,
   не решать в одиночку на этапе кода.
3. `wallpaper_ctl::next()` (T339) при активном mpvpaper должен реально
   ротировать video-файлы через его Set, а не только считать их и
   показывать «skipped» — сообщение из T339 (`refusal_message`) остаётся
   для случая, когда активный бэкенд ДЕЙСТВИТЕЛЬНО не может показать то,
   что есть в папке (например смешанная папка и картинки закончились).
4. `WallpaperState.backend`/`per_monitor` — синхронизировать с реальным
   активным движком, не только `Backend::Awww` по умолчанию.
