# T308 — wrap-матте съезжает, когда открыта боковая панель (живая находка владельца)

**Роль:** FRONTEND. **Приоритет:** P0 (регресс на кровном факте T303,
принятого несколько часов назад). **Зона:** `crates/app/src/frame.rs`
(`wrap_window_options`, вокруг frame.rs:588-680).

## Контекст

Владелец прислал живой скрин своего рабочего wrap-шелла (стиль `wrap`,
`thickness=16`, `inner_radius=16`, `~/.config/chronos/frame.toml`) с левой
панелью открытой (`side_panel_left_rail` замаплен). Архитектор сверил
`hyprctl layers -j` на этом же живом PID (660076, чужая сессия — трогать
её саму не пришлось, только читал):

```
frame_wrap_matte:        x=56,   y=0,  w=2560, h=1440
frame_wrap_excl_left:    x=0,    y=15, w=16,   h=1440
side_panel_left_rail:    x=32,   y=30, w=40,   h=1394   (своя exclusive_zone, отдельно от frame.rs)
```

Матте должна быть `x=0` (полноэкранная, левый край flush) — T303 это и
проверял живым grim. Но с открытой левой панелью Hyprland сдвигает
`LEFT`-якорь на **56px = 40 (резервация рейла) + 16 (резервация
`frame_wrap_excl_left`)** — компенсирующий `margin.left = -inset` (T303)
считает только СВОИ 16px, не резервацию соседнего сёрфейса. Матте той же
ширины (2560), просто сдвинутая на 56px вправо — правая граница/кольцо
(`border`) уезжает за экран (56+2560=2616 при ширине экрана 2560),
**правое кольцо визуально не рисуется вовсе**. Слева — 56px голых обоев
до начала матте (в основном скрыто под самим рейлом, поэтому визуально
менее заметно, но структурно то же смещение).

## Подозреваемый корень (проверить в первую очередь)

Матте задаёт `exclusive_zone: None` (frame.rs, `WrapRole::Matte`-ветка
`wrap_window_options`, 5-й элемент кортежа). Это **не то же самое**, что
явный opt-out `Some(px(-1.))` — T305 уже наступал на эти грабли для
control-center popup (см. `MIGRATION.md` T305, кровный факт
`exclusive_zone: Some(px(-1.))`, `control_center.rs:141`): без явного
`-1` компositor всё равно учитывает резервации соседних поверхностей при
позиционировании anchor-only (не exclusive) слоя. Проверить: заменить
`None` → `Some(px(-1.))` на матте, живой grim с открытой И закрытой левой
панелью — если гипотеза верна, x матте станет 0 в обоих случаях.

Если `-1` не решает — тогда придётся разбираться, почему Hyprland вообще
суммирует резервацию рейла (у него своя, независимая `exclusive_zone`) с
резервацией `frame_wrap_excl_left` при расчёте LEFT-anchor placement для
третьего, невовлечённого сёрфейса (матте) — читать live-поведение
`zwlr_layer_shell_v1` в Hyprland, не гадать по памяти T303-отчёта.

## Верификация (обязательна, живая — это визуальный баг)

1. Стиль `wrap` в `~/.config/chronos/frame.toml` (уже так стоит).
2. Живой grim с **закрытой** левой и правой панелью — матте `x=0`,
   кольцо видно на обоих боках (это должно было работать и до фикса).
3. Открыть левую панель (`chronos-ipc toggle-side-panel-left`) —
   `hyprctl layers -j` на `frame_wrap_matte` → `x` должен остаться `0`.
   До фикса: `x=56`.
4. Повторить с правой панелью (`toggle-side-panel-right`) — проверить
   симметричный сдвиг по правому краю (правая резервация рейла).
5. Обе панели одновременно — проверить, что смещения не удваиваются
   криво.
6. `cargo test -p chronos --lib frame` — не сломать существующие 17
   тестов геометрии.

## Не трогать

- `wrap.thickness`/`inner_radius` логику (T303 закрыт, она верна для
  случая без открытых панелей — там живой grim совпал).
- Rail/side_panel exclusive_zone код — предполагаемый фикс только в
  `wrap_window_options`, не в `side_panel_left`/`side_panel_right`.
