# T314 — живая эксклюзивная зона wrap-полос: рельс становится кромкой кадра

**Роль:** FRONTEND. **Приоритет:** P1.
**Зона:** `crates/app/src/frame.rs`. Точечно —
`crates/app/src/side_panel_left/mod.rs`,
`crates/app/src/side_panel_right/mod.rs` (только `content_window_margin`,
если промер покажет расхождение).
**Не трогать:** `crates/app/src/bar/**`, `crates/ui/**`, `FrameStyle` и
`deserialize_style` (это T312), рендер самих рельсов (это T315).

Прямое продолжение T311 — его шаг D3 был правильным по замыслу и
сломанным в реализации. T311 принят с этим остатком, вынесенным сюда.

## Решение владельца, которое реализуем

Край оболочки в режиме `wrap` ведёт себя так:

- **рельс спрятан** → на этом крае кольцо толщиной `wrap.thickness`
  (16 по дефолту), контент начинается с 16;
- **рельс показан** → рельс САМ является кромкой кадра: стоит на `x=0`
  (левый) / вплотную к правому краю, шириной `RAIL_WIDTH` (40),
  кольца на этом крае нет, контент начинается с 40.

Апертура при переключении сдвигается на 24px (40 − 16). Это принято
осознанно — кадр отдаёт место панели, а не рисует её поверх себя.

Побочно возвращается ещё 16px ширины: сегодня при открытом рельсе
контент начинается с 56.

## Что сломано сейчас

`WrapSurfaceView::render` (`frame.rs`, ветка `WrapRole::Matte`) честно
читает `wrap_inset_left(&cfg, rail_mapped(FrameSide::Left))` и перестаёт
красить край, когда рельс маплен. А полоса `frame_wrap_excl_left`
создаётся один раз в `wrap_window_options` и **свою эксклюзивную зону
больше никогда не меняет** — `apply_wrap` пересоздаёт wrap-набор только
по `wrap_geometry_changed` (сравнение `WrapConfig`), а маппинг рельса
`WrapConfig` не меняет.

Результат: полоса продолжает резервировать 16px и держит рельс на x=16,
а матте эти 16px уже не красит. Матте и резервация разошлись — ровно тот
дрифт, который чинил T303.

Проявляется не сразу, а на первой перерисовке матте. Измерено живьём
2026-08-19, один и тот же открытый левый рельс, строка y=700, белые
обои под тёмной темой:

```
сразу после chronos-ipc toggle-side-panel-left:
  0   (24,24,37)     плита
  55  (69,71,90)     бордер
  56  (255,255,255)  контент

после chronos-ipc toggle-theme ×2 (любая перерисовка):
  0   (255,255,255)  ОБОИ  ← 16px голых обоев у края экрана
  16  (24,24,37)     рельс
  55  (69,71,90)     бордер
  56  (255,255,255)  контент
```

`hyprctl layers` в обоих случаях одинаков:
`frame_wrap_excl_left 0 15 16 1440`, `side_panel_left_rail 16 30 40 1404`.

## Как чинить — и как НЕ чинить

**НЕ пересоздавать wrap-поверхности на смене маппинга.** Исполнитель
T311 попробовал именно это, получил от Hyprland `Protocol error
invalid_object` на каждый тогл (в логе по 4 ошибки на `wl_surface`,
поверхности больше не открывались), откатился и оставил 76 строк мёртвой
инфраструктуры. Не повторять этот путь.

**Менять зону на живой поверхности.** API в форке есть и работает:
`Window::set_exclusive_zone` — `Source/gpui/src/window.rs:2005`. В дереве
он уже вызывается вживую в пяти местах, бери их как образец:

- `crates/app/src/bar/mod.rs:649` и `:651`
- `crates/app/src/side_panel_right/rail_view.rs:74`
- `crates/app/src/side_panel_right/mod.rs:552`, `:632`, `:639`

Размер самой поверхности менять не нужно: полоса ничего не рисует
(`render` для не-Matte ролей возвращает пустой `div().size_full()`) и не
берёт ввод (`window.set_input_region(Some(&[]))`). Достаточно менять
число зоны — это легально по wlr-layer-shell и уже задокументировано в
`side_panel_right/mod.rs:272` («exclusive zone is a *value*, independent
from the surface's own pixel footprint»).

Ход работ:

1. В `apply_wrap` добавить второй сигнал рядом с `wrap_geometry_changed`:
   маппинг рельсов. Заготовка уже лежит в дереве —
   `LAST_RAIL_MAPPING` (`frame.rs:921`), `wrap_rail_mapping()`,
   `wrap_rail_mapping_changed()`. Сейчас значение пишется и **никогда не
   читается для решения**, а комментарий на `frame.rs:910-920` описывает
   поведение, которого в коде нет. Либо дай этому коду работу, либо
   удали вместе с тестом `wrap_rail_mapping_changed_only_on_actual_edit`
   — мёртвой инфраструктуры «на будущее» в дереве не оставляем.
2. При смене маппинга — НЕ `close_wrap_windows`, а проход по живым
   хендлам `wrap_windows()` и `window.set_exclusive_zone(px(inset))` для
   `ExclLeft`/`ExclRight` с новым значением
   `wrap_inset_left/right(&cfg, rail_mapped(...))`.
3. Тем же сигналом заставить матте перерисоваться (`cx.notify()` на
   entity матте или `cx.refresh_windows()`), чтобы закраска и резервация
   менялись одним кадром, а не по разным поводам.
4. Проверить `content_window_margin` в обеих панелях: он считает
   `RAIL_WIDTH + wrap_inset_{left,right}_cached(rail_mapped(...))`
   вручную, потому что окно контента опт-аутится через
   `exclusive_zone: -1`. После фикса при открытом рельсе это должно
   давать 40, а не 56. Если промер покажет иное — править здесь,
   но НИЧЕГО больше в панелях не трогать.

**Реентерабельность.** Обновление зоны идёт через
`handle.update(cx, ...)`. Не вызывать его из колбэка самого этого окна —
`ARCHITECTURE.md §4.1`, сага ghost-window 2026-07-18. И не глушить
результат через `let _ =` — либо `?`, либо `.log_err()`, либо явный
`match`. Именно проглоченный `Err("window not found")` был корнем той
саги.

## Верификация — живая, обязательная

```bash
cargo build --release --bin chronos
magick -size 2560x1440 xc:white /tmp/t314-white.png
awww img -o DP-1 --transition-type none /tmp/t314-white.png
RUST_LOG=info ./target/release/chronos > /tmp/t314/log 2>&1 &
```

Промер (вставить дословный вывод в отчёт, оба состояния):

```bash
hyprctl layers | grep -E "frame_wrap|side_panel_(left|right)_(rail|content)"
grim -o DP-1 /tmp/t314/shot.png
magick /tmp/t314/shot.png -crop 2560x1+0+700 +repage txt: \
  | awk 'NR>1{split($0,a,":");split(a[1],p,",");split(a[2],c," ");
           if(c[1]!=q){print p[1], c[1]} q=c[1]}'
```

Критерии приёмки:

1. **Рельс спрятан:** `x=0..15` — цвет плиты, `x=16` — обои.
   `frame_wrap_excl_left` зона 16.
2. **Рельс показан:** `x=0..39` — рельс, `x=40` — контент/обои.
   Между ними НЕТ ни одного пикселя обоев. `frame_wrap_excl_left` зона 0,
   `side_panel_left_rail` на `x=0`.
3. **Правый край** — зеркально, оба состояния.
4. **Переключение туда-обратно пять раз** — геометрия каждый раз та же,
   `hyprctl layers` без осиротевших `frame_wrap_*`,
   `grep -c 'Protocol error' /tmp/t314/log` = **0**. Это главный
   критерий: именно здесь утонул предыдущий заход.
5. **Устойчивость к перерисовке:** в состоянии «рельс показан» дёрнуть
   `chronos-ipc toggle-theme` дважды и промерить снова. Картинка обязана
   быть той же. Это тот самый дефект, ради которого заведён тикет —
   проверять обязательно, не «по аналогии».
6. Обе темы, оба контрастных фона (белые обои под тёмной, чёрные под
   светлой).
7. `cargo test -p chronos --lib` зелёные. Если решил дать работу
   `wrap_rail_mapping_changed` — тест на него должен проверять реальный
   переход, а не `!=` двух `u8`.
