# T352 — BACKEND: swaybg — живой Set, не только argv-юнит

**Роль:** BACKEND. **P2.** Дочерний T349 (принят 2026-08-22, канон —
`.chronos-ops/checkpoint/ARCHITECTURE.md` §19). Отчёт T349 честно раскрыл:
swaybg собран (`crates/services/src/wallpaper/backends.rs`
`swaybg_argv`/`apply_swaybg`) и юнит-протестирован (2 теста: All без
`-o`, один монитор с `-o`), но живьём НЕ гонялся.
**Зона:** только живая проверка + фикс багов — код `apply_swaybg` уже
написан в T349, не переписывать с нуля.
**Не параллелить с T351/T353** — один файл (`backends.rs`), делать
последовательно.

## Зачем

swaybg — restart-based (`pkill -9 swaybg` + один новый процесс), в
отличие от T349-кода **НЕ портирован** waytrogen'овский per-monitor
реестр (`SWAYBG_WALLPAPERS`, пересборка всех блоков `-o/-i/-m/-c` в один
процесс при смене одного монитора — см.
`.chronos-ops/reports-log/recon/T348-wallpaper-backend-control-surfaces-report.md`
раздел «swaybg»). ChronOS-версия `apply_swaybg` шлёт только текущую
команду в один `swaybg_argv` — **если это Set на одном мониторе, а до
этого уже был Set на другом, второй Set убьёт первый процесс и запустит
новый БЕЗ старого монитора** (в отличие от waytrogen, который
пересобирает все известные мониторы). Это разница в поведении, которую
надо подтвердить живьём и решить, важна ли она (при одном мониторе не
проявится вовсе).

## Что сделать

1. Живой Set на «All» — один процесс, без `-o`.
2. Если на машине больше одного монитора: живой Set на конкретном
   мониторе, затем Set на ДРУГОМ мониторе — проверить, остаётся ли
   картинка на первом (waytrogen сохранил бы её через реестр; ChronOS
   T349-код, вероятно, её теряет). Зафиксировать факт, не чинить молча —
   если поведение разошлось с waytrogen, решение (портировать реестр или
   принять регресс для мультимонитора) за архитектором.
3. Доказательства: `pidof swaybg`, `grim` кадр(ы), лог.
4. `cargo test -p chronos-services wallpaper` зелёный.

## Готово когда

Живой swaybg-Set подтверждён кадром на «All»; если мониторов ≥2 —
задокументирован факт про потерю картинки на другом мониторе при
повторном point-Set (или подтверждено, что реестр всё же держит её —
тогда просто закрыть без правок); тесты зелёные.
