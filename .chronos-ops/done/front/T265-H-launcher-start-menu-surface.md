## Сдача слоями (тикет уже в работе — не пилить на три)

Мокап толстый. Приёмка **не** требует весь HTML в одном коммите.
Сдать ядро, остальное честно в «не сделано» — заведу H2/H3, не отклоню H.

1. **Ядро (обязательно, без этого не H):** Overlay, закрыть левую панель,
   `dock-start` открывает меню а не OSD, две колонки, поиск, сетка All Apps
   из общей модели, Esc/Enter/стрелки, launch+close. Никто не кроет меню.
2. **Рейл (можно не в этом коммите):** Pinned / Recent / Files / категории
   T297 + крошки. Заглушки «скоро» не рисовать — пункта нет, пока нет кода.
3. **Футер (можно не в этом коммите):** аватар + 5 power из F. Без картонок
   кнопок без бэкенда (T246).

Не бросать ядро недоделанным ради рейла. Не плодить второй индекс.

## Зачем

Сейчас Start-кнопка в баре (`bar/widgets/dock.rs`, `id="dock-start"`) просто
вызывает `crate::launcher::toggle(cx)` — открывает тот же OSD-лаунчер, что и
SUPER+R. Эпик требует вторую поверхность: компактное меню «Пуск»,
раскрывающееся от кнопки. Обе поверхности живут параллельно и делят одну
модель данных, один индекс, один конфиг и один frecency. Это единственная
волна, куда ложится требование «две поверхности»: резать H = резать ключевое
требование эпика, а не косметику.

## Зависимости (жёсткие)

1. **T280 — принят.** Ради этой зависимости волна и выделена отдельным
   тикетом. Start-кнопка живёт в `bar/widgets/dock.rs`, а T280 в том же
   каталоге (`bar/widgets/mod.rs`) вырезает `project`. Старт до приёмки T280
   даёт несамодостаточный коммит в shared-файле (в проекте таких уже три).
2. **T265-A — закоммичен.** Меню «Пуск» пользуется тем же поиском и frecency,
   что OSD-лаунчер; ранжирование должно уже лежать в модели.
3. **T265-B — закоммичен.** Grid-примитивы и навигация по списку/сетке.
4. **T265-C — опционально.** Верхняя секция recents/favorites, если включаем
   её в компактное меню сразу; иначе — позже, не блокер.
5. **Мокап — есть.** `docs/design/chronos-start-menu.html`. Не клонировать
   OSD-карточку и не импровизировать Kickoff.

## Канон (мокап, пиксель в пиксель по раскладке)

`docs/design/chronos-start-menu.html` — две колонки, не OSD-карточка.

- Ширина `min(720px, 94vw)`, рейл **210px**, сетка `auto-fill` min **84px**.
- Рейл: Places (All Apps / Pinned / Recent / Files) + Categories (только
  Main из T297, короткие лейблы: Dev←Development, Web←Network,
  Productivity←Office, Media←AudioVideo, плюс System / Utility / Game;
  пустые не показывать) + футер: аватар/имя/хост (T265-F) и 5 кнопок
  power — Lock, Suspend, Log Out, Restart, Shut Down. Hibernate в мокапе
  нет — не рисовать. Logout/Restart/Shutdown — arm/confirm как F.
- Main: kit `Input` «Search applications…», крошки, скролл-сетка
  (иконка 34 + имя). Pinned = `favorites.order`. Recent = frecency recents.
- Files в рейле: empty-state «Open the File Manager…» + Enter/клик →
  `select_tab(Files)` (или дефолтный FM). Не файловый браузер внутри меню.
- User card — display-only (профиля в ките нет). Toast «launching…» из
  мокапа **не** делать: launch + close, как OSD.
- **Якорь:** бар ChronOS сверху, кнопка слева (`dock-start`). Меню
  открывается **вниз** от кнопки. Мокап стоит снизу экрана как у Windows
  — это сцена, не геометрия Hyprland. Не сажать меню в низ монитора.
- Палитра мокапа (`--bg #181825`, `--accent #007acc`) — токены темы,
  не хардкод.

Модель/индекс/конфиг/frecency общие с OSD. Клавиатура: Esc **закрывает
меню** (в HTML-мокапе Esc только чистит поиск — в продукте иначе),
Enter запускает, стрелки по сетке.

`on_click` `dock.rs:86` — открыть это меню, не `launcher::toggle`.
SUPER+R по-прежнему OSD.

## Слой — ничего не перекрывает «Пуск»

Как у Windows / KDE Kickoff / GNOME: меню «Пуск» выше тайлов, флоатов и
наших панелей. Не «обычно сверху» — **никогда не под чужой поверхностью**.

Почему голого `AnchoredPopup` от бара мало: бар — `Layer::Top`, левая и
правая панели — `Layer::Overlay`. Overlay выше Top. Меню у левой кнопки
падает ровно в колонку чата. `grab: false` обязателен (T264, Hyprland
съедает сиденье). Exclusive zone на меню — нельзя (панели так пробовали,
окна дёргаются, откатили).

Рецепт:

1. Само меню — `Layer::Overlay` (xdg-popup, родитель которого Top-бар,
   панелями накрывается).
2. В `open` закрыть левую панель (`side_panel_left::close`). Правую —
   если её геометрия пересекает меню. Не оставлять два Overlay в одном
   прямоугольнике и не гадать z-order.
3. `grab: false`. Dismiss свой: клик мимо / Esc / повторный клик Start /
   запуск приложения.
4. Live: открыть левую панель → клик Start → меню видно целиком,
   чат не рисуется поверх. `hyprctl layers` — меню выше/вместо панели
   в этом прямоугольнике. Тот же кадр с открытым обычным оклом под меню.

Не чинить «поднять z-index попапа бара» — у wlr-layer-shell нет слоя
выше Overlay.

## Не входит

- Категории, папки, drag-n-drop избранного — это B/C, в компактное меню
  переносятся по готовности, а не переделываются заново.
- OSD-лаунчер не трогаем (кроме реюза его модели).

## Верификация

Живой прогон обязателен: клик по Start открывает меню у кнопки (`grim`);
поиск находит и запускает; Esc/Enter/стрелки; OSD и «Пуск» не расходятся
по избранному. **Слой:** левая панель открыта → Start → меню целиком
видно, панель его не кроет; обычное окно под меню тоже не кроет.
`hyprctl layers` + кадр. `cargo test -p chronos --lib --bins` без регресса.

`launcher : меню «Пуск» — вторая поверхность на AnchoredPopup, общая модель (T265-H)`
