# T246 — убрать/заменить фейковый permission-мок с дефолтного System-таба

**Приоритет:** P0 — прямое нарушение теста доверия продукта, на первом
экране, в обеих темах, всегда (не hover, не edge-case).
**Роль:** FRONTEND (Rust, GPUI), минимум кода.
**Источник:** `docs/orchestration/tasks/report-log/T223-design-audit-report-v4-reshoot.md`
находка #1 (табл. §3), топ-10 п.1.

## Контекст

`crates/app/src/side_panel_right/permission.rs:1` — дословно:
*«Static permission card (Claude Code mock) — no backend wiring.»*
`render_permission_card()` (тот же файл) рендерит карточку «Claude Code
needs your permission to run a command» с кликабельными Allow/Deny —
визуально неотличима от настоящего системного permission-попапа, но
architecturally ничего не делает при клике (нет backend wiring).
Подключена **безусловно** в `crates/app/src/side_panel_right/tab/system.rs:17,139`
— рендерится на дефолтной System-вкладке (первый экран после открытия
правой панели) в обеих темах, всегда, не за флагом.

Живой пользователь подтвердил: «этот alloy deny он персистентен там как
недоделка, всегда перед глазами». Аудит классифицирует это как активно
вводящий в заблуждение элемент (не "недоделанная фича" — пользователь,
не знающий, что это мок, увидит «AI просит разрешение выполнить
команду» на дефолтном экране десктопного шелла и обоснованно
испугается), это решает тест доверия раньше, чем начнётся разговор про
grid и отступы.

## Что нужно

Убрать `render_permission_card()` из `system.rs:139` **совсем** —
не прятать за debug-флагом с тем же кликабельным видом (сама
кликабельность без действия — обман, см. находку дословно). Варианты,
любой приемлем:
1. Просто удалить `.child(render_permission_card(cx))` (строка 139) и
   импорт (строка 17). Если `permission.rs` целиком становится мёртвым
   кодом — удалить файл, вычистить `mod permission;` из
   `side_panel_right/mod.rs`.
2. Если карточка задумана как будущая витрина реального ACP
   permission-флоу (когда бэкенд появится) — оставить файл, но заменить
   рендер на честную некликабельную заглушку («Coming soon» / статичный
   текст без Allow/Deny кнопок с hover-стилями) — не обязательно, но
   допустимо, если пользователь при приёмке это предпочтёт.

**Не решать за пользователя, какой вариант** — если неочевидно, спросить
прямо перед тем как удалять файл целиком (не отслеженный файл — не
проблема, он в git, откатится).
