# T312 — два режима оболочки: `normal` / `wrapped`

**Роль:** FRONTEND. **Приоритет:** P2.
**Зона:** `crates/app/src/frame.rs` (энум `FrameStyle`, `deserialize_style`,
`FrameJunction`, `apply`/`apply_hide`/`apply_wrap`, тесты в том же файле).
**Не трогать:** `crates/ui/**`, `crates/services/**`, панели
(`side_panel_left/`, `side_panel_right/`), бар.

**ЗАБЛОКИРОВАН T311.** Не начинать, пока T311 не принят: он меняет
семантику толщины плиты по краям, и `normal` в этом тикете определяется
через неё. Начнёшь раньше — переделывать оба.

**Канон решения:** `.chronos-ops/active/design/T310-wrap-mode-invisible-and-mocha-mousse-palette.md`,
раздел **I** дополнения (после разделителя `---`). Тело исходного брифа
T310 написано до перепромера и его выводы отменены — не читать его как
руководство.

## Зачем

Сейчас у рамки два стиля с невнятными именами и пересекающейся
семантикой: `Hide` (рисует тонкую нижнюю планку между рельсами) и
`Wrap` (полноэкранная плита-паспарту). Владелец хочет ровно два режима
с честными именами:

- **`normal`** — оболочки нет. Хром прижат к краям экрана, плиты не
  существует, инсетов нет. Бар `y=0` во всю ширину, левый рельс
  `x=0..39`, правый `x=2520..2559`, углы прямые, нижней планки нет,
  обои начинаются сразу за рельсами. Режим для тех, кто хочет каждый
  пиксель под окна.
- **`wrapped`** — единая оболочка с апертурой: результат T311.
  Непрерывная плита, толщина краёв по функции, скруглённая апертура.
  Режим-витрина.

## Что сделать

### 1. Переименование энума

`FrameStyle { Hide, Wrap }` (`frame.rs:~104`, дефолт `Hide`) →
`FrameStyle { Normal, Wrapped }`, дефолт `Normal`.

Соответственно `apply_hide` → `apply_normal`, `apply_wrap` →
`apply_wrapped`, `STYLE_ID_HIDE`/`STYLE_ID_WRAP` (`frame.rs:760`) —
по смыслу. Ветвление в `apply` (`frame.rs:~868`) переименовать
механически.

### 2. Алиасы в разборе конфига — КРИТИЧНО

`deserialize_style` парсит стиль **из строки вручную**, а не через
`#[derive(Deserialize)]`, именно потому, что на неизвестном значении
дерайв роняет разбор всего файла и `load()` молча заменяет конфиг
дефолтами. Комментарий об этом висит прямо в коде, `frame.rs:97-101`,
это инцидент T268.

Значит:

- `"normal"` → `Normal`, `"wrapped"` → `Wrapped` (новые имена);
- `"hide"` → `Normal`, `"wrap"` → `Wrapped` (**алиасы, обязательны**).
  У владельца в `~/.config/chronos/frame.toml` сейчас лежит
  `style = "wrap"` вместе с рабочими толщинами и радиусами. Уберёшь
  алиас — конфиг схлопнется в дефолты целиком, вместе со всей
  геометрией, и без единой ошибки в логе;
- регистр не важен (сейчас разбор уже нечувствителен — сохранить);
- неизвестное значение → дефолт + `tracing::warn!`, но **остальные
  поля конфига обязаны сохраниться**.

Тесты (в том же файле, рядом с существующими):

- `"normal"` / `"wrapped"` дают правильный вариант;
- `"hide"` / `"wrap"` дают правильный вариант (тест на алиасы);
- `"WRAP"` / `"Wrapped"` — регистр;
- мусорное значение (`style = "banana"`) даёт дефолт И сохраняет
  `wrap.thickness` / `bottom_strip.height` из того же TOML-текста —
  это главный тест, ради него всё и делается;
- отсутствующий ключ `style` даёт дефолт.

### 3. Нижняя планка переезжает под `wrapped`

Сегодня нижнюю планку рисует режим `Hide`: `DEFAULT_HEIGHT = 4.0`
(`frame.rs:54`), `BottomStripConfig`, `FrameJunction`
(`Flush`/`Break`/`Rounded`, `frame.rs:~75-90`), `hide_strip_insets`
(`frame.rs:348`), `hide_strip_wanted` (`frame.rs:357`),
`BottomStripView` (`frame.rs:389`).

В новой схеме планка — это **нижний край плиты**, то есть часть
`wrapped`, а не самостоятельная сущность. В `normal` её нет вовсе.

- `FrameJunction` применяется только в `wrapped`;
- поля `[bottom_strip]` из конфига **не удалять** — они должны
  продолжать парситься и игнорироваться в `normal`. Удаление ключа =
  повтор T268 у всех, у кого секция в файле лежит;
- после T311 нижняя толщина живёт в `wrap.bottom_thickness`. Решить и
  описать в отчёте, что происходит со старым `bottom_strip.height`:
  либо он остаётся источником для планки в `wrapped`, либо становится
  игнорируемым легаси. Второе — чище, но тогда явно логировать один раз
  при старте, что значение больше не читается. Молча игнорировать
  чужую настройку нельзя.

### 4. `normal` = нулевая толщина

После T311 толщина краёв уже попиксельно-краевая. `normal` должен
выражаться через неё как «ноль по всем краям», а не как отдельная
кодовая ветка со своей отрисовкой. Если после T311 это не получается
одним значением — написать в отчёте, почему, и не городить вторую
реализацию рамки.

В `normal` не должно создаваться ни одного слоя `frame_wrap_*`:
ни матте, ни эксклюзивных полос. Проверяется через `hyprctl layers`.

## Верификация — живая

```bash
cargo build --release --bin chronos
magick -size 2560x1440 xc:white /tmp/t312-white.png
awww img -o DP-1 --transition-type none /tmp/t312-white.png
RUST_LOG=info ./target/release/chronos &
chronos-ipc toggle-side-panel-left
chronos-ipc toggle-side-panel-right
```

Конфиг перечитывается на лету (debounce 300ms, `frame.rs:50`) —
рестарт не нужен, переключать `style` прямо в
`~/.config/chronos/frame.toml`.

Приёмка:

1. `style = "wrapped"` → на y=700 плиты по бокам нет (рельс с `x=0`),
   снизу плита есть, все четыре угла апертуры скруглены. То есть
   картинка T311 не сломалась.
2. `style = "normal"` → на y=700 `x=0` принадлежит рельсу; на x=1280
   пиксель `y=1439` — обои, не планка. `hyprctl layers` не содержит
   ни одного `frame_wrap_*`.
3. Переключение `wrapped ↔ normal` пять раз подряд — нет осиротевших
   слоёв, нет паник в логе, геометрия каждый раз одна и та же.
4. **Тест на алиас, живой:** поставить `style = "wrap"` (старое имя) —
   должен дать `wrapped` и сохранить `wrap.thickness`/`inner_radius`
   из файла. Проверить промером, а не только тестом: положить в конфиг
   нестандартную толщину (например 24) и убедиться, что она применилась.
5. Мусорное значение `style = "banana"` — режим падает в дефолт,
   `wrap.thickness = 24` из п.4 **остаётся в силе**, в логе один warn.
   Это главная живая проверка тикета.
6. Обе темы.

Промеры — теми же командами, что в T311 (`grim` + `magick ... txt:`),
вывод вставить в отчёт.

`cargo check -p chronos --bins` и `cargo test -p chronos --lib`
зелёные. Существующие тесты `frame.rs` переименовать под новые имена
вариантов, но **не ослаблять**: если тест проверял поведение — он
обязан проверять его и после.
