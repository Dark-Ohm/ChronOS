# T322 — панели перестают пересоздавать поверхности при смене стиля рамки

**Роль:** FRONTEND. **Приоритет:** P1 (сейчас шелл теряет ВСЕ поверхности —
чинится только рестартом).
**Зона:** `crates/app/src/side_panel_left/mod.rs`,
`crates/app/src/side_panel_right/mod.rs` — путь `apply_frame_inset` и
window-options обеих панелей.
**Не трогать:** `frame.rs` (T321 принят, живой sync геометрии переделке не
подлежит), `aperture_ring`, маршрут вкладок (T320), палитру.

## Что происходит

При смене `frame.style` (`hide` ↔ `wrap`) **с открытыми боковыми панелями**
шелл теряет все слои. Воспроизведено исполнителем T321 и подтверждено
дословными логами:

```
frame: failed to open bottom strip: Adapter "NVIDIA GeForce RTX 3070"
  (backend=Vulkan, device=0x2484) is not compatible with the display
  surface for this window.
side_panel_left: content surface failed to open: Adapter ... not compatible
side_panel_right: content surface failed to open: Adapter ... not compatible
frame: wrap surface Matte failed to open: Adapter ... not compatible
```

Дальше флуд `Protocol error 1 on object wp_viewport@...` — до **миллионов**
строк за секунды (замерено: 5 343 366 при 20 переходах шагом 400 мс,
1 956 205 при рецепте 100 мс). `hyprctl layers` пустеет, процесс жив,
поверхностей нет. Лечится только рестартом.

**При закрытых панелях не воспроизводится** — 20 переходов, ноль ошибок.
То есть спусковой крючок именно каскад панелей.

## Корень — два слоя

**Нижний, в форке.** Ошибка приходит из
`Source/gpui_wgpu/src/wgpu_context.rs:194-200`
(`check_compatible_with_surface`): `surface.get_capabilities(&adapter)`
возвращает пустой `formats`, и свежесозданная wgpu-поверхность не проходит
проверку совместимости. Сопутствующий `Protocol error on wp_viewport` —
обращение к wayland-объекту уже уничтоженной поверхности. Это гонка
жизненного цикла в форке, а не логика приложения. Сверено архитектором по
исходнику форка.

**Верхний, наш и чинибельный.** Гонку дёргает объём: на каждый
style-переход `frame` пересоздаёт свой набор, а **каждая панель через
`apply_frame_inset` закрывает и переоткрывает по две поверхности** (rail +
content). Итого `4 + 4 + 2×2 + 2×2` за секунду. Убери каскад панелей —
и частота close/open падает вчетверо.

## Что сделать

Панели должны менять инсет **живьём**, а не пересозданием — ровно тем же
приёмом, которым это уже дважды сработало:

- **T314** — эксклюзивная зона полос: ушли с `close + open` на
  `window.set_exclusive_zone` по живым хендлам;
- **T321** — геометрия wrap-поверхностей: ушли с рекрейта на
  `window.resize` + `set_exclusive_zone` + `cx.notify` для матте. Замерено:
  `closed wrap surface = 0`, `Protocol error = 0`, правка применяется.

Здесь то же самое: при смене стиля меняется `margin` (инсет края) и высота
панели. Проверить, что из этого форк умеет менять на живой поверхности:

- `window.resize` — есть, используется в `bar/mod.rs` и hide-полосе;
- `set_exclusive_zone` — есть, `Source/gpui/src/window.rs:2005`;
- **`margin`** — вот главный вопрос. Если публичного сеттера нет (в T307
  зафиксировано, что геометрия запекается в `window.open`), то либо
  пересчитывать инсет иначе (например держать панель на месте, а сдвигать
  содержимое), либо заводить сеттер в форке отдельным тикетом. **Не
  выдумывать API — сверить с исходником `Source/gpui` и написать в отчёте
  фактом со ссылкой на файл:строку.**

Если живой путь для `margin` недостижим — второй приемлемый вариант:
**сериализовать** каскад. Не пересоздавать всё разом: дождаться закрытия
одной поверхности перед открытием следующей, либо развести пересоздание
панелей и рамы по разным тикам. Это лечит гонку, не убирая рекрейт.

Что бы ни выбрал — **ошибку не глушить**. Если поверхность не открылась,
состояние не должно оставаться полуживым: либо повтор, либо честный откат
с записью в лог (в `frame.rs` это уже сделано в T321 — `open_wrap_windows`
возвращает `bool`, и при неудаче hide-полоса остаётся на месте).

## Верификация

```bash
cargo build --release --bin chronos
RUST_LOG=info ./target/release/chronos > /tmp/t322.log 2>&1 &
chronos-ipc toggle-side-panel-left
chronos-ipc toggle-side-panel-right
# скрипт: 20 переключений style в frame.toml с шагом 400 мс
```

Приёмка:

1. **20 переходов при ОБЕИХ открытых панелях** — `grep -c "failed to
   open\|not compatible" /tmp/t322.log` = **0**, `grep -c "Protocol
   error"` = **0**. Это главный критерий; сегодня тут 14 и пять миллионов.
2. `hyprctl layers` после серии: все четыре `frame_wrap_*`, бар, оба
   рельса и оба контента на месте.
3. Повтор рецепта на шаге 100 мс — тот же результат.
4. Геометрия после серии совпадает с конфигом (промер строки и столбца).
5. То же при одной открытой панели и при закрытых — не сломать то, что
   уже работает.
6. `cargo test -p chronos --lib` зелёные.
