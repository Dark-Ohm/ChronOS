## Грабли (кровные, не наступать)

- **Zed — только референс паттерна, НЕ источник кода.** «Как в Zed editor»
  означает поведение (единый канвас, авторост редактора), а не порт:
  Zed GPL-3.0, наше дерево Apache-2.0 — ноль скопированных строк, включая
  `reference/`. Скиллы `zed-agent-panel`/`zed-thread-view`/
  `zed-message-editor` описывают их архитектуру для понимания — читать
  можно, копировать нельзя. Живой sparse-чекаут для сверки паттернов:
  `/home/neo/scratch/zed-agent-recon` (depth-1; номера строк в скиллах —
  якоря, при расхождении re-grep).

- **НЕ трогать flex-геометрию корня панели**: `main-content` обязан
  сохранить `.min_w(px(0.)).overflow_hidden()`, resize-handle —
  `.flex_none()`. Это фикс fbcadd6 («resize dies at min width», флексовый
  `min-width:auto`). Любое изменение этих строк = автоматический reject.
- **Rust 2024 RPIT capture:** функции, возвращающие `impl IntoElement` и
  зовущие `cx.listener` внутри, конфликтуют по borrow с последующими
  такими же вызовами. Смотри комментарий в `panel.rs:38-43` и сигнатуру
  `build_sessions_sidebar` (`impl IntoElement + use<>`). Новые
  render-функции с листенерами — тот же паттерн.
- `overflow_y_scroll()` требует `.id(...)` (StatefulInteractiveElement).
- Один `on_hover` на элемент (форк ассертит) — root панели уже занят
  peek-debounce, не добавлять hover-логику на root.
- Никаких `let _ =` на fallible вызовах (`this.update(cx, ...)` в
  существующем коде — legacy, новый код так не пишет: `.log_err()` или
  явный match).
- **rsx vs builder — правило флагмана (sidebar v2, T098):** статичный хром
  порти на `gpui-rsx` (`use gpui_rsx::rsx;` — макрос компайл-тайм, эмитит
  builder-цепочки против нашего форка): шапка треда (блок A), карточка
  юзер-сообщения, пилл-кнопки тулбара. Динамику с листенерами и
  переменной геометрией (поток треда, авторост textarea, дропдауны) —
  builder `div()`. Откат rsx→div при боли — не failure, но фиксируй в
  rsx-vs-div map отчёта.
  Кровные факты rsx: `use gpui::div` обязателен даже в чисто-rsx файле
  (E0425 без него); `hover={|s| ...}` принимает `StyleRefinement`, не `Div`
  (E0631); stateful-атрибуты (`onClick`, `hover`, `overflowYScroll`) требуют
  `id=...`. Хекс-цвета из мокапа — атрибутами `bg={rgb(0x18_18_25)}`, не
  Tailwind-классами. Непонятная ошибка типов внутри разметки → обернуть тот
  же кусок в `rsx_expand!` и читать эмиттед-цепочку — это обычная gpui-ошибка
  в костюме макроса. Живой образец: `side_panel_right/{header,permission,
  disks}.rs`. Скиллы: `gpui-rsx` (consumer), `gpui-rsx-markup` (внутренности
  крейта).

## Верификация (гейты — прогнать и приложить вывод)

1. `cargo build -p chronos` — зелёный, ноль новых warnings.
2. `cargo test -p chronos side_panel_left` — существующие тесты зелёные.
3. `cargo build --release -p chronos`.
4. Живой смок: `pkill -x chronos; CHRONOS_SMOKE_SIDE_PANEL_LEFT=1
   RUST_LOG=info ./target/release/chronos &` — панель открыта.
5. `grim` скриншоты: (а) пустой тред + композер, (б) длинный
   многострочный ввод (10+ строк) — композер вырос, текст читаем, каретка
   видна, стрелки/клик двигают курсор, выделение работает (TextInput,
   блок C-2; если fallback — честно пометить),
   (в) после отправки — карточка юзера в потоке, ответ агента плоским
   текстом, (г) YOLO активен/неактивен, (д) дропдауны модели/режима.
6. Resize-смок ОБЯЗАТЕЛЕН: потянуть панель до min-ширины и обратно
   несколько раз — ручка живая (регресс fbcadd6 = reject).
7. Отчёт → `docs/orchestration/tasks/report/T109-agent-thread-canvas-report.md`:
