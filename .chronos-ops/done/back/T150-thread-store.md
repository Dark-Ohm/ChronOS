## Зачем

Треды в левой панели живут только в памяти: `sessions: Vec<SessionItem>`,
заголовки буквально `Session N` (`side_panel_left/mod.rs:237`). Перезапуск
шелла — всё потеряно. Кнопка «+» и сейчас означает потерю контекста.

## Разделение правды — главное решение, не отступать от него

**Содержимое разговора принадлежит агенту.** Hermes 0.18.2 это уже умеет,
проверено по его исходникам:

| Что | Где у агента |
|---|---|
| объявляет `load_session=True` в capabilities | `~/.hermes/hermes-agent/acp_adapter/server.py:888` |
| `session/load` — реплеит всю историю обратно | `server.py:1133` (+ `:1024` о реплее) |
| `session/resume` — продолжение без реплея | `server.py:1193` рядом |
| `session/list` — `{session_id, cwd, title, updated_at}`, фильтр по cwd, курсорная пагинация | `server.py:1249` |

**Мы храним то, чего агент знать не может:** какому агенту принадлежит тред
(у нас их несколько — `agents.toml`, T138), наш заголовок и переименования,
пин, архив, порядок, последнюю выбранную модель — и **кэш транскрипта**,
чтобы список и открытие были мгновенными и работали, когда агент не
запущен.

Кэш — именно кэш: при расхождении с тем, что реплеит агент, **прав агент**.

## Что сделать

### 1. Зависимость и место на диске

`rusqlite` (последняя версия, фича `bundled` — своя libsqlite, без системной
зависимости), плюс `zstd` для сжатия кэша транскрипта, если решишь сжимать
(Zed сжимает; на наших объёмах можно и без — реши сам и обоснуй одной
строкой).

Файл: `~/.local/share/chronos/threads/threads.db` (через `dirs::data_dir()`,
`dirs` уже в зависимостях — образец использования: `hermes_acp/registry.rs:70`).
Каталог создавать при первом запуске.

### 2. Схема

Минимум, который обязан быть (имена на твоё усмотрение, смысл — нет):

```
threads(
  id            TEXT PRIMARY KEY,   -- наш uuid, не ACP-шный
  agent_id      TEXT NOT NULL,      -- ключ из agents.toml
  acp_session_id TEXT,              -- id сессии у агента; NULL пока не создана
  title         TEXT,               -- авто-заголовок
  title_override TEXT,              -- переименование пользователем; побеждает
  cwd           TEXT,
  last_model    TEXT,
  pinned        INTEGER NOT NULL DEFAULT 0,
  archived      INTEGER NOT NULL DEFAULT 0,
  created_at    TEXT NOT NULL,      -- RFC3339
  updated_at    TEXT NOT NULL
)
```

Плюс кэш транскрипта: либо колонкой-блобом в этой же таблице (путь Zed),
либо отдельной таблицей сообщений. **Выбери сам и обоснуй в отчёте** — но
если делаешь отдельную таблицу, поиск по содержимому обязан быть на FTS5,
иначе смысла в нормализации нет.

**Версионирование схемы обязательно** — `PRAGMA user_version` и функция
миграции. База переживёт не одну версию шелла; молча ломать её нельзя.

### 3. Сервис

Модуль `crates/services/src/threads/`. По образцу соседей
(`hermes_acp/`, `applications/`): публичный тип с методами, вся работа с
диском — на блокирующем исполнителе, **не на главном потоке**.

Нужны операции: список (с фильтрами pinned/archived), создать, обновить
(заголовок/модель/`acp_session_id`/`updated_at`), удалить, пин, архив,
дописать сообщение в кэш, прочитать кэш треда, поиск по подстроке.

**Линты:** новый крейт не заводишь, но если заведёшь — `[lints] workspace = true`
обязателен. `unwrap`/`expect` в новом коде не пиши; ошибки не глуши
`let _ = …` (правила в `CLAUDE.md`, они не декоративные).

### 4. Две ACP-команды в клиент

`HermesClient` сейчас умеет `create_session` / `send_prompt` /
`send_prompt_streaming` / `set_model` (`hermes_acp/client.rs`, enum `Command`
и `execute_command`). Добавь по тому же образцу:

- **`list_sessions`** — `session/list` (типы `ListSessionsRequest`,
  `SessionInfo` в `agent-client-protocol-schema-1.5.0/src/v1/agent.rs`);
- **`load_session`** — `session/load` (`LoadSessionRequest`, там же,
  `:1171`). Ответ агента — реплей истории: он приходит **потоком**
  `session/update`, как обычный ход. Значит `load` обязан уметь отдавать
  события наверх тем же способом, что `send_prompt_streaming`
  (`on_event: Option<UnboundedSender<StreamingEvent>>`), а не одним
  ответом. Это ключевая деталь, не проглядеть её.

Проверь по крейту, есть ли типы (`grep` по кэшу cargo), и если метода в
2.0.0 нет — шли через `UntypedMessage`, как уже сделано для
`session/set_model` (`client.rs`, там же образец и пометка DELETE).

### 5. Чего НЕ делать

- Не трогать UI (`crates/app/**`) — это T151.
- Не переписывать существующие пути ACP: `stream_read_turn`, дедлайны,
  перехват моделей — всё это принято живыми прогонами, ломать нечего.
- Не тащить ORM/диезель. `rusqlite` и руками написанный SQL.

## Приёмка (2026-07-29): код принят, четыре правки до закрытия

Проверял сам: `cargo test -p chronos-services --lib -- threads` → **9 passed,
0 failed**. Схема, миграции, WAL, путь через `dirs::data_dir()` — на месте,
как заявлено. Решение по blob-транскрипту вместо FTS5 для наших объёмов
согласен.

### 1. Коммит несамодостаточен — `Cargo.lock` не в нём

`c688c11` добавил `rusqlite` в `crates/services/Cargo.toml`, а обновлённый
`Cargo.lock` остался несохранённым в рабочем дереве (`rusqlite 0.32.1`,
`libsqlite3-sys 0.30.1`, `hashlink`, `fallible-iterator` — всё висит как
`M Cargo.lock`). Свежий клон на этом коммите соберёт другой набор версий.

Это **четвёртый случай подряд** в проекте — правило из `CLAUDE.md` («перед
коммитом `git diff --staged` глазами, поимённый `git add`») написано ровно
про это. Довесить `Cargo.lock` в тот же коммит (`--amend`).

### 2. `rusqlite 0.32` — древность

На crates.io сейчас **0.40.1**. Мы на bleeding-edge (`docs/MEMORY.md`), чужие
пины не наследуем. Восемь мажорных версий назад — это не «стабильно», это
техдолг с первого дня. Поднять до 0.40, прогнать тесты заново.

### 3. `.expect("just inserted")` в боевом коде

`threads.rs:106`. В воркспейсе `expect_used = warn`, и новый код такие
предупреждения не добавляет. Заменить на
`ok_or_else(|| anyhow!("insert succeeded but row missing: {id}"))`.

### 4. Заявление про ACP-типы — НЕВЕРНО

Цитата отчёта: «Типов `ListSessionsRequest`/`LoadSessionRequest` в ACP 2.0.0
нет (подтверждено grep-ом по кэшу cargo)». Проверил по версии из нашего
`Cargo.lock` (ровно `2.0.0`):

```
.../agent-client-protocol-2.0.0/src/schema/client_to_agent/requests.rs:4:
    ListSessionsRequest, ListSessionsResponse, LoadSessionRequest, LoadSessionResponse,
.../requests.rs:16:
    impl_jsonrpc_request!(ListSessionsRequest, ListSessionsResponse, "session/list");
```

Типы есть, лежат в `schema::v2`, и у них уже прописан маппинг на
`session/list`. `UntypedMessage` работает, но мы теряем типизированный
ответ и ловим расхождение протокола рантаймом вместо компиляции — при том,
что ACP у нас уже дважды менял форму. Переписать обе команды на типы.

Это второй отчёт за сутки, где «подтверждено grep-ом» не подтверждается.
Грепай по той версии, что в `Cargo.lock`, а не по первой попавшейся в кэше
— там лежат 0.9.3, 0.10.6, 0.11.1 и 2.0.0 одновременно.

### Что НЕ придирка

5 новых `let _ = tx.send(...)` в `client.rs` — для oneshot-ответов, где
получатель мог уйти, это законно. Но правило проекта требует объяснения:
добавь однострочный комментарий «получатель мог быть сброшен — молчание
намеренное», иначе следующий чтец не отличит это от проглоченной ошибки.

### Живая часть

ACP-команды живьём не проверены — принимаю, это за мной. Опасение из отчёта
про 120-секундное зависание `session/load` при отсутствии `StopReason`
разделяю; проверю вместе с T151.
