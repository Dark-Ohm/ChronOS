# Scene-модель и композиция шелла по режиму (слайс 2) — Implementation Plan

Реализует §14 п.2 спеки
`docs/superpowers/specs/2026-07-30-adaptive-developer-gamer-shell-ide-design.md`
(«shared scene model and stable shell-mode composition»). Опирается на
закрытый слайс 1: `crates/app/src/workspace_mode.rs` уже даёт глобал
Developer/Gamer, персист в `~/.config/chronos/workspace.toml`, env-оверрайд,
IPC и контракт предложения смены.

**Объём утверждён пользователем 2026-07-31: вариант B.** Сцена в этом слайсе
помнит только состояние шелла — режим, вывод, набор и активную вкладку
правого рейла, состав дока. Внешние окна (захват раскладки через `hyprctl
clients`, восстановление, перенос между выводами) — **вариант C, следующая
итерация.** Пользователь прямо сказал: начинаем с B, улучшаем обновами.

**Из этого следует обязательное требование к формату сцены:** файл несёт
`version = 1` с первого коммита, а раздел под окна заранее объявлен
зарезервированным. В B он не пишется и не читается. Причина не абстрактная:
в T163 добавление одного builtin-виджета в уже существующий
пользовательский `bar.toml` стоило двух эррат и двухфазной миграции, потому
что формат не был рассчитан на рост. Второй раз мы этот фильм не смотрим.

## Global Constraints

Действуют поверх `docs/orchestration/agents/RULES.md`, не заменяют их.

1. **Режим не переключается сам.** Контракт слайса 1 остаётся в силе:
   `workspace_mode::set`/`toggle` зовутся только из пользовательских путей.
   Восстановление сцены при смене режима — следствие действия пользователя,
   а не автопереключение; новых вызовов `set`/`toggle` слайс 2 не добавляет.
   Проверяется грепом на приёмке, как в T162.
2. **Ссылки на выводы — только UUID дисплея.** §3.6 спеки: `DisplayId` и
   индексы не переживают сессию и hotplug. В сцене хранится UUID строкой.
3. **`cx.primary_display()` из поверхностей не зовётся.** Единственный
   резолвер — `crates/app/src/monitor.rs::pult_display()`, фолбэк живёт
   внутри него.
4. **Не превращать `side_panel_right/view.rs` в монолит побольше** (§11
   «Do not do»). Композиция читается из общего состояния, а не обрастает
   ветками внутри вью.
5. **Палитра — только токены темы.** Хардкод цветов запрещён (§11).
6. **Ошибки не глушим.** `let _ = fallible()` вне закона; `?`, `.log_err()`
   или явный `match` — см. CLAUDE.md.
7. **Каждое отступление от плана — в отчёт явным разделом «Что НЕ сделано».**
   T162 сделал это образцово, планка теперь такая.

## Задачи

| ID | Роль | Что | Зависимость |
|---|---|---|---|
| T164 | BACKEND | `scene.rs`: модель, персист `scenes.toml`, глобал, восстановление последней сцены режима | — |
| T165 | FRONTEND | Композиция по режиму: набор вкладок рейла и состав дока читаются из сцены/режима | после T164 (нужен API) |
| T166 | BACKEND | Добивка `pult_display()`: четыре прямых `cx.primary_display()`, поведение при hotplug | параллельно T164/T165, зона не пересекается |

T164 → T165 строго последовательно: T165 садится на API, которого без T164
не существует. T166 идёт параллельно с обоими — его зона (`monitor.rs` и
четыре файла-потребителя) не пересекается ни с одной из них.

## Формат `~/.config/chronos/scenes.toml`

```toml
version = 1

# Последняя активная сцена каждого режима — то, что восстанавливается
# при переключении (§5 «restore the selected mode's last scene»).
[last]
developer = "chronos"
gamer = "hub"

[[scene]]
id = "chronos"                 # стабильный ключ, не меняется при переименовании
name = "ChronOS"               # то, что видит человек
mode = "developer"
display = "09e7b298-aad0-546d-a4de-adcb9106fd7d"   # UUID вывода, НЕ индекс
rail_tabs = ["system", "files", "editor", "terminal"]  # опционально: оверрайд
active_tab = "files"           # опционально
dock = ["kitty", "code", "vivaldi"]                    # опционально: оверрайд

# ЗАРЕЗЕРВИРОВАНО под вариант C (внешние окна). В слайсе 2 не пишется и не
# читается; парсер обязан переживать его наличие, не падая и не затирая.
# [scene.windows]
```

Все три поля-оверрайда опциональны: отсутствие означает «бери дефолт
режима». Это и есть развязка сцены и композиции — сцена не обязана
дублировать то, что и так задаёт режим.

## Осознанно отложено (не считать пропуском)

- **Вариант C** — захват и восстановление внешних окон. Требует видимой
  сцен-транзиции (§5: «do not move external windows without a visible scene
  transition») и атомарного применения через компоновщик (§8). Отдельный
  слайс со своим планом и живым смоком на чужих окнах.
- **UI управления сценами** (`SceneManager`, §12 Developer composites) —
  слайс 3/4. В слайсе 2 сцены создаются и переключаются кодом и конфигом,
  экранного менеджера нет.
- **Per-game сцены** (§4.2) — слайс 5.
- **Применение компоновочного профиля `GamingModeState`** — §5 прямым
  текстом: это отдельный слой, вход в Gamer его НЕ включает, и UI не имеет
  права рисовать его активным только потому, что выбран Gamer.

## Итоговая верификация слайса

Слайс закрывается живым смоком (T167, QA, заводится после приёмки T166) —
release-сборка, `RUST_LOG=info`, кадры `grim`. «Компилируется и тесты
зелёные» для оконного кода не значит ничего.

## Что живьём проверяет архитектор

1. Сцена переживает рестарт: `scenes.toml` читается, `[last]` применяется.
2. Переключение Developer ⇄ Gamer меняет **набор вкладок рейла** и **состав
   дока**, при этом позиции общих инструментов сохраняются (§5).
3. Панели при смене режима **не закрываются** и не теряют состояние (§5,
   §11 «do not close panels on focus loss»).
4. Греп: ни одного нового вызова `workspace_mode::set`/`toggle` из
   не-пользовательских путей; `request_switch` по-прежнему в проде не зовут.
5. Греп: ноль `cx.primary_display()` вне `monitor.rs`.
6. Битый/чужой `scenes.toml` (мусор, неизвестный режим, секция `[scene.windows]`)
   не роняет шелл и **не затирается молча**.
7. Отключение пульт-вывода: шелл пере-резолвит, показывает видимое
   уведомление, состояние сцены не теряется, при возврате вывода
   применяется снова (§3.6).
