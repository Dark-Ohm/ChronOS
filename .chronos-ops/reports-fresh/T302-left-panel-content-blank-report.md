# T302 — левая панель: контентная зона рендерится пустой — отчёт

**Роль: FRONTEND.** Итог: **рендер-баг в текущем дереве не найден** —
описанный в тикете симптом в точности совпадает с ПРИНЯТЫМ дизайном
rail-only при призыве (T220) и с фейдом enter-анимации. Правка без
решения архитектора по поведению `toggle` — выход за зону миньона
(AGENTS.md: «Agents implement against a brief; they do not decide scope»).

## Что сделано (живой прогон, релизный бинарь, HEAD, Hyprland живой)

Все проверки — release-бинарь (тот же, что был у архитектора:
`crates/` с момента находки не менялся, кроме launcher-рефактора),
живой Hyprland, `RUST_LOG=chronos=debug`, grim + по-пиксельный разбор.

### 1. `chronos-ipc toggle-side-panel-left` — репро архитектора

- `hyprctl layers`: `side_panel_left_rail` (40px) и
  `side_panel_left_content` (920px-канвас) живы, координаты как в тикете.
- Рейл рисуется. Контентная зона прозрачна, сквозь неё обои.
- **Это и есть дизайн T220**: призыв открывает ТОЛЬКО рейл
  (36px strip + 4px handle = 40px), чат НЕ выезжает. Канон:
  - `HANDOFF-LOG.md:2449` — «chat **rail-only при призыве** (Super+A /
    peek открывает только рейл … чат НЕ выезжает)»;
  - `HANDOFF-LOG.md:1278` (запись самого архитектора) — «панель …
    раскрывается в rail-only (40px) по IPC»;
  - живой рецепт в HANDOFF (`Левая (T220)`) — призыв → ширина ~40px,
    видна ТОЛЬКО рейл-полоса;
  - `crates/app/src/side_panel_left/tabs/mod.rs` `WorkspaceAction::Toggle`
    → `panel_width: RAIL_WIDTH`, `dock_content: false`;
  - `crates/app/src/side_panel_left/state.rs` — комментарий T220 про
    старый баг T137 (призыв прятал композер), из-за которого и ввели
    rail-only.
- `close()` сбрасывает `panel_width = RAIL_WIDTH`/`dock=false`, поэтому
  каждый следующий toggle гарантированно rail-only.

### 2. `chronos-ipc expand-left` — контентный путь

Открывает rail + content, ACP-сессия поднимается, чат рендерится
ПОЛНОСТЬЮ (по-пиксельно, grim + `%[pixel:p{x,y}]`):

- поверхность: заливка `(30,30,46)` на всю видимую долю;
- шапка: сигил + «Agent» + статус + лампа (`y≈35..55`, пиксели текста);
- empty-state: «No messages yet» по центру тела (`x≈251..356, y≈681..691`);
- композер внизу: строка пикеров + плейсхолдер инпута (`y≈1290..1360`);
- ресайз-ручка 4px на правом краю видимой доли.

`expand-left` ведёт на Chat+dock+фокус композера через единый редьюсер
(`WorkspaceAction::ExpandComposer`), ширина = `width_for_open(Chat)`
(запомненная или soft-мин).

### 3. Интерактивные пути (ydotool, калибровка 2× как в HANDOFF)

- toggle (rail-only) → **клик иконки Chat на рейле** → контент
  раскрывается: mean региона тела 57.4 (обои, rail-only) → 31.9
  (тёмная поверхность панели), шапка 37.8. Работает.
- Циклы закрыть→открыть ×3: контент появляется каждый раз.
- Dock-тоггл и клики рейла идут через `WorkspaceView::on_*` (weak-хендл)
  + `cx.notify()` — утечки подписки нет.

### 4. Анимация входа (единственное, что «мигает пустотой»)

`render_panel` оборачивает `main-content` в `with_animation(
"side-panel-left-enter", enter_animation, apply_enter_from_left)` —
начинается с `opacity(0)` + `left(-14px)`, 260ms (ENTER_MS). Первые
~0.3–0.6с после раскрытия контент-зона **прозрачна — сквозь неё видны
обои**, затем плавно проявляется. Замер: mean региона
56.5 → 31.2 за ~0.6с, далее стабильно 31.2, при повторных открытиях
тоже. Если грим снять в этот промежуток — картина 1:1 из тикета
(«сквозь неё виден рабочий стол/обои»). После фейда панель остаётся
полностью видимой (циклы ×3 подтверждают).

Лог чистый: 0 error/panic/warn за всю сессию (journalctl, grep).

## Корень

Симптом из тикета воспроизводится в двух состояниях, оба — не баг
рендера:

1. **toggle → rail-only** — контентная зона намеренно пустая (T220,
   задокументировано, рецепт в HANDOFF ожидает ровно это);
2. **сразу после раскрытия** — enter-анимация стартует с opacity 0,
   грим в первые ~0.5с даёт «прозрачная зона + обои» (то же описание).

Реального «панель открыта, но не рисует, и так и остаётся» — не
найдено ни на одном пути: toggle, expand-left, клик таба, циклы,
замеры во времени.

## Чего я НЕ делал

- Не менял поведение `toggle` (это изменение принятого дизайна T220 —
  решение архитектора).
- Не трогал `composer.rs` Select-попапы (зона T298/T301).

## Что предлагаю на решение

Если тикет жив как «архитектор хочет менять дизайн» — есть три
развилки, все требуют слова архитектора:

- **A. Оставить rail-only** (как есть): закрыть T302 как by-design,
  в отчёт приложить рецепт проверки (toggle → rail, клик иконки →
  чат).
- **B. Toggle/Super+A открывает чат сразу** (remembered width или
  soft-мин): правка `WorkspaceAction::Toggle` (и, вероятно, рецепта в
  HANDOFF + T220-комментариев) — маленькая, но это смена принятого
  решения.
- **C. Не трогая поведение, убрать «мёртвую пустоту»**: например,
  сделать enter-анимацию с меньшим стартовым прозрачным окном или
  дать контент-зоне в rail-only лёгкий hint (вне текущего дизайна).
