# T324 — бар, dock, виджеты: отчёт живого UX-захода

**Бар/dock готовы к показу? — НЕТ.**

Один блокер убивает показ сам по себе: клик по часам открывает календарь
**без собственной подложки** — на обоях и поверх панели он нечитаем.
Часы — самый кликаемый виджет любого бара. Ещё два блокера: подсветка
активного воркспейса врёт компоситору, и сетевой виджет режется пополам
на легальной минимальной высоте бара (20 = `HEIGHT_MIN`).

Хорошая новость: три из четырёх гипотез T323 не подтвердились. Кнопки не
мёртвые — врут индикаторы. Крашей нет: `panic|Protocol error` = **0**,
чужих `ERROR` от chronos = 0 за 671 строку лога и ~30 минут работы.

- Улики: `.chronos-ops/dump/qa-ux/T324/` — 68 кадров, 49 кропов, лог.
- Сборка: `target/release/chronos` (20 авг 23:59), в дереве нет ни одного
  `.rs` новее бинарника — проверено `find -newer`.
- Монитор: DP-1 2560×1440, `chrome_monitor` по UUID совпал.
- ydotool: экранные координаты делятся на 2 — **проверено замером**
  (`-x 1200` → `hyprctl cursorpos = 2400`).

## Блокеры сферы (3)

### B1. Календарь открывается без подложки — нечитаем

Клик по часам открывает попап календаря, у которого **нет собственной
заливки**. Видно только тонкую рамку самого `Calendar` из gpui-component;
всё, что под попапом, просвечивает насквозь.

- Поверх обоев: `frames/23-calendar-over-wallpaper.png` —
  полосы обоев идут прямо через сетку дат.
- Поверх открытой панели Updates: `frames/22-clock-calendar-over-panel.png`,
  1:1 кроп `crops/22-calendar-over-panel-1to1.png` — «imath» поверх «26»,
  «opencode» поверх «16», версии пакетов сквозь ячейки дат. Держится и
  через 2 секунды, это не кадр в середине анимации.
- На тёмном фоне (когда сзади оказалась панель) читается —
  `crops/42-calendar-recheck.png`. То есть читаемость целиком зависит от
  того, что за спиной.

Корень, дословно из дерева:
`crates/app/src/calendar_popup/view.rs:32-34` — `render` возвращает голый
`Calendar::new(&self.calendar)`, ни одного `.bg(` во всём файле (35 строк).
Контейнеры вокруг — `calendar_popup/mod.rs:118` и `:134` — оба
`bg(gpui::transparent_black())`. Для сравнения, как сделано правильно:
`crates/app/src/volume_popup/view.rs:147` —
`.bg(theme.surface_color(bg.alpha(0.82)))`. Попап громкости выглядит как
нормальная карточка с заголовком «Sound» и крестиком
(`crops/10-volume-popup.png`) — календарь рядом с ним смотрится как
недоделка.

### B2. Подсветка активного воркспейса рассинхронизирована с компоситором

Клик по точке **работает** — компоситор слушается. Врёт индикатор.

Чистая репродукция (кадры `28-dots-before.png` / `29-dots-after.png`,
стопка `crops/28-dots-stale.png`):

```
до:    hyprctl activeworkspace = 11 (HDMI-A-1)   бар: синяя точка №3  ✔ верно
клик по точке №1 (ws 2)
после: hyprctl activeworkspace = 2  (DP-1)       бар: синяя точка №3  ✘ врёт
```

Пиксельная проверка после 3 секунд отстоя: точка №3 — `#007ACC` (accent),
точки №1 и №2 — `#45475A` (disabled). Компоситор при этом на ws 2.

Тот же симптом словили раньше в другой связке: активен был ws 2 на DP-1, а
синей стояла точка №2 (ws 12) — `frames/07-dots-settled.png`.

Корень: `crates/services/src/compositor/hyprland.rs:331-352` подписан
ровно на четыре события — `workspace_changed`, `workspace_added`,
`workspace_deleted`, `active_window_changed`, `layout_changed`. Обработчика
**`ActiveMonitorChanged` (focusedmon) нет**. Когда `FocusWorkspace(id)`
целится в воркспейс, который уже активен на своём мониторе, Hyprland
меняет только фокус монитора → шлёт `focusedmon`, а не `workspace` →
`refresh_workspaces` не зовётся → флаг `active` остаётся на прошлом
воркспейсе. Событие в крейте есть:
`hyprland-0.4.0-beta.3/src/event_listener/mod.rs:34` →
`ActiveMonitorChanged` → генерится `add_active_monitor_changed_handler`.
Заодно не слушаются `WorkspaceMoved` и `WorkspaceRenamed` — те же грабли
на переезде/переименовании воркспейса.

Для покупателя это выглядит ровно как «кнопка мёртвая» — он кликает,
фокус уезжает на другой монитор, а бар перед носом не меняется вообще.
Это и есть та самая гипотеза T323, только диагноз обратный.

### B3. Сетевой виджет режется пополам на минимальной высоте бара

При `appearance.height = 20` вторая строка спидометра («↑ 688») обрезана
ровно посередине глифов, первая упирается в верхний край:
`crops/40-network-clipped.png` (кроп 70×30 в увеличении 700%).

20 — это не самодеятельность пользователя, это **официальный минимум**:
`crates/app/src/bar/appearance.rs:173` — `HEIGHT_MIN: f32 = 20.0`. То есть
продукт разрешает высоту, на которой ломается его собственный виджет.
Двухстрочная вёрстка (`network.rs:216-231`) не имеет ни фолбэка в одну
строку, ни проверки «влезаю ли».

## Находки покрупнее блокеров не дотянувшие (4)

### M1. Точки воркспейсов: мишень 7×7, ноль ховера, ноль подписи

`crates/app/src/bar/widgets/workspaces.rs:17` — `DOT_SIZE = 7.0`, зазор
5px. У элемента есть `cursor_pointer()` и `on_click`, но **нет `.hover(...)`,
нет тултипа, нет номера**. Проверено живьём: наведение на каждую из трёх
точек не меняет ни одного пикселя — `crops/03-hover-left-stack.png`,
строки 4–6 идентичны строке 1 (покой).

Плюс: точки показывают воркспейсы **всех мониторов вперемешку**
(`monitor_id` в `Workspace` есть, виджет его не использует). На баре DP-1
из трёх точек две принадлежат HDMI-A-1. Клик по такой точке уносит фокус
на соседний монитор — без единого намёка на то, что произойдёт.

Итого мишень 7px без ховера, без подписи, без тултипа, с непредсказуемым
эффектом. Для продукта за $100 это не «минимализм», это отсутствие
аффорданса.

### M2. Сетевой виджет полностью инертен, а его индикатор мигает

`network.rs:194-232` — ни `.id()`, ни `.hover()`, ни `on_click`. Живая
проверка: наведение не даёт плашку (`crops/08-hover-right-stack.png`,
нижняя строка — единственная из семи без подсветки), клик не открывает
ничего (кадр `25-network-click.png`, `hyprctl layers` без изменений).
Это единственный виджет правого кластера без реакции: громкость, RU,
колокольчик, обновления, часы — у всех плашка есть.

Точка состояния при этом **мигает**: `indicator_color` (`network.rs:83-97`)
красит зелёным при `dl+ul >= IDLE_THRESHOLD` и серым ниже порога. На
холостом трафике порог перещёлкивается каждую секунду — в семи подряд
кадрах зелёный/серый чередуются без всякой смены состояния связи
(`crops/08-hover-right-stack.png`). Пользователь читает это как «интернет
моргает», хотя связь не рвалась ни разу.

### M3. Контекстное меню дока — чужая палитра, 230px под одно слово

ПКМ по иконке дока меню **открывает** (гипотеза T323 «меню не открылось»
не подтвердилась) — `crops/30-dock-rmb.png`. Но:

- заливка меню измерена пипеткой: **`#0A0A0A`**. Схема бара при этом
  `bg.primary #181825`, `bg.elevated #313244`. Это дефолтная тёмная
  поверхность **gpui-component** (`dock/context_menu.rs:27` —
  `use gpui_component::menu::{PopupMenu, PopupMenuItem}`), тема ChronOS
  до неё не доведена. Рядом со старт-меню и попапом громкости, которые
  сидят в семействе `#1e1e2e`, меню выглядит инородным чёрным кубиком;
- габарит замерен по кадру: **228×34px** под единственный пункт «Unpin»
  (текст занимает x 50…95, дальше 175px пустоты). Ширина зашита —
  `context_menu.rs:33` «canon `min-width:230px`». Канон писался под меню
  трея с длинными пунктами, для одного «Unpin» он абсурден;
- верхняя граница меню на y=37 при баре высотой 42 — меню залезает в бар
  на ~5px.

И содержательно: единственное действие — «Unpin». Ни «Запустить», ни
«Новое окно», ни имени приложения в шапке.

### M4. У дока нет тултипов вообще

Наведение на иконку 2 секунды — ничего, `frames/27-dock-tooltip.png`
(кадр 400×140, взят с запасом ниже бара, чтобы поймать всплывашку).
В коде подтверждается: `grep -n "tooltip"` по `bar/widgets/dock.rs` — ноль
совпадений, есть только `.hover(|s| s.bg(...))` на строках 84 и 154.
Гипотеза T323 «hover tooltip был» не подтвердилась.

Отдельно, **известное, приношу только как уточнение механизма** (T309 /
TBD): три из четырёх пинов не рисуются — в логе
`dock: skipping pinned app pin=firefox|code|vivaldi reason="no AppEntry"`.
Уточнение для того, кто будет чинить: в системе физически есть только
`vivaldi-snapshot.desktop`; `vivaldi.desktop`, `firefox.desktop`,
`code.desktop` отсутствуют, то есть матчинг по basename отрабатывает
честно, а пины в `dock.toml` просто протухли. Хуже, чем в T309, не стало.

## Мелочи (5)

1. **Два `separator` в секции `right` не делают ничего и молчат об этом.**
   `bar.toml` содержит `right = ["separator", "separator", "volume", ...]`.
   Пиксельный проход по строке бара: от x=130 до x=2178 ни одного пикселя
   `bg.elevated` — разделителей нет. Это не баг рендера, это дизайн T234:
   `bar/mod.rs:331` — `.filter(|(n, _)| right_widget_group(n) != 0)`,
   `separator` дропается и заменяется межгрупповым отступом. Но
   `sanitized()` их бережно сохраняет («Keeps separators and duplicates»,
   `layout_config.rs:382`), в лог не пишется ни слова, а в редакторе бара
   их, судя по всему, можно двигать. Пользователь настраивает пустоту.
   В левой секции разделитель рисуется нормально (x=77, 1×14px).
2. **Плашки ховера обрезаются при высоте бара 20** — кнопка старта и
   иконка приложения имеют `h(px(24.))` (`dock.rs:75`, `:145`), в 20px
   бар не влезают: скругления срезаны в плоскость,
   `crops/41-left-20px.png` (нижняя строка — ховер).
3. **Тишина и сдохший cava выглядят одинаково.** `cava.rs:14` —
   `MIN_BAR_H = 2.` плюс `levels.resize(BAR_COUNT, 0)` «so layout stays
   stable if cava is down». В обоих случаях в центре бара пунктирная
   строчка из 24 точек (`crops/01b2-center-zoom.png`). Отличить «музыка не
   играет» от «визуализатор отвалился» невозможно — я сам на этом
   споткнулся и час гонял mpv.
4. **`let _ =` на диспатче** — `workspaces.rs:59`
   (`let _ = AppState::compositor(cx).dispatch(...)`) и
   `keyboard_layout.rs:79` (то же с `CycleKeyboardLayout`). Прямое
   нарушение кровного правила проекта: если диспатч не дошёл, клик молча
   ничего не делает, и в логе пусто. Именно из-за этого «мёртвую кнопку»
   в B2 нечем было отличить от «сломанного индикатора» без hyprctl.
5. **Шум в логе:** `usvg::parser::svgtree: Failed to parse marker-start /
   marker-mid / marker-end value: 'none'` — десятки строк при первой
   отрисовке иконок правого рейла (08:37:38Z). Не влияет на картинку, но
   засоряет `RUST_LOG=info`, в котором ищут настоящие проблемы.

## Что хорошо

Честно: правый кластер собран аккуратно, и половина проверок прошла чисто.

- **Громкость.** Ховер-плашка, клик открывает попап «Sound» — нормальная
  непрозрачная карточка с заголовком, крестиком, слайдерами и кнопками
  (`crops/10-volume-popup.png`). Повторный клик по виджету закрывает.
- **Раскладка.** 4 состояния подряд, метка совпала с
  `hyprctl devices` **4 из 4**: RU→HE→US→RU (`crops/15-kbd-cycle.png`).
  Сокращение `"English (US)"→US`, `"Hebrew"→HE` работает как в юнитах.
- **Колокольчик.** Пустой — тонкий контур без числа; с двумя
  нотификациями — залитый белый колокол и розовое «2»
  (`crops/17-bell-badge-zoom.png`), различие состояний читается мгновенно.
  Тоггл панели: **4 клика подряд open/close/open/close**, пиксельная
  проверка каждого. Бейдж гаснет при открытии центра, сами уведомления
  остаются — правильное «прочитано».
- **Обновления.** «↑ 19» на баре ↔ «Updates (19)» в панели — сошлось
  (`crops/20-updates.png`). После установки Vivaldi стало 20, тоже сошлось.
- **Трей.** Пустой — не рисует ничего (правильно, никаких плейсхолдеров).
  Живой элемент от Vivaldi поднялся и отрисовался иконкой, несмотря на
  `title=Some("")` и `icon=None` в логе — `crops/39-tray-with-item.png`.
- **Батарея.** На десктопе без батареи виджет честно рисует пустой `div`
  вместо «0%» (`battery.rs:29-36`) — и в кадре его действительно нет.
- **Старт (гексагон).** Открывает старт-меню: непрозрачная панель с
  сайдбаром Places/Categories, поиском, сеткой приложений и строкой
  пользователя (`crops/26-cube-click.png`). Проверено 2/2 после правки
  координат под новую высоту бара + сверено с `chronos-ipc
  toggle-start-menu` (1/1 открыл, 1/1 закрыл) — поведение идентично.
  Ставит полноэкранный `chronos-popup-click-catcher`, click-away работает.
- **ЛКМ по иконке дока запускает приложение** — Vivaldi Snapshot
  поднялся, окно в `hyprctl clients`, следом в трее появился его
  `StatusNotifierItem`. Основное действие дока живо.
- **cava** реагирует на реальный системный звук: 4 кадра подряд с разной
  высотой столбиков, `fx:mean` 0.1616 / 0.1590 / 0.1530 / 0.1551
  (`crops/38-cava-live.png`).
- **mpris** с живым плеером показывает глиф паузы и заголовок трека с
  многоточием, не ломая ширину бара (`crops/37-mpris-filled.png`).
- **Стабильность.** 671 строка лога, ~30 минут, десятки открытий/закрытий
  попапов и панелей: `grep -cE "panic|Protocol error"` = **0**, `ERROR` от
  chronos = **0** (в логе есть `ERROR` только из `hermes.stderr` — чужой
  подпроцесс, к шеллу отношения не имеет).
