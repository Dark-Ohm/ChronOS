# T247 — compose-and-send: авто-сабмит после коннекта + фикс честной доставки

**Статус:** ЗАКРЫТ. Коммиты: `panels+ipc : compose-and-send auto-submit + width-desync fix (T247)` + orchestration.

## Корень (найден живым прогоном, не чтением)

Живой тест на свежем бинаре воспроизвёл симптом аудита точно и показал
причину: **`send_composer` молча дропал сообщение, когда `agent_status ==
Thinking`**. Хронология лога:

- `13:10:36` — `compose-and-send:hello` получен (шеф-старт, клиент ещё не
  подключён: `HermesClient::new` + `create_session` занимают секунды);
- `13:10:40` — ACP-клиент подключился — **на 4 секунды позже**;
- в момент вызова `send_composer` статус был `Thinking` → ранний `return`
  → сообщение потеряно, поле осталось с текстом, тред «No messages yet».
  Ровно кадр из аудита (текст в поле + пустой тред).

**Width-desync (160px) в текущем HEAD НЕ воспроизводится**: render-гейт
T243-зеркала (`needs_width_resize(window.bounds(), state.width)`) уже
само-лечит ресайз — после compose-and-send панель держит 352px во всех
прогонах, включая 3 подряд compose-and-send + expand-left. Код не менялся
для ширины, зафиксировано в отчёте.

## Фикс (очередь до коннекта)

- `composer.rs`: `send_composer` разбит на три метода:
  - `send_composer` — текстовый гейт + ветвление по состоянию;
  - `push_user_message` — юзер-сообщение + авто-тайтл (T151), общий для
    всех путей (исключает двойной пуш при отложенной отправке);
  - `start_acp_turn` (pub(crate)) — тело старого send_composer.
- **Очередь только в фазе подключения** (`!clients.contains_key(active)` &&
  Thinking): юзер-сообщение пушится сразу, честная заметка
  «Агент ещё подключается — сообщение будет отправлено автоматически»,
  текст в `pending_send: Option<String>`. Хендлер коннекта в
  `SidePanelLeft::new` дренирует очередь и запускает ход.
- **Mid-turn (клиент есть, но ход идёт)** — НЕ очередь (она дренится
  только на коннекте — застряла бы с ложным обещанием): честная заметка
  «Агент ещё отвечает…», сообщение показано в треде.
- Connect-фейл: `pending_send` чистится + честная ошибка. `switch_agent` /
  `create_new_session`: очередь сбрасывается (чужая/устаревшая).
- `mod.rs`: connect-хендлер переименован `_cx`→`cx`, добавлен
  `cx.notify()` (UI обновлялся и раньше по косвенным путям — теперь явно).

## Верификация (живая)

1. **Свежий запуск + compose-and-send в t=2s** (до коннекта): сообщение
   поставлено в очередь → при коннекте (t≈+4s) немедленно
   `composer: send text="first queued msg"` + `turn START` + реальный
   ответ агента (тулколы search/read, thread 139 строк текста).
2. **Второе compose-and-send во время стриминга**: НЕ спавнит второй ход
   (нет turn START), тред получает юзер-сообщение + честную заметку —
   параллельный ход не портится.
3. **Ширина**: 352px во всех прогонах (в т.ч. после 3 циклов
   compose-and-send + expand-left) — просадки 40/160 нет.
4. Тесты: `--bin chronos -- side_panel_left composer` 13/13,
   release-сборка чистая (новых warning нет — проверено диффом позиций).

**Триггер:** нет. Ключевое продуктовое обещание «агент слева отвечает»
теперь доказуемо одной IPC-командой без Wayland-seat.
