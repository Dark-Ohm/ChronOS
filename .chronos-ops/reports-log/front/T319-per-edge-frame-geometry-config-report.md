# T319 — геометрия оболочки по каждому краю

**Роль:** FRONTEND. **Статус:** готово к приёмке.
**Зоны:** `crates/app/src/frame.rs`, `crates/app/src/side_panel_left/tabs/mod.rs`,
`crates/app/src/side_panel_right/mod.rs`. Других файлов не касался.

## Форма конфига (обоснование)

```toml
[wrap]
inner_radius = 10
top    = 0     # 0 = следовать bar.toml [appearance] height
left   = 16
right  = 16
bottom = 16
```

Обоснование — ровно то, что просил бриф:

- **`top` не дублирует бар.** Верхний край физически рисует бар, поэтому
  `top = 0` (дефолт) означает «взять `bar.toml [appearance] height`». Ненулевое
  значение — осознанный оверрайд; при применении логируется один раз, что
  высота бара игнорируется. Молча расходиться нельзя.
- **`left`/`right` действуют только когда рельса на этом крае НЕТ** (T314 —
  мапленный рельс сам и есть край). Описано в комментарии `WrapConfig`.
- Все четыре значения идут через `sanitized()` с тем же клампом
  `MIN_THICKNESS..=MAX_THICKNESS` (1..64); `top` дополнительно сохраняет 0 как
  сентинел «следовать бару».
- **Старые имена `thickness` и `bottom_thickness` читаются как алиасы**
  (`thickness` → left+right, `bottom_thickness` → bottom). Ручной
  `Deserialize` вместо `#[serde(alias)]`, потому что serde-алиас маппится
  один-в-один и не может размножить один ключ на два поля. Явный новый ключ
  бьёт алиас (`left` поверх `thickness` и т.д.). Это закрывает инцидент T268 —
  конфиг владельца со старыми именами не схлопывается в дефолты.

**Ленивый разбор по ключам.** `left = "много"` (мусор по типу) → `None` →
дефолт **только этого ключа**, остальные ключи и секции выживают. Структурная
ошибка на уровне таблицы (`wrap = "не таблица"`) по-прежнему роняет весь
конфиг в дефолты — поведение, аналогичное junction (T268), осознанно сохранено.

## Решение по п.2 — единый источник ширины рельса

Выбрал **«одна константа, владеет `frame.rs`»**, а не «`[wrap] rail` из
конфига» и не «frame получает ширину через хук»:

- `frame.rs` держит `pub(crate) const RAIL_WIDTH: f32 = 40.0` (бывшая
  `RAIL_INSET`), обе панели реэкспортируют её (`side_panel_left/tabs/mod.rs`,
  `side_panel_right/mod.rs`). Второй копии больше нет.
- Правило «frame никогда не импортирует panels» не нарушено: панели импортируют
  frame, а не наоборот. Зависимость осталась однонаправленной.
- Хук `set_after_apply` для этого не годится: frame читает ширину рельса
  **синхронно** при открытии wrap-поверхностей и в `Render` (мапленный рельс →
  `inset = RAIL_WIDTH`), а хук исполняется *после* `apply`. Гнать величину
  через пост-хук значило бы читать её до того, как она пришла.
- **Конфигурируемую ширину рельса (`[wrap] rail`) не делал.** Бриф даёт её как
  один из двух вариантов и «решает исполнитель». Она тянет за собой больше,
  чем устранение дубля: геометрию rail-поверхности обеих панелей, эксклюзивную
  зону, `content_window_margin` и кольцо апертуры — это отдельный объём, и его
  «если конфигурируемо»-проверка в брифе при таком решении не применяется.
  Отмечаю как возможный follow-up.

Кольцо апертуры и `content_window_margin` обеих панелей теперь берут ширину
рельса из того же `frame::RAIL_WIDTH` — свои копии удалены.

## Что сделал

- `WrapConfig` переведён на `top`/`left`/`right`/`bottom`; ручной `Deserialize`
  с алиасами и ленивым разбором; `sanitized()` клампит каждый край.
- `RAIL_INSET` → `pub(crate) RAIL_WIDTH` (frame), панели реэкспортируют.
- Геттеры `wrap_inset_left/right/bottom` читают новые поля; добавлен
  `shell_top_gap()` (top = override, иначе живая высота бара), подключён в
  кольцо апертуры. Оверрайд `top` логируется один раз в `apply_wrap`.
- Кламп кольца вынесен в `aperture_ring_border()` — тестируется без дерева
  элементов.
- Не трогал: `aperture_ring` форму (принята владельцем), `FrameStyle`/
  `deserialize_style` (T312), палитру, `bar/appearance.rs` (только читаю высоту).

### Живой smoke (Hyprland, release-бинарь, hot-reload без рестарта)

Измерение толщин полос — `hyprctl layers` (xywh), промер пикселей — `grim` +
`magick`. Тема по умолчанию тёмная, для критерия 4 переключился на светлую
(`scheme = "Light"`), чтобы хром/обои различались (обои у нижнего края белые
`255,255,255`, хром светлой темы `236,238,250`).

**1. Правка каждого ключа меняет свой край живьём.** `[wrap] left=24 right=30
bottom=8` →
```
frame_wrap_excl_left   0 16 24 1440   (24)
frame_wrap_excl_right  2530 16 30 1440 (30)
frame_wrap_excl_bottom -3 1432 2560 8  (8)
```
До правки все три были 16 (дефолт). Каждый ключ двигает ровно свою полосу.

**2. Старые имена работают.** Файл ТОЛЬКО со старыми именами
`thickness = 20`, `bottom_thickness = 6` →
```
frame_wrap_excl_left   0 16 20 1440   (20 = thickness)
frame_wrap_excl_right  2540 16 20 1440 (20 = thickness)
frame_wrap_excl_bottom 0 1434 2560 6   (6  = bottom_thickness)
```
Геометрия применилась, не схлопнулась в дефолт (было бы 16/16/16).

**3. Мусорное значение.** `left = "много"`, `right = 22`, `bottom = 7` →
```
frame_wrap_excl_left   0 16 16 1440    (16 = дефолт, ключ упал в дефолт)
frame_wrap_excl_right  2538 16 22 1440 (22 — выжил)
frame_wrap_excl_bottom -3 1433 2560 7  (7  — выжил)
```
`cat` файла до/после — файл не переписан, мусор лежит дословно.

**4. Край тоньше радиуса.** `bottom = 4` при `inner_radius = 10`, светлая
тема, вертикальный скан x=30:
```
bottom=16: y=1423 белое(обои) → y=1424..1440 хром   (полоса 16)
bottom=4:  y=1435 белое(обои) → y=1436..1440 хром   (полоса 4)
```
Полоса ровно 4px, кольцо ужалось, наружная часть на обои не вылезла
(выше y=1436 — белые обои). Кламп дополнительно закрыт юнит-тестом
`aperture_ring_border_clamps_to_smallest_edge`.

**5. `top` следует бару / оверрайд.** `top = 0` + `bar.toml height = 40` →
`bar` стал `0 0 2560 40`, полосы сдвинулись на y=20. Затем `top = 48` →
логовая строка:
```
INFO chronos::frame: frame: wrap.top override active — bar.toml [appearance] height ignored for the shell top edge top=48.0
```
(одна строка на apply, не спамит).

**6. Обе темы.** Default (тёмная) и Light — шелл жив, геометрия применяется в
обеих, цвет хрома следует теме (в светлой хром `236,238,250`).

## Проверено самостоятельно

- `RAIL_INSET` в `crates/` больше не встречается ни разу; единственный
  источник — `frame.rs:63` `pub(crate) const RAIL_WIDTH: f32 = 40.0`,
  панели реэкспортируют (`side_panel_left/tabs/mod.rs:33`). Дубля нет;

- **старые имена, живой прогон.** Конфиг ТОЛЬКО со старыми ключами
  (`thickness = 20`, `bottom_thickness = 6`) →
  `excl_left w=20`, `excl_right w=20`, `excl_bottom y=1434` (высота 6).
  Не схлопнулось в дефолт (было бы 16/16/16). **Инцидент T268 закрыт**;
- **мусорное значение, живой прогон.** `left = "много"`, `right = 22`,

  работает как заявлено;
- per-edge правки двигают ровно свой край: `left=24 right=30 bottom=8`
  дало `24 / 30 / 8`.

Ручной `Deserialize` вместо `#[serde(alias)]` обоснован верно: алиас
маппится один-в-один и не может размножить `thickness` на два поля.

## Известный артефакт — не блокер

При **асимметричных** боковых краях нижняя полоса уезжает по x:
`left=24 right=30` → `frame_wrap_excl_bottom x=-3`. Механика та же, что
описана в T303: якорь `LEFT|RIGHT` при фиксированной ширине 2560
центрирует переполнение в доступной области, а она урезана боковыми
резервациями — `24 + (2506 − 2560)/2 = −3`. При симметричных краях
`x = 0`, проверено.

**Визуально не проявляется:** промер y=1436 на обоих нижних углах даёт
сплошной хром `(24,24,37)` — полосу не видно, её роль чисто
резервационная, а краску кладёт полноэкранная матте. Практический
эффект — резервация внизу справа короче на 3px, то есть клиент может
залезть на 3 пикселя. Косметика, но записано: раньше эта же механика
уже кусалась (T303, замеренные −28).

Не чинил и в отдельный тикет не выношу — всплывёт, когда владелец
реально уйдёт в асимметрию; тогда лечится тем же приёмом, что матте в
T308 (`exclusive_zone: Some(px(-1.))` + явный margin).

## Осознанно не сделано — принято

- **`[wrap] rail` (конфигурируемая ширина рельса)** — исполнитель
  отказался с внятным обоснованием: тянет за собой геометрию
  rail-поверхностей обеих панелей, эксклюзивные зоны,
  `content_window_margin` и кольцо апертуры. Бриф давал это как выбор
  исполнителя. Согласен, отдельный объём;
- **ползунки в `bar_settings.rs`** — бриф помечал опциональными;
- аргумент, почему `set_after_apply` не годится для передачи ширины
  (frame читает её синхронно при открытии поверхностей и в `Render`,
  а хук исполняется после `apply`), — верный и стоило его записать.
