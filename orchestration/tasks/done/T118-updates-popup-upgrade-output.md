## ЗАДАНИЕ — Updates popup: живой вывод во время "Upgrade all"

**Контекст:** T117 (anchored-редизайн попапа) принят пользователем живьём
("справился почти прекрасно, готов на 90%"). Осталось два хвоста:
1. Скролл списка не проверен на реальном количестве пакетов (низкий
   риск, код уже есть — `overflow_y_scroll` из T117/T116, просто нужно
   дождаться момента, когда реально накопится длинный список, и
   визуально подтвердить, что скроллится).
2. **Вывод процесса апгрейда — сейчас грубый (Idle/Running/Done/Failed),
   пользователь хочет живой прогресс** (это и есть T118, основной объём
   задачи).

**Желаемое поведение (дословно от пользователя):** нажимаю "Upgrade
all" → строки списка обновляемых пакетов улетают одна за другой снизу
вверх, "ступенечкой" (staircase — не все разом, по одной, по мере того
как пакет реально доустановился) → кнопка "Upgrade all" начинает
крутиться (спиннер вместо статичной кнопки) → под кнопкой появляется
полоска прогресса → справа от полоски — проценты → под всем этим
красиво стримит последняя строка вывода из терминала (живой "хвост"
процесса, не статичный текст).

## Текущее состояние бэкенда (что реально есть, не выдумывай сверх)

`crates/services/src/aur/`:

- `run_upgrade_all()` (`mod.rs:309-331`) — `Command::new(bin).args(&args)
  .status()`. **Вывод НЕ захватывается вообще** — процесс наследует
  stdio родителя, ChronOS не видит ни одной строки, только код возврата
  в конце. Это надо переделать на потоковое чтение (см. "Что делать
  #1").
- `UpgradeState` (`types.rs:22-29`) — плоский enum `Idle/Running/Done/
  Failed`, без данных внутри. Нужно расширить как минимум `Running`
  вариантом, несущим прогресс (структуру продумай сам, см. "Что делать
  #2" — не единственно верный дизайн, но обоснуй выбор в отчёте).
- Команда — `pkexec yay -Syu --noconfirm` (если есть `yay`) или `pkexec
  pacman -Syu --noconfirm` (`upgrade_command_args`, `mod.rs:297-303`).
  `pacman`-вывод для установки пакетов имеет узнаваемый формат строк
  вида `(N/M) upgrading <name>...`/`(N/M) installing <name>...` —
  реальный источник для процента и для "какой пакет только что закрылся"
  (нужно для staircase-анимации). `yay` при сборке AUR-пакетов может
  давать другой формат вывода (makepkg) для стадии сборки — **проверь
  реальный вывод на этой машине** (`yay -Syu --noconfirm` вручную в
  терминале, если пакетов на апгрейд сейчас нет — спровоцируй тестовый
  апгрейд одного мелкого пакета или временно смени команду на что-то
  безопасное для эксперимента), не гадай по памяти о формате.

## Что делать

### 1. Потоковый вывод процесса апгрейда (сервисный слой)

Замени `Command::.status()` на потоковое чтение stdout (по аналогии с
тем, как это уже сделано в `crates/app/src/desktop_terminal/` для PTY —
не обязательно PTY, но паттерн "спавн процесса + читать построчно из
отдельного потока/таска + слать в reactive state" тот же). Каждая новая
строка вывода должна:
- обновлять "последнюю строку" в состоянии (то, что стримится под
  прогресс-баром),
- если строка матчит `(N/M) upgrading|installing <name>` — пересчитывать
  процент (`N/M`) и определять, какой пакет только что обработан (для
  анимации в UI).

### 2. Расширить `UpgradeState`/`UpdatesState`

Реши сам точную форму (задокументируй в отчёте почему), минимум нужно
нести наружу: текущий процент (или `current/total`), последнюю строку
вывода, и множество/список уже обработанных имён пакетов (чтобы UI знал,
какие строки списка убрать). Пример направления (не обязателен
дословно):

```rust
pub enum UpgradeState {
    Idle,
    Running(UpgradeProgress),
    Done,
    Failed,
}

pub struct UpgradeProgress {
    pub current: usize,
    pub total: usize,
    pub last_line: String,
    pub completed_names: Vec<String>, // или HashSet<String>
}
```

### 3. UI — попап (`updates_popup/view.rs`)

- Кнопка "Upgrade all" во время `Running` — спиннер вместо текста
  (иконка вращения — проверь, есть ли уже вращающаяся иконка в проекте,
  например `icons/arrows-clockwise.svg` уже существует в
  `crates/app/assets/icons/` — крути её через `gpui-animation`, уже
  вендорнута, см. `skills/vendored-gpui-animation`, не пиши свой
  анимационный цикл с нуля).
- Под кнопкой — полоска прогресса (`current/total` из state), справа —
  текст процента.
- Под полосой — последняя строка вывода, обновляется реактивно
  (`cx.notify()` на каждое изменение state, как остальные reactive
  панели в проекте).
- Строки списка пакетов — при появлении имени в `completed_names`
  убираются с анимацией (staircase — одна за другой, снизу вверх).
  Используй `gpui-animation` (`transition_when`/`with_transition`) для
  fade/height-collapse перехода, не мгновенное исчезновение — если
  библиотека не даёт удобного height-collapse перехода из коробки,
  задокументируй, что взял вместо этого (например opacity-fade без
  height-коллапса как компромисс первой итерации) — не мучайся с этим
  бесконечно, честный компромисс лучше зависшей задачи.

## Что НЕ делать

- Не выдумывай формат вывода `yay`/`pacman` по памяти — проверь реально
  на этой машине перед парсингом (2026 год, версии могли измениться).
- Не пиши собственный анимационный тикер для спиннера/переходов — в
  проекте уже вендорнута `gpui-animation` (`Source/gpui-animation/`),
  используй её.
- Не блокируй UI-поток чтением stdout — потоковое чтение строго на
  фоновом таске (`tokio::task::spawn_blocking` или отдельный поток,
  как уже принято в `desktop_terminal`/`cava` сервисах в этом дереве),
  реактивно прокидывается через тот же `Mutable`/state-паттерн, что и
  остальные сервисы (`Service` trait, `crates/services/src/`).
- Не переусложняй "определение какой пакет только что обработан" сверх
  простого match по имени в строке — если парсинг иногда промахивается
  (не находит имя), просто не анимируй эту конкретную строку, не
  крашь и не гадай.

## Верификация

Живой смок обязателен (release + `RUST_LOG=info`) — это ЖИВОЙ, не
воспроизводимый синтетическим кликом надёжно на этой машине (см.
`MEMORY.md`: ydotool на этой машине нестабилен) — минион должен прогнать
это ЛИЧНЫМ живым кликом на своей машине/сессии, не полагаться только на
компиляцию:
1. Реальный "Upgrade all" на реальных пакетах (или honest PENDING с
   объяснением, если в моменте нет доступных обновлений для теста —
   тогда хотя бы unit-тест на парсинг прогресс-строк из фикстур
   реального `pacman`-вывода, приложенного в отчёте как сырой текст).
2. Спиннер крутится, полоса растёт, процент меняется, последняя строка
   реально стримит (не статичный текст).
3. Строки списка убираются по мере завершения пакетов, не все разом.
4. По завершении — состояние `Done`/`Failed` рендерится как и раньше
   (не сломано T117's существующий футер-статус).
