## Что реально сломано (не гадать заново — уже диагностировано)

1. **Клик по иконке updates в баре не открывает попап стабильно.**
   Два живых прогона архитектора: первый — попап открылся и тут же
   исчез, хендл остался висеть на мёртвом окне (лог непрерывно спамит
   `updates_popup: resize failed: window not found` / `notify failed:
   window not found` на каждый AUR-poll до перезапуска процесса).
   Второй прогон — клик не дал вообще НИЧЕГО, ни строчки в логе.
2. **Диагностированная причина** (`crates/app/src/bar/widgets/
   updates.rs`, метод `render()`, ближе к концу): внешний `div()`,
   оборачивающий `row.on_mouse_down(...)` и `canvas(...)`, НЕ помечен
   `.relative()`. Без явного позиционирующего предка
   `canvas(...).absolute().size_full()` якорится не к границам этого
   виджета, а куда-то выше по дереву элементов (вероятно вся полоса
   бара) — bounds capture даёт непредсказуемый/чужой прямоугольник,
   из-за чего то клик проваливается в никуда, то попап открывается и
   тут же ловит паразитный dismiss.
3. **Пользователь лично подтвердил: попап визуально НЕ изменился,
   мокапу `design/Updates Popup.dc.html` не соответствует ни в чём.**
   Раз клик не работает — задача провалилась целиком по сути, даже если
   часть кода (Task 3-5 плана) технически на месте: без рабочего триггера
   пользователь физически не может увидеть ни anchored-позиционирование,
   ни визуал.

## Что делать

1. Почини bounds capture: добавь `.relative()` на внешний `div()`
   (`bar/widgets/updates.rs`), который оборачивает `row` + `canvas`.
   Провентилируй результат — после фикса canvas должен якориться ровно
   на границы виджета `row`, не шире/уже. Если `.relative()` само по
   себе не решает (возможна вторая причина — z-order canvas ПОВЕРХ row
   может перехватывать hit-test раньше, чем `row`'s `on_mouse_down`) —
   рассмотри альтернативу: убрать отдельный canvas-overlay и вместо
   этого captur'ить bounds ВНУТРИ `row`'s собственного `on_mouse_down`
   через `window`/`cx` API, если такой путь существует (проверь, не
   выдумывай); иначе — canvas должен идти ПЕРЕД `row` в порядке детей
   (первым child, не вторым), чтобы `row` рисовался и хит-тестился
   поверх, а canvas просто пассивно измерял геометрию под ним.
2. После того как клик реально стабильно открывает попап — сверь
   визуал 1:1 с `design/Updates Popup.dc.html` (dark + light), не на
   слово "код написан по плану" — реальным скриншотом рядом с мокапом.
3. Перепроверь Task 6 из старого плана
   (`docs/superpowers/plans/2026-07-24-updates-popup-anchored-redesign.md`)
   полностью — она обязательна и была пропущена в T116 (отчёт сам
   честно написал "PENDING", просто прошлый минион остановился, не
   передав задачу на доводку сам).
