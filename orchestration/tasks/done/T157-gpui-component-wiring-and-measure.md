## Шаг 1 — проводка

Рецепт доказан пилотом `20ee13a` (`pilot : gpui-component spike`), смотри
его `git show 20ee13a -- Cargo.toml crates/app/Cargo.toml` — там рабочая
форма. Отличия для нас: путь в worktree и **фичи выключены**.

В корневой `Cargo.toml`, в `[workspace.dependencies]`:

```toml
gpui-component = { path = "../Source-wt-component/gpui-component/crates/ui",
                   default-features = false }
```

Компонент тянет `gpui` с `https://github.com/zed-industries/zed` —
одного нашего `[patch."https://github.com/Dark-Ohm/Chronos-GPUI"]` мало,
нужен **второй** patch-блок на zed-URL (в пилоте ровно это и было):

```toml
[patch."https://github.com/zed-industries/zed"]

gpui_macros = { path = "../Source/gpui_macros" }
gpui_platform = { path = "../Source/gpui_platform" }
gpui_web = { path = "../Source/gpui_web" }
```

В `crates/app/Cargo.toml`: `gpui-component.workspace = true`.

**Чего НЕ делать:** не добавлять компонент членом какого-либо `[workspace]`
— ни `Source/Cargo.toml`, ни ChronOS. У него свой воркспейс, и это
правильно. В T155 его сделали членом, не сняв его `[workspace]`, и получили
`multiple workspace roots` — `cargo` перестал работать во всём `Source/`.

## Шаг 2 — потребитель, без которого замер врёт

**Голая зависимость в `Cargo.toml` даёт дельту около нуля и ложное «дёшево».**
У нас `lto = true`, `opt-level = "z"`, `strip = true` — линкер выкинет всё,
на что нет живых ссылок. Мерить надо то, что реально линкуется.

Поэтому в `side_panel_right/view.rs` добавь **один настоящий `TextInput`**
компонента: создание состояния, рендер, ввод с клавиатуры. Не заглушку, не
`let _ = TextInput::...`. Именно поле ввода, потому что ради него всё и
затевается.

Не забудь `gpui_component::init(cx)` (в пилоте — `crates/app/src/main.rs`),
иначе тема/ассеты компонента не поднимутся и рендер упадёт или будет пустым.

**Потребитель — `Button`, а не поле ввода.** В задании (шаг 2) это было

### Потребитель — связка, а не один виджет

Мерить `Button` (первый заход) или один `Input` бессмысленно: в IDE-панели

| Виджет | Зачем в IDE | Что тянет |
