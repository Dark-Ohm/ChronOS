## Состояние System-таба при переключении

`SidePanelRightView` — один персистентный `Entity`, переключение вкладки —
просто смена поля `active_tab`; `self.scroll: ScrollHandle` и всё остальное
состояние структуры НЕ пересоздаются при смене таба (System-тело не
размонтируется/не ремаунтится, это тот же instance view, просто рендерит
другую ветку). Значит state (scroll position, cpu/ram/net истории) переживает
переключение автоматически — если твоя реализация вдруг этого не делает
(например, из-за поспешного рефакторинга `view.rs`), это регрессия, а не
допустимый вариант. Точную формулировку смотри в плане, Task 4, Step 3.
