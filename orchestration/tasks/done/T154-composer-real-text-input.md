## Жалоба пользователя

> «copy paste, drag and drop, that blinking stick when i type»

Три вещи, которых нет: буфер обмена, перетаскивание файлов, мигающая
каретка. По сути — композер сейчас не текстовое поле, а накопитель символов.

## Что сейчас

`handle_composer_key` (`composer.rs:~700`) — самописный разбор клавиш:
`composer_text: String` + `composer_cursor: usize`, символ берётся из
`event.keystroke.key_char`, обрабатываются `backspace`, `left/right`,
`home/end`, `enter`, `shift+enter`. Всё.

Чего нет вообще: каретки на экране, выделения, `Ctrl+C/V/X`, `Ctrl+A`,
удаления выделенного, `Ctrl+←/→` по словам, `delete`, drop файлов, IME.
Курсор двигается по **байтам** (`composer_cursor` сравнивается с
`text.len()`) — на кириллице и иврите это ходячая паника, ровно того
класса, что уже убивала ход (`&prompt[..80]`, 2026-07-28).

## Что в форке уже есть — не изобретать

**Эталонная реализация ввода лежит в дереве:**
`Source/gpui/examples/input.rs` (778 строк) — полноценное поле с кареткой,
выделением, мышью, IME и буфером обмена. Это наш форк под Apache-2.0,
паттерн переиспользуем свободно.

Что там смотреть:

| Нужное | Где в примере |
|---|---|
| структура состояния (`content`, `selected_range`, `selection_reversed`) | `input.rs:36-45` |
| `paste` / `copy` / `cut` через `ClipboardItem` | `input.rs:144-165` |
| `EntityInputHandler` (IME, замена диапазона) | `input.rs:274+` |
| отрисовка каретки и выделения как `PaintQuad` | `input.rs:408, 506-560` |
| курсор `CursorStyle::IBeam` | `input.rs:591` |
| действия и клавиши через `actions!` + `KeyBinding` | `input.rs:16+` |

Буфер обмена в API: `cx.read_from_clipboard()` / `cx.write_to_clipboard()`
(`Source/gpui/src/app.rs:1334, 1349`).
Перетаскивание файлов: `ExternalPaths` (`Source/gpui/src/interactive.rs:685`)
плюс рабочий пример `Source/gpui/examples/drag_drop.rs`.

## Что сделать

1. **Каретка.** Видимая, мигающая, на своём месте по позиции курсора; при
   потере фокуса — не мигает. Мигание — на GPUI-таймере, **не на tokio**
   (правило рантайма, `RULES.md`).
2. **Выделение.** `Shift+←/→`, `Shift+Home/End`, `Ctrl+A`, выделение мышью
   (drag по тексту), двойной клик — слово. Выделенное подсвечивается,
   ввод символа заменяет выделение.
3. **Буфер обмена.** `Ctrl+C`, `Ctrl+X`, `Ctrl+V` через `ClipboardItem`.
   Вставка многострочного текста не должна отправлять сообщение — только
   `Enter` без модификаторов отправляет.
4. **Перетаскивание.** Файл, брошенный на панель → путь(и) вставляются в
   композер текстом (`@путь` или просто путь — реши сам, но одинаково для
   одного и нескольких файлов). Приём — `ExternalPaths`, образец в
   `drag_drop.rs`. Визуальный отклик при наведении с файлом обязателен,
   иначе непонятно, что бросать можно.
5. **Индексы — по символам, а не по байтам.** Любая арифметика по
   `composer_text` обязана быть на границах символов. Проверь руками:
   кириллица, иврит, эмодзи. Паника на срезе — то, что уже стоило нам
   хода.
6. **Ctrl+←/→ по словам, `delete`, `Ctrl+Backspace`** — раз уж всё равно
   переписываешь разбор клавиш.

## Приёмка

Кадры `grim`, снятые исполнителем, плюс живая проверка:

1. Каретка видна и мигает в пустом поле и в середине текста; при клике по
   тексту встаёт в точку клика.
2. Выделение мышью и `Shift+стрелками` подсвечивается; ввод заменяет.
3. `Ctrl+C` из композера → вставка в другое приложение даёт тот же текст;
   `Ctrl+V` многострочного текста из другого приложения не отправляет
   сообщение.
4. Файл, брошенный на панель, появляется путём в поле; при наведении с
   файлом виден отклик.
5. Кириллица, иврит, эмодзи: набор, стрелки, `backspace`, выделение —
   **без паники**. Приложить `grep -c panicked` по логу прогона.

Нет доступа к живому сеансу — так и пиши, «за архитектором»; синтетический
клик/ввод доказательством не считается (у нас полноэкранная игра ломает
даже это — проверено).

Коммит: `panel : что сделано`, без AI-трейлеров, `git add` поимённо,
`git diff --staged` глазами.
