## Формат файла

Точный формат — в плане слайса, раздел «Формат `~/.config/chronos/scenes.toml`».
Скопируй его в докблок модуля, как это сделано в `workspace_mode.rs:1-14`.

**Три вещи, которые обязаны быть правильными с первого коммита:**

1. **`version = 1` в файле.** Не «на будущее» — вариант C (внешние окна)
   утверждён как следующая итерация, файл будет расти. Отсутствие поля
   трактуется как `version = 1`.
2. **Неизвестные секции переживаются, а не затираются.** Парсер обязан не
   падать на `[scene.windows]` (резерв под C) и на любых незнакомых полях.
   **Тест на это обязателен.** Причина: T163 (вчера) стоил двух эррат
   ровно потому, что формат конфига не был рассчитан на рост.
3. **`display` — UUID строкой, никогда не индекс и не `DisplayId`** (§3.6).
   В этом слайсе поле только парсится и сериализуется; **резолвить его в
   реальный вывод НЕ надо** — этого в варианте B нет, и `monitor.rs` в твоей
   зоне отсутствует. Не выдумывай зависимость от него.

## API, на который сядет T165

T165 (композиция рейла и дока) стартует сразу после твоей приёмки и садится
на этот API. Он должен существовать и быть покрыт тестами:

```rust
pub fn current(cx: &App) -> Option<&Scene>;          // активная сцена, если есть
pub fn rail_tabs_override(cx: &App) -> Option<&[String]>;
pub fn dock_override(cx: &App) -> Option<&[String]>;
pub fn active_tab_override(cx: &App) -> Option<&str>;
```

Возвращают `None`, когда сцены нет или поле не задано — это штатный случай,
означающий «бери дефолт режима», а не ошибку. Сигнатуры можно уточнить
(например, отдавать owned `Vec<String>`), если так чище ложится на GPUI —
но семантика «`None` = дефолт режима» неизменна.

## Восстановление последней сцены

§5 спеки: смена режима **может** восстановить последнюю сцену этого режима.
Секция `[last]` в файле хранит `id` последней сцены по каждому режиму.

- при `workspace_mode::set` активная сцена меняется на `[last][новый режим]`,
  если такая сцена есть в файле; если нет — сцена становится `None`
  (композиция = чистый дефолт режима), и это **не ошибка**
- `[last]` обновляется при смене активной сцены и персистится

**Красная линия:** это НЕ автопереключение режима. Ты не добавляешь ни
одного нового вызова `workspace_mode::set`/`toggle`/`request_switch` —
наоборот, `set` зовёт тебя. Контракт слайса 1 («режим не переключается сам»)
проверяется грепом на приёмке, как в T162. Нарушишь — задача отклоняется
целиком, без разговора о качестве остального.

## Тесты

Обязательный минимум, все — на чистых функциях, без GPUI:

1. пустой/отсутствующий файл → дефолт, без паники
2. мусор вместо TOML → `warn` + дефолт, **файл не перезаписан**
3. неизвестная секция `[scene.windows]` и незнакомое поле → парсится, не
   теряет остальное
4. `[last]` резолвится в существующую сцену; ссылка на несуществующий `id`
   → `None`, не паника
5. неизвестный `mode` в сцене → сцена игнорируется с `warn`, остальные живы
6. round-trip: сериализация → парс → те же данные

# ЭРРАТА (2026-07-31, после приёмки первого захода)

## 1. БЛОКЕР: `restore_for_mode` молча уничтожает пользовательский конфиг

`scene.rs:249-251,266,273`:

```rust
let valid = filter_valid(cfg.scene.clone());
cfg.scene = valid;          // отфильтрованные сцены выброшены
...
cfg.last.remove(&key);      // ключ вычищен
save_config(&cfg);          // БЕЗУСЛОВНАЯ запись на диск
```

Живьём: пользователь написал сцену с опечаткой в `mode` (`"developper"`) — при
первом переключении режима она **стирается из его файла навсегда**, с одним
`warn` в логе. Ключ `[last]` для режима без сцены тоже вычищается.

Бриф говорил прямым текстом: битый вход → `warn` + дефолт, **не перезапись**.
Это повтор T163: тихая правка живого конфига под пользователем.

Плюс `save_config` зовётся на **каждый** `set()`, включая не-смену режима —
`set-workspace-mode:developer` при уже developer читает и пишет файл впустую.

**Чинить:**
- `restore_for_mode` **не пишет на диск** и **не мутирует** сохранённый
  конфиг. Фильтрация — только для выбора активной сцены в памяти.
- `[last]` персистится тогда, когда пользователь реально сменил активную
  сцену, а не на каждом `set`.
- Сцены, не прошедшие `filter_valid`, остаются в файле нетронутыми.

## 2. Четыре теста из девяти не проверяют ничего

- `missing_file_returns_default` — не вызывает `load_config()`. Создаёт
  структуру и проверяет `version == 0`. Отсутствующего файла в тесте нет.
- `garbage_toml_returns_default` — проверяет только `toml::from_str` → `Err`.
  Ни дефолта, ни «файл не перезаписан».
- `missing_version_defaults_to_one` — **воспроизводит логику
  `if version == 0 { version = 1 }` внутри самого теста** вместо вызова
  `load_config`. Тест проверяет свой собственный код.
- `empty_overrides_return_none` — проверяет, что пустой вектор пуст.
  `rail_tabs_override` не вызывается ни разу, хотя тест назван в его честь.

**Чинить:** переписать так, чтобы они звали реальные функции. Для файловых
кейсов — временный каталог и параметризуемый путь (или вынести чистую
`parse_config(&str) -> ScenesConfig` и тестировать её).

Работают по-настоящему и трогать не надо: `unknown_section_and_field_preserved`,
`resolve_last_existing_and_missing`, `resolve_last_mode_mismatch`,
`unknown_mode_scene_filtered`, `roundtrip`.

## 3. Forward-compat доказан только на чтении

`[scene.windows]` проверен при **парсинге**. А модуль теперь **пишет** файл, и
`toml::to_string_pretty` с `#[serde(flatten)]`-таблицей рядом с массивом
`[[scene]]` — классическое место, где сериализатор падает на «values must be
emitted before tables». Round-trip-тест гоняет `extra: HashMap::new()` — то
есть ровно тот случай, который ничего не проверяет.

**Чинить:** round-trip с **непустым** `extra`, включая `[scene.windows]` и
скалярное неизвестное поле. Если сериализация в этом случае падает — это
находка уровня плана, пиши в отчёт, не глуши.
