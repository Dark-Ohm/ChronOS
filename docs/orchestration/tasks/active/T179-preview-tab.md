## Решение по объёму — принято Архитектором с пользователем, не обсуждается

Спека хочет «browser or GPUI preview surface». **Встроенного webview в
дереве нет и в этом слайсе не появится.** Поэтому первая версия делает то,
что мы честно умеем: показывает **файл, выбранный во вкладке Files**.

- изображения: `png`, `jpg`/`jpeg`, `svg`, `webp` (что реально отрисуется —
  проверь; `svg` идёт через `usvg`, и он **не поддерживает
  `mix-blend-mode`** — если картинка выглядит битой, это может быть он);
- `markdown` — рендером, а не сырым текстом. Фича `markdown` уже в
  `default` у `gpui-component` (`../Source/gpui-component/crates/ui/Cargo.toml:18`),
  добавлять ничего не надо;
- прочий текст — как текст, с потолком по размеру;
- бинарь или неизвестный тип — честно сказать тип и размер, не пытаться
  рисовать.

**Веб-превью — честное `unavailable` по §13:** сказать прямо, что движка
предпросмотра веб-поверхностей в шелле нет. Не «coming soon», не заглушка
под работающий инструмент.

## 1. Связка Files → Preview

Точка расширения уже заложена в T176 и ждёт тебя:

```rust
fn open_entry(&mut self, entry: &FileEntryDto, cx: &mut Context<Self>) {
    if entry.kind == "dir" {
        self.navigate_to(PathBuf::from(&entry.path), cx);
    }
    // Files: read-only v1 — no open/preview (later capability / Editor tab).
}
```

`crates/app/src/side_panel_right/tab/files.rs:125-130`.

Клик по **файлу** (не каталогу) должен доехать до Preview. Вкладки — разные
сущности в `HashMap<PanelTab, TabContent>` (`view.rs`), напрямую друг друга
не знают, и лезть в `view.rs` тебе нельзя.

Механизм выбираешь ты. Разумный путь — GPUI-глобал с целью превью, на
который Preview подписан (`cx.observe_global`); образец глобалов в дереве —
`crates/app/src/bar/widgets/dock.rs` (`register()`, `has_global`) и
`workspace_mode`. Обоснуй выбор строкой в отчёте.

**Требования к поведению:**
- клик по файлу в Files **не переключает** вкладку сам. Пользователь кликнул
  — цель запомнена; откроет Preview — увидит её. Автопереключение вкладки
  под рукой пользователя раздражает и ломает T174 (авто-фолбэк вкладки);
- Preview открыт без единого клика в Files — честное «ничего не выбрано» с
  указанием, что выбирать надо в Files;
- регрессия: навигация по каталогам в Files продолжает работать ровно как
  сейчас, тесты T176 не переписываются.

## 2. Чтение файла

Читать **в `cx.background_spawn`** — вкладка не имеет права подвиснуть на
большом файле или на медленном диске. Образец — `FilesTab::request_reload`
(`files.rs:54`).

Потолок по размеру: текст выше потолка — показать начало и честно сказать,
что обрезано (как `truncated` в T176). Картинку выше потолка — не грузить,
сказать размер.

Ошибки — по-настоящему: нет прав, файл исчез между кликом и чтением, битая
кодировка. Точный текст, не «failed to load».

## 3. Ширина

Сейчас `Preview` в группе пустых вкладок — **320 px** (`tabs.rs`,
`preferred_content_width`). Для картинок и markdown мало.

Замерь и обоснуй **числом**. Ориентир — 440, как у Files, но это ориентир,
а не ответ: **спека и замер выше моего ориентира**, расхождение с
обоснованием — плюс тебе. Механика ширины готова (T171), от тебя значение.

## 4. Честные состояния (§13, §41)

- ничего не выбрано — сказать, где выбирать;
- тип не поддерживается — назвать тип и размер;
- файл не читается — точная причина;
- веб-превью — `unavailable` с причиной «нет движка», без обещаний срока;
- никаких «coming soon», никакой демо-картинки вместо реального файла.

## Тесты

- определение типа по расширению/содержимому — чистой функцией;
- потолки размера: текст обрезается и отмечается, крупная картинка не
  грузится;
- цель превью: установка из Files и подхват в Preview — без живого клика,
  на уровне состояния;
- вьюха: `#[gpui::test]` с `TestAppContext` — ленивое создание и кэш, как
  для System/Files/Terminal в `tab/mod.rs`;
- Files: существующие тесты (`files_tab_settles_after_background_list`,
  `files_tab_error_on_missing_path`, `truncated_state_when_limit_hit`)
  продолжают проходить **без правок**.

Тест, воспроизводящий логику продукта внутри себя, тестом не считается.

Вывод — в отчёт.

**Живой прогон обязателен.** Релиз, `RUST_LOG=info`, лог в файл.

1. `set-workspace-mode:developer`, открыть панель
   (`toggle-side-panel-right`), Preview без выбора — честное пустое
   состояние. Кадр.
2. Files → клик по `README.md` → Preview: markdown отрисован, а не сырой
   текст. Кадр. **Открой глазами и убедись, что это рендер** — заголовки,
   списки, а не решётки и звёздочки.
3. Клик по картинке (в дереве полно: `crates/app/assets/icons/*.svg`,
   `docs/design/*`) → изображение видно. Кадр.
4. Клик по бинарю (`target/release/chronos`) → честный отказ с типом и
   размером, не попытка отрисовать. Кадр.
5. Регрессия: навигация по каталогам в Files и кнопка `reload` работают как
   раньше. Кадр.
6. Лог целиком: `grep -n "panicked at" лог`.

IPC-сокет `$XDG_RUNTIME_DIR/chronos.sock`, рестарты не нужны.

Рейл — крайние 54 px справа (`x = 2506…2560`), иконки от `y ≈ 57` шагом
≈ 40. `ydotool` берёт **половинные** координаты (подтверждено восемь раз),
сокет `YDOTOOL_SOCKET=/run/user/1000/.ydotool_socket`.

**Кадры открывать глазами и подписывать тем, что на них.** В T177 два кадра
были подписаны не своим содержимым — при приёмке это вскрывается сразу.
Мелкое вырезать и увеличивать:

```
magick кадр.png -crop 560x1410+2000+30 +repage -filter point -resize 200% out.png
```

**Если инструмент не смог что-то проверить — пиши «не смог проверить
инструментом», а не «функция не работает».** В T177 исполнитель объявил
сломанной работающую клавиатуру, потому что `ydotool` не доставил ввод.
Занижать свою работу так же вредно, как приукрашивать.

Пультовый вывод бывает занят фуллскрин-игрой — занят, пиши «не проверено» с
причиной, в игру не лезь. Это засчитывается.
