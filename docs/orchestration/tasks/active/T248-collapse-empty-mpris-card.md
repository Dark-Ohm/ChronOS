# T248 — свернуть пустую "No player" mpris-карточку в компактное состояние

**Приоритет:** P1.
**Роль:** FRONTEND (Rust, GPUI).
**Источник:** `docs/orchestration/tasks/report-log/T223-design-audit-report-v4-reshoot.md`
находка #2 (табл. §3), топ-10 п.2.

## Контекст

`crates/app/src/side_panel_right/mpris_card.rs`, `render_mpris_card()`
(строки 158+) рендерит art-фрейм (`render_art_frame`, "~16:9 of 352
content width" по комментарию строка 183) **безусловно**, даже когда
`state.has_player == false` (`display_title()` строки 20-34 уже отдаёт
"No player" в этом случае — состояние знает, что плеера нет, но
геометрия карточки не реагирует). Вызывается из
`crates/app/src/side_panel_right/tab/system.rs:152`.

Аудит: занимает ~220px вертикали дефолтного System-таба под пустой
чёрный прямоугольник-плеймейкер, когда нет никакого медиа. Вместе с
находкой T246 (permission-мок) — верхняя половина дефолтного экрана
из двух вещей, ни одна из которых не показывает ничего работающего.

## Что нужно

Когда `state.has_player == false` — компактное состояние карточки: без
art-фрейма (16:9 блока), без progress/transport controls, только
маленькая строка "No player" (текст + опционально приглушённая
mpris-иконка), высотой на уровне обычной строки текста, не ~220px.
Как только реальный плеер появляется (`has_player == true`) — обратно
полная карточка с art/progress/controls, без анимационного скачка,
который бы сам по себе выглядел как баг (просто conditional render,
не transition — приемлемо).

## Зона файлов

`crates/app/src/side_panel_right/mpris_card.rs` — основная правка.
`crates/app/src/side_panel_right/tab/system.rs` (строка 152, вызов) —
**тот же файл, что у T246** (там правки на строках 17/139). Не
запускать T246 и T248 параллельно на одной ветке без координации —
оба меняют `system.rs`, конфликт мержа гарантирован при одновременных
правках.

## Верификация

- Живой grim: System-таб без активного плеера, обе темы — карточка
  компактная, не занимает четверть панели под пустоту.
- Живой grim с реальным плеером (`playerctl` / любой mpris-источник) —
  полная карточка с art/progress рендерится как раньше, регрессии нет.
- `cargo build --release -p chronos` чисто, `cargo test --release -p
  chronos --lib -- side_panel_right` зелёные — юнит-тест на
  `display_title`/`has_player` уже есть (строка 352 файла), добавить
  тест на размер/вариант рендера, если тестируется без живого окна
  (иначе — просто живой grim как единственное доказательство, честно
  пометить в отчёте).
