# T163 — bar.toml: новый builtin-виджет не доезжает до пользователя

**Статус:** active. **Роль:** FRONTEND. Общие правила —
`docs/orchestration/agents/RULES.md`.

## Что сломано

`BarLayoutConfig::load()` (`crates/app/src/bar/layout_config.rs:106`) читает
`~/.config/chronos/bar.toml`. **Если файл существует, `Default` не
применяется никогда.** Значит любой новый встроенный виджет, добавленный в
дефолтный вектор, невидим у каждого, кто хоть раз трогал раскладку бара —
а её трогает edit-mode (T134), то есть файл есть почти у всех.

Вскрылось на приёмке T161 (2026-07-31): переключатель режима был написан
корректно, тесты зелёные, дефолт обновлён — и бар при живом прогоне оказался
без виджета. Пришлось руками дописывать `"workspace_mode"` в пользовательский
`bar.toml`, чтобы вообще увидеть фичу.

Это не разовая неприятность: то же самое повторится с каждым следующим
виджетом бара.

## Что нужно

Одноразовая миграция при загрузке: если в `BUILTIN_NAMES` есть имя, которого
нет ни в одной секции пользовательского конфига, и это имя **новее** конфига —
дописать его в ту секцию, где оно стоит в `Default`, на ту же позицию
относительно соседей.

**Осторожно с обратной стороной:** пользователь мог удалить виджет
намеренно. Слепое «дописывать всё, чего нет» вернёт удалённое и взбесит.
Поэтому нужен способ отличить «никогда не видел» от «убрал сознательно».

Варианты, решай сам и обоснуй в отчёте:

- **A. Версия схемы.** В `bar.toml` поле `schema = N`. Миграция знает, какие
  имена появились после версии N, и дописывает только их. Файл без `schema`
  считается версией 0.
- **B. Список известных имён.** Хранить в конфиге `known = [...]` — всё, что
  пользователь когда-либо видел. Новое = `BUILTIN_NAMES` минус `known`.
  Удалённое остаётся в `known` и не воскресает.
- **C. Не мигрировать, а сообщить.** При старте warn в лог + одноразовое
  уведомление «появился новый виджет X, добавь его в bar.toml или через
  edit-mode». Дёшево и честно, но требует от пользователя действия.

Моё предпочтение — **B**: не требует версионирования, переживает откаты, и
семантика «известное» точнее отражает задачу, чем номер схемы. Но если
найдёшь в дереве причину против — бери другое и объясни.

## Зона файлов

- `crates/app/src/bar/layout_config.rs` — миграция + тесты
- при варианте C дополнительно: место, откуда шлётся уведомление

**Не трогать:** `crates/app/src/bar/widgets/**`, `side_panel_*`, `ipc/**`.

## Обязательные тесты

- Конфига нет → берётся `Default`, миграция не срабатывает.
- Конфиг без нового виджета → виджет дописан в правильную секцию и позицию.
- Пользователь удалил существующий виджет → **после перезапуска он НЕ
  вернулся**. Это главный тест, ради него всё и затевается.
- Конфиг с мусорным именем → мусор отфильтрован `sanitized()`, миграция не
  падает.
- Миграция идемпотентна: второй запуск ничего не меняет.

## Живая проверка

1. Сохрани копию своего `~/.config/chronos/bar.toml`.
2. Убери из него какой-нибудь виджет, запусти шелл — виджет **не вернулся**.
3. Убери `workspace_mode` (если он там есть), запусти — **вернулся**, потому
   что пользователь его никогда не видел.
4. Кадр бара `grim -g` по геометрии из `hyprctl layers`.
5. Верни свою копию конфига.

`chronos` сейчас запущен пользователем — перед прогоном `pkill -x chronos`,
после прогона верни его оболочку поднятой и скажи об этом в отчёте.
