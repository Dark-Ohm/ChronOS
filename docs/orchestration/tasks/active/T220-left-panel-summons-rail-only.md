# T220 — Левая панель при призвании появляется рейлом, а не раскрытой

**Статус:** active, не начата  
**Источник:** live dogfood 2026-08-03 — «чтоб левая рельса не раскрывала панель при
призвании, а просто появлялась»  
**Приоритет:** P1 product  
**Параллель:** можно брать одновременно с T219/T221/T222 — зоны не пересекаются
(только `side_panel_left/`).

## Как сейчас

`crates/app/src/side_panel_left/state.rs:64` — панель стартует с
`width: Self::DEFAULT_CHAT_WIDTH` (`state.rs:114`, **352 px**). То есть любой
призыв — `open_pinned` / `open_peek` (`mod.rs:1129`, `:1133`) — сразу выкатывает
полноценную колонку чата.

Правая панель ведёт себя иначе и правильно: `side_panel_right/mod.rs:206` при
обычном открытии принудительно ставит `width = RAIL_ONLY_WIDTH`, а контент
раскрывается отдельным действием.

Нужное «рейл-онли» число слева **уже существует**:
`side_panel_left/sessions_list.rs:85` — `SIDEBAR_MIN_WIDTH = SIDEBAR_COLLAPSED_WIDTH
+ SIDEBAR_HANDLE_WIDTH`, ровно как справа `RAIL_ONLY_WIDTH = RAIL_WIDTH +
HANDLE_WIDTH`. Кросс-панельный тест на равенство ручек/рейлов уже стоит:
`side_panel_left/mod.rs:1284 rails_and_handles_match_right_panel`.

## Решение

Призыв открывает панель шириной `SIDEBAR_MIN_WIDTH` — видна только рельса. Чат
раскрывается отдельно: ручкой (drag) или тем же аффордансом, которым он
раскрывается сегодня после сворачивания (`toggle_collapse`, `mod.rs:453`).

Требования:

1. **Память ширины.** Раскрыв чат до N и закрыв панель, следующий призыв обязан
   снова дать рейл — но раскрытие должно вернуть N, а не дефолтные 352. Правая
   панель хранит такое в `tab_resize_memory`; слева достаточно одного числа.
2. **Exclusive zone.** Резерв обязан соответствовать реальной ширине в обоих
   состояниях (`state.rs:92 exclusive_px`), иначе окна лягут под панель или
   останется мёртвая полоса. Это уже кусалось в T206 справа.
3. **Смоук-рецепты не врут.** В `docs/HANDOFF.md` записан рецепт открытия панелей;
   после этой задачи левая часть рецепта меняется — поправить там же, иначе
   следующий живой прогон будет ловить «пустые кадры» ровно так, как это описано
   в HANDOFF про правую панель.

## Зоны файлов

- `crates/app/src/side_panel_left/mod.rs` — `open_window` / `open_pinned` / `open_peek`
- `crates/app/src/side_panel_left/state.rs` — стартовая ширина, память раскрытой
- `crates/app/src/side_panel_left/hover_strip.rs` — если призыв идёт через полосу
- `docs/HANDOFF.md` — поправить рецепт

Не трогать: `side_panel_right/`, `bar/`.

## Приёмка

```bash
cargo test -p chronos --lib side_panel_left
cargo build --release -p chronos
```

Тесты: призыв даёт `SIDEBAR_MIN_WIDTH`; раскрытие возвращает запомненную ширину, а
не дефолт; `exclusive_px` совпадает с шириной в обоих состояниях.

**Live (обязателен):** призвать панель — видна только рельса, чат не выехал;
раскрыть, закрыть, призвать снова — снова рельса; окна не заезжают под панель.
`hyprctl layers | grep side_panel_left` до и после. Кадры `grim`.

**Коммит:** `panels : left summons rail-only (T220)`.
