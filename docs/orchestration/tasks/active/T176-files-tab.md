## Что делаем — коротко

Вкладка Files = **портированный слой FS** + **своя узкая вьюха**, написанная
по образцу `SystemTab`.

UI проводника из Chronos-FM **не переносится**. Разведка посчитала: его
таблица ~928 px против нашей вкладки в 440, плюс он завязан на `Page`-фреймворк
и чужую тему. Полный перенос ≈ 3–4 тыс. строк борьбы, свой `FilesTab` ≈
0.7–1.0 тыс.

## 1. Порт слоя FS

Из `../Chronos-FM` берётся, с сохранением авторства (это проект того же
автора, лицензионных препятствий нет):

| Что | Откуда | Строк |
|---|---|---|
| `ListParams`, `ListResult`, `list_dir_sync` | `chronos-fm-services/src/fs/listing.rs` | 195 |
| `FileEntryDto` | `chronos-fm-models`, `file_entry.rs:9-21` | 45 |
| сортировка записей | `chronos-fm-pages/src/explorer/entries.rs` | ~80 |

`listing.rs` — **ноль GPUI**, чистый `std::fs`. Тип ошибки у них свой
(`chronos_fm_core::errors`, 18 строк) — можешь скопировать тонко или
заменить на `anyhow`/свой enum, реши и обоснуй.

**`fs/ops.rs` (389 строк) в эту задачу НЕ входит.** §4.1 прямо: «read-oriented
project tree with **later file operations behind explicit capability work**».
Никакого удаления, переименования, копирования в UI. Не тащи и зависимость
`trash`.

### Кровное: листинг блокирующий

`list_dir_sync` синхронный. В Chronos-FM его зовут **прямо в обработчике**
(`navigation.rs:17-25`, `view.rs:62`) — так делать нельзя, у нас правило
Runtime split (`docs/DECISIONS.log`): тики и UI на GPUI-исполнителе.

Листинг обязан уходить в `cx.background_spawn`, результат применяться на
foreground. Лимит каталога по умолчанию 1000 записей (`config.rs:65`) —
даже тысяча на UI-потоке это заметный кадр.

Тесты на сам листинг у них есть — перенеси их вместе с кодом.

## 2. Вьюха

Образец — `crates/app/src/side_panel_right/tab/system.rs`: своя GPUI-сущность
со своим `Render`, создаётся лениво через `TabContent::create`, живёт в кэше.
`FilesTab` делается ровно так же.

**Ширина 440 остаётся.** UI под неё, а не наоборот:

- **одна колонка**: иконка + имя, размер приглушённым справа;
- **строка пути сверху** — текст, не хлебные крошки с виджетами;
- `Enter` / двойной клик — переход в каталог, `..` — вверх;
- каталоги выше файлов, дальше по имени (это и есть портированная
  сортировка);
- **без sidebar**, **без бокового превью** — им в 440 px места нет.

### Про `VirtualList` — по возможности обойдись без него

Разведка показала: `Table` не нужен, а `VirtualList` в Chronos-FM
используется. У нас он есть в `gpui-component` и стоит по замерам T157
всего +15 KB.

**Но** `gpui-component` подключён path-депом на **воркетри**
`../Source-wt-component/` — временный путь, который может исчезнуть при
чистке. Поэтому: если список на 1000 записей нормально живёт на обычном
скролле — сделай на обычном и **скажи это в отчёте**. Если упрётся в
производительность — бери `VirtualList` и приложи замер, обосновывающий
выбор. Не бери его «на всякий случай».

## 3. Честные состояния (§13)

- пустой каталог — «каталог пуст», не пустой экран;
- нет прав на чтение — сказать прямо, что именно не прочиталось;
- каталог обрезан лимитом — **показать это**, а не молча отдать первую
  тысячу.

Никаких «coming soon» и обещаний.

## Верификация

```
cargo test -p chronos
cargo clippy -p chronos --all-targets
cargo build --release -p chronos
```

**Живой прогон обязателен.** Релиз, `RUST_LOG=info`, лог в файл. Панель и
режим — по IPC без рестартов:

```python
import socket
s = socket.socket(socket.AF_UNIX); s.connect("/run/user/1000/chronos.sock")
s.sendall(b"toggle-side-panel-right"); s.close()
```

Что снять:

1. Вкладка Files открыта — список читается, иконки и имена на месте,
   ширина слоя **440** (`hyprctl layers`, namespace `side_panel_right`);
2. переход в подкаталог и обратно через `..`;
3. каталог с большим числом файлов — списком можно пользоваться, UI не
   застывает (это проверка `background_spawn`);
4. каталог без прав (`/root` подойдёт) — честное сообщение, не пустота и не
   паника;
5. лог целиком: `grep -n "panicked at" лог`.

Рейл — крайние 54 px справа (`x = 2506…2560`), иконки от `y ≈ 57` шагом ≈ 40;
Files — вторая сверху. `ydotool` берёт **половинные** координаты
(подтверждено семь раз), сокет `YDOTOOL_SOCKET=/run/user/1000/.ydotool_socket`.

**Кадры открывать глазами**, мелкое — вырезать и увеличить:

```
magick кадр.png -crop 440x1410+2120+30 +repage -filter point -resize 200% out.png
```

Пультовый вывод бывает занят фуллскрин-игрой. Занят — пиши «не проверено» с
причиной, в игру не лезь. Это засчитывается.
