# T254 — досъёмка оставшихся 8 поверхностей брифа T223 (блокировано вводом)

**Приоритет:** P2 — трекинг-тикет, не начинать работу, пока блокер жив.
**Роль:** нет исполнителя, пока блокер не снят.
**Источник:** `docs/orchestration/tasks/report-log/T223-design-audit-report-v4-reshoot.md`
топ-10 п.7, §6 "Чего не увидел".

## Контекст

После двух заходов T233 (пересъёмка чистого стола) 8 обязательных
поверхностей брифа T223 остаются NOT CAPTURED — все требуют
синтетического клика/курсора, которого физически нет:

- Виджет раскладки клавиатуры (клик-цикл)
- Редактор в режиме правки (клик по файлу + Edit)
- Композер + открытый dropdown модели
- Popup громкости/OSD (нет IPC)
- Попап уведомлений/трей (нет IPC)
- Drag ручки ресайза, hover-strip peek клипы (нужен синтетический курсор)
- Правый рейл Edit Mode (T219 стрелки/рамка) — `toggle-edit-mode`
  рейл не переключает, нет отдельной IPC-команды
- Gamer-рейл (Library/Captures) — сверх обязательного минимума, не
  блокер, но тоже недостижим

Корень — `ydotool` мёртв (известно давно), `wtype` печатает в seat
compositor'а, не в GPUI-окно (обойдено для текста через T241
`compose-and-send`, но НЕ для кликов/курсора — это отдельный класс
проблемы, IPC-инъекция текста не решает "нажать эту кнопку мышью").

## Что нужно

**Не начинать съёмку** — сначала снять блокер:
1. Диагностировать `ydotool`/`uinput` на этой машине заново (последний
   раз отмечено "erratic весь вечер" 2026-08-04, возможная связь с
   `cachyos-kernel-modules-mismatch` — modprobe падает после апдейта
   ядра до ребута, см. Claude-память `cachyos-kernel-modules-mismatch.md`).
   Если это оно — ребут решает, не код.
2. Если `ydotool` в принципе нежизнеспособен на Wayland/Hyprland для
   этого класса задач — рассмотреть IPC-инъекцию для оставшихся
   поверхностей по образцу `compose-and-send` (T241): не эмулировать
   курсор, а дать каждой поверхности прямую IPC-команду
   (`toggle-keyboard-layout-widget`, `open-model-dropdown`,
   `trigger-osd:volume`, и т.д.) — дороже (нужна отдельная команда на
   каждую поверхность), но обходит блокер полностью, тем же методом,
   что уже сработал для текста.

## Зона файлов

Диагностика — вне дерева (kernel/systemd). Если выбран путь "IPC per
surface" — затрагивает IPC-диспетчер + каждую конкретную поверхность,
заводить отдельные под-тикеты по факту решения, не в рамках этого.

## Верификация

Блокер снят = хотя бы один живой клик по кнопке в GPUI-окне ChronOS от
синтетического источника (курсор ИЛИ IPC-эквивалент) подтверждён живым
grim до/после, показывающим реакцию UI.

## Коммит

Нет — это трекинг-тикет, реализация уйдёт в под-тикеты по факту снятия
блокера.

## Статус (2026-08-05) — блокер снят, backlog не закрыт

Живая проверка подтвердила: `ydotoold` активен, `/dev/uinput` доступен,
реальный клик через `ydotool mousemove --absolute` + `click 0xC0` дошёл
до GPUI layer-shell (rail-кнопки Library → Captures переключились,
геометрия панели подтверждена `hyprctl layers` до/после). Блокер из п.1
("диагностировать заново") снят фактом успешного клика — судя по всему,
`cachyos-kernel-modules-mismatch` разрешился ребутом с прошлой сессии.

Снято по факту: **1 из 8** поверхностей (Gamer-рейл Library/Captures —
пункт сверх обязательного минимума). Остаются NOT CAPTURED: клавиатурная
раскладка, редактор Edit Mode, композер+dropdown модели, volume/OSD
popup, notifications/tray popup, drag ручки ресайза + hover-strip peek,
правый рейл Edit Mode (T219). Держать активным, работа возобновляема
обычным `ydotool` без IPC-инъекции (план "б" из raздела "Что нужно" не
понадобился — план "а", ребут, сработал).
