# T256 — заголовок правой панели врёт: захардкожен "kitty"

**Роль:** FRONTEND (Rust, GPUI), минимум кода.
**Источник:** живая приёмка T253/T254 (2026-08-05) — при просмотре
собственных кадров T253 (`system-dark.png`/`system-light.png`) архитектор
заметил заголовок `kitty` с крестиком над System-табом на ОБОИХ кадрах,
хотя фокус на момент съёмки был на разных окнах/терминалах, не kitty.
**Приоритет:** P1 — тот же класс обмана, что T246 (фейковый
permission-мок), просто пропущенный всеми предыдущими 11 отчётами и
самим T223-аудитом.

## Находка (код, не гипотеза)

`crates/app/src/side_panel_right/header.rs:7-8`:

```rust
/// Static title until active-window wiring lands.
const WINDOW_TITLE: &str = "kitty";
```

`render_header()` рисует эту строку как заголовок правой панели (весь
таб, не только System) с полным правом выглядеть как «название активного
окна рабочего стола» (шрифт semibold, позиция — там, где обычно
window-title). Рядом — кнопка с крестиком, которая **не закрывает
никакое окно** — она вызывает `crate::side_panel_right::close_this`, т.е.
закрывает саму панель. Название "kitty" никогда не меняется независимо
от того, какое окно реально в фокусе (проверено живьём: `hyprctl
activewindow` в момент T253-съёмки показывал `Freebuff: пиши отчет` /
другой kitty-таб, заголовок панели всё равно "kitty" статично).

Это системная имитация: пользователь видит текст, синтаксически похожий
на «название активного окна», который никогда не отражает реальность —
ровно тот же принцип обмана, что был у permission-мока (T246), просто
не find'нутый визуальным аудитом, потому что совпал по смыслу с реальным
приложением в кадре (kitty терминал реально был на экране в моменты
съёмки прошлых волн — совпадение маскировало баг).

## Что нужно

Два варианта, выбери пользователь перед реализацией (та же дисциплина,
что T240/T246 — spec решение, не код в лоб):

**Вариант А — реальная проводка.** Подключить `WINDOW_TITLE` к реальному
активному окну композитора (`hyprctl activewindow` эквивалент через
существующий Hyprland IPC слой сервисов, если он уже читает окна —
проверить `crates/services/src/` на предмет существующего window-watcher
перед тем как писать новый). Крестик либо реально закрывает то окно
(доп. риск — hyprctl dispatch мёртв в этой версии Lua-Hyprland, см.
skill `hyprland-ecosystem`/DECISIONS.log), либо остаётся «закрыть
панель», но тогда его нужно визуально отделить от заголовка окна (не
рядом с чужим названием).

**Вариант Б — честная переименование.** Если window-tracking не входит
в MVP-scope сейчас — заголовок должен называться тем, что он есть
("System" / имя таба, как остальные вкладки — сверься с
`tab/acp_settings.rs`/`tab/hypr_binds.rs`, у них заголовок = имя таба, не
фейковое название стороннего окна), а крестик — обычная кнопка закрытия
панели без маскировки под «закрыть окно».

**Не заводить эту правку самостоятельно без спроса** — тикет только
диагностирует, реализация после решения пользователя (тот же процесс,
что T240 → T255).

## Верификация (после решения и правки)

- `cargo build --release -p chronos` — чисто.
- `cargo test --release -p chronos --lib -- side_panel_right` — 167/167.
- Живой grim, обе темы, минимум 2 разных активных окна в фокусе на
  момент съёмки (не kitty) — заголовок панели должен либо показывать то
  реальное окно (вариант А), либо не изображать окно вообще (вариант Б).
