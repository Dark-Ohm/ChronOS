# T274 — виджет проектов: контекст сессии агента, контекстное меню, выбор ветки, полировка попапа

**Приоритет:** P1 — задевает связку «проект = корень для всего шелла»,
ради которой Shell-IDE и строится.
**Роль:** FRONTEND (`crates/app/src/project_switcher/**`,
`crates/app/src/bar/widgets/project.rs`, `crates/app/src/side_panel_left/mod.rs`).
**Зависимость:** части C и D делаются ПОСЛЕ коммита T263 — меню строится на
том же `gpui-component::PopupMenu` и anchored-popup пути. Части A и B
независимы, их можно начинать сразу.

## Улики (живые кадры архитектора 2026-08-13)

## Часть A — сессия агента стартует в активном проекте

**Дефект.** `side_panel_left/mod.rs:526`:

```rust
let cwd = std::env::current_dir().unwrap_or_default().to_string_lossy().to_string();
```

Новая ACP-сессия укореняется в рабочем каталоге ПРОЦЕССА ШЕЛЛА. Шелл
автостартует композитор при логине, значит там `$HOME` или `/` — корень
случайный и не меняется никогда. Контекст расщеплён: таблетка проекта
задаёт корень для Build (`services/tasks/`) и терминала, а агент слева
живёт отдельно. Пользователь переключил проект, Build показывает его
задачи — а агент на «почини тест» идёт искать файлы не там.

**Что сделать.**

1. `create_new_session` берёт корень из активного проекта
   (`project_switcher::cached()`, поле активного проекта). `current_dir()`
   остаётся фолбэком, когда активного проекта нет.
2. **Существующие треды не трогать.** Их `cwd` уже лежит в сторе
   (`threads.cwd`) и передаётся в `session/load` (`mod.rs:622-669`) —
   ретроспективно переписывать нельзя, иначе старые сессии переедут в
   чужой каталог.
3. Убрать `.unwrap_or_default()`: пустой `cwd` — не валидное состояние,
   ниже уже стоит костыль `!cwd.is_empty()` (`mod.rs:651`), который лечит
   симптом. Нет корня — не создавать сессию, сказать об этом в UI.
4. Смена активного проекта НЕ переносит открытую сессию. Новый корень
   действует со следующей новой сессии — иначе агент посреди работы
   потеряет контекст. Поведение назвать явно в UI (см. часть D).

## Часть B — полировка попапа (не требует T263)

1. **Нижняя строка обрезана.** `popup_height()` (`mod.rs:145-147`) считает
   `HEADER_H + n*ROW_H + ADD_ROW_H` и не учитывает паддинги/бордер/тень
   карточки — контент выше окна. Это известная ловушка форка
   («footer clipped», скилл `chronos-gpui-popup`). Считать высоту от
   реального контента, а не от суммы констант; проверить на 1, 3 и 12
   проектах (`MAX_ROWS`).
2. **Язык UI — английский** (планка T252/T269, `DECISIONS.log` 2026-08-13).
   В попапе сейчас шесть русских строк:
   `view.rs:48` «Проекты», `:71` «Пока пусто — добавь первый`,
   `:144` «+ Добавить проект», `mod.rs:247` заголовок портала
   «Добавить проект», плюс `bar/widgets/project.rs:33` фолбэк «проект».
   Все — на английский. Локаль даты/времени тут ни при чём, исключение не
   применяется.
3. **Empty-state по канону T252.** «Пока пусто — добавь первый» не
   объясняет, откуда берутся проекты. Заменить на honest hint через
   `empty_state_note` (T269), сказав про `~/.config/chronos/projects.toml`
   и кнопку добавления.

Правый клик по таблетке открывает меню на том же движке, что трей и док

`docs/design/Chronos-Context-Menu.dc.html`). Состав:

- **Open in terminal** — вкладка Terminal в корне проекта;
- **Open in Files** — вкладка Files там же;
- **Copy path**;

- **Remove from list** — только из списка ChronOS, каталог на диске НЕ

Пункт без работающего действия не добавлять (планка T246).

## Часть D — подменю выбора ветки (после T263)

**Это мутация чужого репозитория из бара. Осторожность — часть задачи.**

1. **Список веток.** Читать `.git/refs/heads/` плюс `.git/packed-refs`
   (ветки часто упакованы, только каталога недостаточно). Учесть
   worktree-случай: `current_branch` (`mod.rs:113-131`) уже умеет
   `gitdir:` — переиспользовать эту логику, не писать вторую.
   Текущая ветка помечена галочкой (`.checked()`).
2. **Переключение — через `git` подпроцессом**, не своей реализацией:
   `git -C <path> checkout <branch>`. Свой чекаут — верный способ
   испортить рабочее дерево пользователя.
3. **Грязное дерево = запрет.** Перед показом подменю проверить
   `git -C <path> status --porcelain`. Не пусто → пункты переключения
   `.disabled()`, причина видна («Working tree has uncommitted changes»).
   Молча переключать нельзя: `checkout` при конфликте оставит человека с
   наполовину переехавшим деревом.
4. **Ошибка — видимая.** Непустой stderr от `git` показывается тостом с
   текстом ошибки, а не глотается (правило про `let _ =`).
5. **Подпроцесс не на рендер-потоке.** `git` дёргается из
   `crates/services`, результат приезжает в UI сообщением. В `render()`
   ничего не спавнить — это правило уже записано в T266 по поводу
   `hyprctl`.
6. Ветка в баре обновляется сама на секундном тикере — специально
   инвалидировать ничего не нужно.

## Верификация

- **Часть A:** новая сессия в проекте X — в `threads.cwd` лежит путь X
  (проверить в сторе), агент видит файлы X. Переключение проекта при
  открытой сессии её не переносит. Без активного проекта — фолбэк
  работает, пустой `cwd` не создаётся.
- **Часть B:** кадры попапа при 1, 3 и 12 проектах — нижняя строка видна
  целиком. Ноль русских строк: `grep -rn '[А-Яа-я]' crates/app/src/project_switcher/`
  даёт только комментарии/тесты.
- **Части C/D:** живые кадры меню (rest/hover/disabled), кадр подменю
  ветокв двух состояниях — чистое дерево и грязное (пункты disabled с
  причиной). Плюс живой чекаут: переключились, бар показал новую ветку.
  Синтетические клики запрещены, как и в T263.
- `cargo test -p chronos --lib --bins` без регресса.

## Поправка архитектора 2026-08-13: подменю — WORKTREE, не ветки

Уточнение владельца: подменю должно давать выбор **рабочего дерева
(worktree)**, а не только ветки. Это не косметика формулировки, а другая
операция по природе:

- **Переключение worktree — смена каталога.** Активный проект указывает на
  другой путь, репозиторий не трогается вообще. Безопасно, обратимо,
  мгновенно.
- **`git checkout` — мутация рабочего дерева.** При грязном состоянии
  способен оставить пользователя с наполовину переехавшими файлами.

Поэтому часть D переопределяется:

1. **Основной пункт — «Switch worktree →»**, список из
   `git -C <path> worktree list --porcelain`: путь + ветка каждого дерева,
   текущее помечено `.checked()`. Выбор = смена пути активного проекта в
   `projects.toml`. Никаких git-мутаций.
2. Смена worktree меняет корень для Build/терминала так же, как смена
   проекта, и подчиняется тому же правилу из части A: открытая сессия
   агента не переносится, новый корень действует со следующей сессии.
3. **Checkout ветки — отдельный, вторичный пункт** и только с
   предохранителями из первой редакции (грязное дерево → `.disabled()` с
   причиной, ошибка `git` видимым тостом, подпроцесс не на рендер-потоке).
   Если по объёму придётся резать — режется checkout, worktree остаётся.
4. Проект без дополнительных worktree (единственное дерево) → пункт
   скрывается целиком или показывает одну текущую запись; пустого подменю
   быть не должно (канон T252: отсутствие информативно → строка, не
   информативно → скрыть).

## Побочная роль этого тикета: первое живое подменю в шелле

На 2026-08-13 в дереве НЕТ ни одного меню с детьми: ни трей, ни док не
содержат вложенных пунктов. Поэтому submenu widest-reserve из T263
(`estimate_menu_width` + `submenu_chain_reserve`, `tray_menu/mod.rs:216-234`)
доказан только юнит-тестами — живьём его проверить было не на чем.

**Это подменю станет первой живой проверкой T263-механики.** При приёмке
T274 обязательно снять/посмотреть: подменю встаёт сбоку от карточки,
не обрезано host-окном, у правого края экрана срабатывает flip. Если
клиппинг проявится — дефект относится к T263-коду, а не к этому тикету, и
чинится там же.
