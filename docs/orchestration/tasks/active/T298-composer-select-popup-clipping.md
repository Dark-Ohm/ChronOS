# T298 — попап model/mode `Select` обрезан

**Родитель:** T287-A (принят `25ac46a`, живой смок владельца 2026-08-16 —
«работает — да, выглядит плохо — да»: меню и содержимое обрезаны).
**Приоритет:** P2 — функция живая (клик/выбор/фильтр работают), это
визуальный дефект, не блокер.
**Роль:** FRONTEND. `crates/app/src/side_panel_left/composer.rs`
(`model_picker`/`mode_picker`, кит `Select`), возможно
`workspace_view.rs`.

## Симптом

Живой смок 2026-08-16 (владелец, уточнено вторым заходом): попап
пикеров model/mode рендерится, но и сам попап, и его содержимое (список
моделей/режимов) обрезаны — не влезают целиком. Функция работает
(фильтр, выбор, `set_model` подтверждён приёмкой), это чисто
размер/клиппинг.

**Позиционирование — отдельный, более точный симптом:** попап
появляется **по центру курсора**, а не заякорен от триггера вверх.
Композер внизу фиксированной 920px-панели — попап, открывающийся
центрированно на мыши, **уезжает вниз за нижнюю границу монитора**.
Правильное поведение: открываться **от мыши/триггера вверх** (места
снизу физически нет — композер у самого низа канваса).

## Рабочая гипотеза (не подтверждена — сверить в живом дебаге)

Триггер узкий (`model_picker` — `w(px(150.))`, `mode_picker` —
`w(px(90.))`, `composer.rs:444,468`) — если попап кита наследует ширину
триггера вместо ширины содержимого, длинные имена моделей/режимов режутся.
Отдельно: `workspace_view.rs:381` (`clip` в `render`) оборачивает видимую
часть панели в `.overflow_hidden()` на `visible_w` — если попап `Select`
не уходит на `anchored`/`deferred`-слой окна (рендерится в обычном потоке
внутри этого контейнера), обрежется этим родителем, а не собственной
логикой кита. Композер также в самом низу фиксированной 920px-панели
(канон T287/чекпоинт 2026-08-14) — если попап открывается вниз без
фолбэка на «открыть вверх», может упираться в нижнюw границу окна.

Это гипотезы, не диагноз — смотреть код кита
`../Source/gpui-component/crates/ui/src/select.rs` (`anchored`/`deferred`
использование, надо разбор — не гадать) и живой grim с подписанными
границами перед правкой.

## Сделать

1. Живой grim открытого попапа (window border виден) — установить, где
   именно обрезка: своей шириной, `overflow_hidden` родителя, или
   границей окна/монитора.
2. **Позиционирование (подтверждённый симптом, не гипотеза):** попап
   центрируется на курсоре вместо якоря от триггера. Найти в
   `select.rs`/`searchable_list.rs` (`anchored`/`deferred` вызов) точку
   якоря — скорее всего курсор передаётся как anchor point по умолчанию
   вместо bounds триггера. Переключить на якорь от `composer-model-picker-wrap`
   / `composer-mode-picker-wrap` div (их `id` уже есть,
   `composer.rs:442,466`), направление **вверх** (`Corner::BottomLeft`/
   аналог в ките, сверить реальное имя API — не гадать по памяти).
3. Если ширина попапа = ширина триггера — переопределить (кит обычно
   даёт способ задать min/max width попапа независимо от триггера,
   сверить API `select.rs`, не гадать).
4. Если обрезка от `workspace_view.rs` `overflow_hidden` — проверить,
   уходит ли кит-попап через `anchored`/`deferred` (должен рендериться
   вне этого контейнера, на слое окна). Если да и всё равно обрезан —
   смотреть `gpui-layer-shell`/`chronos-gpui-popup` скиллы, канон по
   фиксированным layer-shell окнам (попапы уже ловились на этом раньше:
   T243 wobble, T226 mx overflow).
5. Если после якоря-от-триггера-вверх всё ещё упирается в границу
   монитора — flip логика (открыть вниз только если снизу реально есть
   место), либо сузить список/раздвинуть композер.
