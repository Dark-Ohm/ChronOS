## Что делаем

Сегодня режим Developer/Gamer не меняет в шелле ничего, кроме подписи
виджета в баре — слайс 1 сознательно был только состоянием. Теперь режим
начинает менять **композицию**: набор инструментов правого рейла и состав
дока (§5 спеки, «Transition contract»).

## Что в дереве сейчас (проверено, опирайся на это)

`crates/app/src/side_panel_right/tabs.rs:56` — жёсткий массив на десять
элементов:

```rust
pub const ALL: [PanelTab; 10] = [ System, Files, Editor, Terminal,
    AcpSettings, McpSettings, LspSettings, ApiProviders, EditorSettings,
    HyprlandBinds ];
```

Потребители: `rail.rs:47` (`.children(PanelTab::ALL.into_iter()...)`) и
тесты в самом `tabs.rs:13-28`, один из которых прямо утверждает
`assert_eq!(PanelTab::ALL.len(), 10)`. Этот тест придётся переписать — это
ожидаемо и разрешено; **но `ALL` как «все существующие вкладки» должен
остаться**, потому что тесты покрытия иконок и подписей (`tabs.rs:21,28`)
обязаны продолжать проверять КАЖДУЮ вкладку, а не только вкладки текущего
режима. Появляется второе понятие — набор для режима.

`crates/app/src/dock/config.rs:14` — `DEFAULT_PINNED` из пяти приложений,
кэш в `OnceLock<Mutex<DockConfig>>`, файл `~/.config/chronos/dock.toml`.

## Контракт композиции

Порядок разрешения — от частного к общему, ровно такой:

1. **оверрайд сцены**, если сцена активна и поле задано. T164 принята
   2026-07-31, API в дереве и **заморожен** — вот фактические сигнатуры
   (`crates/app/src/scene.rs`), сверено по коду, не по отчёту:

```rust
pub fn current(cx: &App) -> Option<Scene>
pub fn rail_tabs_override(cx: &App) -> Option<Vec<String>>
pub fn dock_override(cx: &App) -> Option<Vec<String>>
pub fn active_tab_override(cx: &App) -> Option<String>
```

   Возвращают owned-значения (`Vec<String>`, не `&[String]`) — так легло на
   GPUI-глобал, это осознанно. Пустой оверрайд отдаётся как `None` уже внутри
   `scene.rs` — на твоей стороне «пустой список» от «поля нет» не отличается,
   и различать их не надо. На функциях висит `#[allow(dead_code)]` с пометкой
   «T165 consumer» — **сними его**, когда подключишь
2. **дефолт режима** — иначе
3. существующий дефолт — если режим ничего не переопределяет

Наборы режимов определи сам по §4.1/§4.2 спеки и обоснуй в отчёте одной
строкой на вкладку. Ориентир: Developer — System, Files, Editor, Terminal и
настроечные вкладки; Gamer — System остаётся, разработческие настроечные
вкладки уходят. **`System` присутствует в обоих режимах и остаётся первой** —
это `PanelTab::default()` (`tabs.rs:37`) и посадочная вкладка
(`view.rs:294`).

**Позиции общих инструментов сохраняются** (§5 прямым текстом: «change which
mode-specific rail tools are present while preserving the positions of
shared tools»). Практически: относительный порядок вкладок, присутствующих
в обоих режимах, между режимами не меняется. Это не пожелание — это пункт
приёмки, и он проверяется кадрами до/после.

## Красные линии

1. **Панели при смене режима не закрываются и не теряют состояние** (§5:
   «must not discard panel or editor state»). Если активная вкладка исчезла
   из набора нового режима — переключись на `System`, но **не закрывай
   панель**.
2. **`view.rs` не превращается в монолит побольше** (§11 «Do not do»).
   Твоя правка в нём — точечная: взять набор вкладок из нового источника
   вместо `PanelTab::ALL` и обработать случай «активная вкладка исчезла».
   Ветвление по режиму внутри рендера — признак того, что ты пошёл не туда.
3. **Хардкод палитры запрещён** — только токены темы (§11). Источники
   токенов: `crates/ui/src/theme/mod.rs` и `schemes.rs`.
4. **`let _ = fallible()` вне закона.** `?`, `.log_err()` или явный `match`.
5. **Ни одного нового вызова `workspace_mode::set`/`toggle`.** Ты читаешь
   режим (`workspace_mode::current`), а не меняешь его. Греп на приёмке.

## Тесты

- набор вкладок Developer и набор Gamer — оба непусты, оба содержат `System`
  первой
- относительный порядок общих вкладок одинаков в обоих наборах (это и есть
  «preserving the positions of shared tools» в машинной форме)
- оверрайд сцены перебивает дефолт режима; пустой оверрайд ≠ отсутствие
  оверрайда (пустой список — это осознанный выбор пользователя, решай и
  обоснуй в отчёте, что он значит)
- неизвестное имя вкладки в оверрайде сцены игнорируется с `warn`, остальные
  применяются
- существующие тесты `tabs.rs` на покрытие иконок и подписей продолжают
  обходить ВСЕ вкладки

**Живой прогон обязателен — это оконный код.** «Компилируется и тесты
зелёные» здесь не значит ничего:

1. `scripts/dev/chronos-stop`, затем старт с `RUST_LOG=info` и логом в файл
2. кадр правого рейла в Developer (`hyprctl layers` для геометрии, затем
   `grim -g "x,y WxH"`)
3. переключение в Gamer кликом по виджету бара **или** IPC
   `set-workspace-mode:gamer`
4. кадр правого рейла в Gamer — набор вкладок изменился, `System` на месте
   и первой, порядок общих вкладок тот же
5. кадр дока до и после
6. панель **осталась открытой** через переключение; если была открыта
   вкладка, исчезнувшая в новом режиме — панель открыта на `System`
7. лог без паник

**Координаты `ydotool` на этой машине — половина экранных** (`absolute -x N`
попадает в `2N`). Подтверждено трижды: T157, T158, T162. Клик по правому
кластеру бара — `-x 1127 -y 7`. Нужен `YDOTOOL_SOCKET=/run/user/1000/.ydotool_socket`
и запущенный `ydotoold`. Промахнёшься — решишь, что фича не работает.
