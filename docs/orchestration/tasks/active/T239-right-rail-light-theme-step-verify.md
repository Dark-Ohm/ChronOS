# T239 — Правый рейл: геометрия отдельно от контент-панели, проверить ступень в светлой теме

**Роль:** FRONTEND/QA — в основном живой замер, минимум кода.
**Источник:** `docs/orchestration/tasks/report/T223-design-audit-report.md`,
топ-10 п.7 + раздел "NOT VERIFIED" (снято из таблицы находок как
недостаточно надёжное).

**Приоритет:** P2 — verification задача, может не породить код-фикс.

## Контекст

Критик прямо сказал: "Точная визуальная ступень рейл/контент-панель в
светлой теме — пиксель-сэмплинг по приблизительным координатам
неоднозначен, координата рейла не подтверждена отдельно от
`side_panel_right` через `hyprctl layers`." Это не находка — это
непроверенная гипотеза, которую предыдущий T223-аудит (2026-08-04,
отклонённый) поднимал как P2 #10 ("рейл рисуется чёрным на светлом
фоне") — тоже не подтверждено вживую.

## Что нужно

1. Открыть правую панель на светлой теме, **рейл в состоянии rail-only**
   (контент закрыт) — снять геометрию рейла отдельно через
   `hyprctl layers -j` (не смешивать с открытой контент-панелью).
2. `grim` именно этой области, пиксель-сэмпл фона рейла vs фона
   контент-панели (когда она открыта следом).
3. Сравнить оба значения с `theme.bg.tertiary`/`theme.bg.elevated` из
   `schemes.rs` light-схемы — должна быть **видимая, но не резкая**
   ступень (rail-only обычно темнее/светлее контента на один уровень
   палитры).

## Возможные исходы

- Ступень в порядке (соответствует токенам) → закрыть, задокументировать
  в отчёте, ничего не чинить.
- Ступень отсутствует (рейл сливается с контентом) → найти, где рейл
  берёт цвет фона (`side_panel_right/rail.rs`), поправить на правильный
  токен.
- Рейл рисуется неожиданным цветом (как в старом P2 #10 T223-находке,
  "чёрный на светлом") → это баг токена, завести починку по факту
  находки, не по старому непроверенному описанию.

## Верификация

Живой grim + пиксель-сэмпл, факт — не на глаз. Если код меняется —
`cargo build --release -p chronos`.
