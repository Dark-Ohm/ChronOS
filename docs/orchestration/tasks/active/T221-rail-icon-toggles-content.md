# T221 — Клик по иконке рейла открывает и закрывает контент правой панели

**Статус:** active, не начата  
**Источник:** live dogfood 2026-08-03 — «нужно на правой, чтоб я нажимал на иконку
вкладки и она открывала/закрывала контент панели»  
**Приоритет:** P1 product  
**Порядок:** **после** коммита T216/T218 и **последовательно** с T219 — общий
`side_panel_right/{view,rail}.rs`.

## Как сейчас (и почему это стоило двух человеко-дней)

Панель раскрывается **в два приёма**: клик по иконке рейла только *выбирает*
вкладку, ширина остаётся рейловой; контент раскрывает кнопка `⊞`/`⊟` внизу рейла.
Это прямо записано в `docs/HANDOFF.md` как «механика, на которой потерялись двое,
включая меня» — без неё живые прогоны давали пустые кадры и превращались в фикцию.

В коде: `side_panel_right/view.rs:323 on_tab_select` — **повторный клик по активной
вкладке это `return`**, ранний выход. Кнопка дока дёргает `dock_content`
(`rail.rs:97`), а `content_open` считается как `dock_content || panel_width >
rail_only_width + 1` (`view.rs`).

## Решение

Клик по иконке рейла становится единственным нужным жестом:

| ситуация | поведение |
|---|---|
| клик по **другой** вкладке | переключить вкладку и **раскрыть** контент на её натуральной ширине |
| клик по **активной** вкладке, контент открыт | **свернуть** до рейла |
| клик по **активной** вкладке, контент свёрнут | раскрыть |

То есть ранний `return` для той же вкладки заменяется тумблером. Кнопка `⊞`/`⊟`
остаётся как есть: она про **док** (контент всегда виден), а не про разовое
раскрытие, и эти два понятия не сливать.

Требования:

1. **Ширина берётся по правилам T218.** Раскрытие сажает панель на
   `active_tab_width` — то есть на `preferred_content_width` для фиксированных
   вкладок и на запомненную для Editor/System settings. Не вводить свою ширину.
2. **Сворачивание не стирает память.** Свернул и раскрыл Editor — вернулась его
   ширина, а не дефолт.
3. **Док главнее.** Если `dock_content = true`, контент виден всегда; клик по
   активной вкладке в этом режиме не должен ронять панель в рейл, оставляя
   `dock_content` включённым — это была бы противоречивая пара состояний.
   Решение: при доке клик по активной вкладке — no-op (либо снимает док, но тогда
   явно и с логом; выбрать одно и закрепить тестом).
4. **HANDOFF переписать.** Абзац про «два приёма» после этой задачи становится
   неправдой. Оставить его — значит гарантированно послать следующего исполнителя
   по ложному следу; заменить на новую механику и пометить дату.

## Зоны файлов

- `crates/app/src/side_panel_right/view.rs` — `on_tab_select`
- `crates/app/src/side_panel_right/rail.rs` — только если нужен аффорданс/hover

Не трогать: `tabs.rs`, `tab/`, `side_panel_left/`.

## Приёмка

```bash
cargo test -p chronos --lib side_panel_right
cargo build --release -p chronos
```

Тесты (звать `on_tab_select`, а не воспроизводить логику в тесте):

- другая вкладка → активна и контент открыт на её натуральной ширине;
- та же вкладка при открытом контенте → рейл-онли;
- та же вкладка при свёрнутом → снова открыт;
- Editor: раскрыть → перетянуть до N → свернуть → раскрыть = N;
- поведение при `dock_content = true` закреплено выбранным вариантом.

**Live (обязателен):** кликать по иконкам, снимать `hyprctl layers | grep
side_panel_right` — ширина ходит между рейлом и натуральной; кадры `grim`, что
контент реально рисуется, а не просто окно шире.

**Коммит:** `panels : rail icon toggles content (T221)`.
