## Подготовка

```
cargo build --release -p chronos
```

Гонять только релизный бинарь, `RUST_LOG=info`, лог в файл. Дебажная
сборка для оконного кода доказательством не считается.

**Сохрани копии конфигов до начала и верни в конце:**
`~/.config/chronos/{workspace.toml,scenes.toml,dock.toml,bar.toml,monitor.toml}`.
Это машина архитектора.

**Механика, проверенная в этом слайсе** — пользуйся, не изобретай:

```python
import socket
def ipc(msg):
    s = socket.socket(socket.AF_UNIX)
    s.connect("/run/user/1000/chronos.sock")
    s.sendall(msg.encode()); s.close()

ipc("toggle-side-panel-right")        # открыть/закрыть панель
ipc("set-workspace-mode:developer")   # сменить режим, без рестарта
ipc("set-workspace-mode:gamer")
```

`toggle-side-panel-right` открывает панель в **rail-only** (`w=54`).
Развернуть контент можно двумя путями: клик по любой вкладке рейла или
захват ресайз-хэндла на левом краю панели.

**Геометрия рейла** (замерено 2026-07-31): рейл — крайние 54 px справа,
`x = 2506…2560`; иконки идут сверху вниз от `y ≈ 57` с шагом ≈ 40 px.
`ydotool` на этой машине: **absolute-координаты = экран / 2** (подтверждено
шесть раз: T157, T158, T162, T167, T168, T171). Сокет
`YDOTOOL_SOCKET=/run/user/1000/.ydotool_socket`. То есть клик по первой
иконке — `ydotool mousemove --absolute -x 1266 -y 28`.

Ширину слоя мерить так:

```bash
hyprctl layers -j | python3 -c "
import json,sys
for out,v in json.load(sys.stdin).items():
    for lvl,l2 in v['levels'].items():
        for l in l2:
            if l.get('namespace')=='side_panel_right': print(out, l['x'], l['w'], l['h'])"
```

## Пункты смока

### P1. Вкладка уходит из набора режима — панель НЕ закрывается

**Это главный пункт задачи и долг ещё со слайса 2** (в T167 он остался
непроверенным: на обоих кадрах активной была System, то есть сценарий не
разыгрывался).

Шаги: Developer → открыть панель → перейти на вкладку, которой **нет** в
Gamer (Editor, Terminal, Files, Preview, Inspector, Build, SourceControl) →
`set-workspace-mode:gamer`.

Ожидание: панель **осталась открытой**, активной стала **System**, шелл
жив. Отдельно посмотри, что стало с шириной: активной вкладкой становится
System (400), а до перехода была, скажем, Editor (560) — ширина обязана
поехать за вкладкой, а не залипнуть.

Кадры до и после, строка `hyprctl layers` до и после, строки лога.

### P2. Все четырнадцать пустых состояний

Пройди по всем вкладкам, у которых нет содержимого (то есть по всем, кроме
System), и убедись, что каждая рисует честное пустое состояние: иконка,
название, одна строка описания. Тексты **разные** у разных вкладок.

Достаточно одного кадра на 3–4 вкладки, если они помещаются в серию, но
**открой кадры глазами**. Мелкий текст — вырезать и увеличить:

```
magick кадр.png -crop 400x1410+2160+30 +repage -filter point -resize 200% out.png
```

Ни на одной не должно быть слов «coming soon», «в разработке», сроков.

### P3. Ленивость и кэш — по логу

Контракт T168: вьюха вкладки создаётся при **первой** активации и потом
живёт в кэше.

- Старт + открытие панели → в логе ровно одна строка
  `lazy-create tab view tab="System"`, других нет.
- Прошёл по пяти вкладкам → пять новых строк, по одной на вкладку.
- Вернулся на уже посещённую → **новой строки нет**.

Приложи грепы `grep -c "lazy-create" лог` на каждом шаге.

### P4. Память ресайза по вкладкам

Захвати ресайз-хэндл (левый край панели) на одной вкладке и растяни.
Перейди на другую — ширина стала её собственной. Вернись — **твоя
растянутая ширина восстановилась**, а не сбросилась в дефолт.

В логе это видно строками `tab select → apply per-tab width before=… after=…`.
Приложи их.

Отдельно: **повторный клик по уже активной вкладке не должен сбрасывать
ручной ресайз** (в T171 под это сделан отдельный guard).

### P5. Сцена с четырнадцатью вкладками

Слайс 2 дал оверрайд состава рейла через `~/.config/chronos/scenes.toml`
(ключ `rail_tabs`). Проверь, что он работает и на новом наборе:

- создай сцену с `rail_tabs` из нескольких id, включая **новые**
  (`preview`, `inspector`, `build`, `source_control`);
- добавь в список заведомо мусорный id — он должен быть **пропущен**, а не
  уронить панель;
- убедись, что рейл показывает именно оверрайд, а не дефолт режима.

Формат `scenes.toml` — в задании T164 (`done/T164-scene-state-model.md`) и в
тестах `crates/app/src/scene.rs`. **Каждый ключ на своей строке** — в T167
рецепт был написан невалидным TOML и чуть не привёл к ложному дефекту.

И главное, что уже ловилось: после прогона файл обязан остаться
**побайтово тем же** (`sha256sum` до и после). `restore_for_mode` read-only,
это принято в T164.

### P6. Док и его меню

T170 починила глобалы дока. Подтверди, что живо:

- правый клик по иконке в доке открывает меню («Unpin»), шелл не падает;
- в логе есть `warn` про нерезолвящиеся пины (`firefox`, `code`, `vivaldi`
  на этой машине их нет) — **ровно по одному на пин**, без флуда;
- состав дока меняется при смене режима.

### P7. Нагрузка при четырнадцати вкладках (§10)

Записано в долг ещё в T165: `resolve_for_mode` / `rail_tabs_override` /
`resolve_pinned` возвращают свежий `Vec` **на каждый рендер**. При десяти
вкладках это никого не волновало; теперь их четырнадцать.

Померь, а не рассуждай: `top -H -p $(pgrep -x chronos)` при спокойной
панели, при быстром переключении вкладок и при перетаскивании ресайз-хэндла
(самый горячий путь — рендер на каждый кадр движения мыши). Приложи цифры.

Если увидишь, что поток шелла уходит в полку, — это находка уровня
отдельной задачи, опиши и не чини.

### P8. Ноль паник

`grep -n "panicked at" лог` — **по всему файлу**, не по своему модулю.
В T170 отчёт заявил «0× panicked», грепнув по своей зоне, а в логе лежали
четыре паники из чужой задачи.

## Правила улик

- **Кадр снят — значит открыт.** Не «проанализирован по пикселям», не
  «известно, что там». В этом слайсе на этом уже попались: во втором заходе
  T168 «панелью ChronOS» оказалось окно файлового менеджера на втором
  мониторе.
- Осторожность про мелкий текст — это требование **увеличить и посмотреть**,
  а не повод не делать вывод. В T167 исполнитель так занизил собственный
  PASS: тосты на его же кадрах читались прекрасно.
- Не чини найденное. Воспроизведи и опиши: шаги, ожидание, факт, кадр,
  строка лога.
- Продуктовый код не трогать. Понадобился временный зонд — откатывай
  полностью и покажи `git status` в отчёте.
- Пультовый вывод может быть занят фуллскрин-игрой. Занят — **остановись и
  напиши «не проверено»** с причиной, в игру не лезь. Это засчитывается.
- В конце вернуть конфиги и сказать об этом в отчёте.
