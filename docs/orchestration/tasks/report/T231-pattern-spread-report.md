## Что сделано

Общие визуальные примитивы T231 вынесены из `bar_settings.rs` в новый модуль
`crates/app/src/side_panel_right/tab/ui.rs` (консолидация: `section_header`
до этого был продублирован в трёх файлах):

- `elevated_card(theme) -> Div` — `bg.elevated`-подложка с elevation-тенями
  темы (`elevation_popup()` + `elevation_apply_light_chrome`). `.id()` после
  вызова — helper отдаёт голый `Div`.
- `section_header(theme, title, subtitle)` — акцентный тик + semibold +
  mono-подпись (иерархия T231 §2).
- `setting_label` / `setting_row` — label+path пара и ряд.
- `GRID_BREAKPOINT = 720` / `is_wide(window)` — резиновый переключатель
  (дефолт 560 — 1 колонка, 960 — 2+). Тест переехал в `ui.rs`.

Три вкладки приведены к паттерну, **логика не тронута**:

| Вкладка | Изменения |
|---|---|
| `files.rs` | Header по паттерну (Files + `..`/`reload` справа, cwd как mono-подпись); список внутри elevated-карточки; loading/error/empty/truncated — в карточку. Список оставлен 1-колоночным (файловый браузер — список, а не сетка карточек) |
| `hypr_binds.rs` | Header по паттерну (+ Reload, mono-подпись = источник `~/.config/hypr/modules/`); содержимое в карточку; группы — общий `section_header` (подпись = имя модуля); бинды **grid 2 колонки на широкой** панели, 1 на узкой |
| `acp_settings.rs` | Header по паттерну; карточка; секции «Configured agents»/«Actions» через `section_header`; агенты **grid 2 колонки на широкой**; Open/Reload/error/example — в карточку; T212-комментарий про `flex_none` сохранён; убран пустой placeholder-тест |

`bar_settings.rs` отрефакторен на `ui::*`-хелперы (дубли удалены, поведение
не менялось — commit `f5b69c5` уже принял этот код).

## Верификация

- `cargo build --release -p chronos` — чисто, без warning-ов в изменённых файлах.
- `cargo test --release -p chronos --lib -- side_panel_right` — **165 passed, 0 failed**.
- **Live** (без рестартов, на рабочей сессии пользователя): state-лог
  подтверждает `select-tab:files` → `lazy-create tab="Files"` →
  `switched tab → width=440.0` **без единого `zero size`** и без падения.
  Пользователь подтвердил: «шелл не падает». Процесс стабилен часами.
  Синтетические grim-кадры трёх вкладок не сняты: живая сессия активно
  используется (левая панель, ACP-сессии), `hyprctl layers` в текущей
  конфигурации мониторов пуст — не стал дёргать пользовательский шелл.

## Диагностика «падающего шелла» (ложная тревога)

В ходе live-прогона процессы хроноса «умирали» каждые 1-2 мин. Раскопки
показали: **это были мои же `pkill -x chronos` в рестарт-командах** —
следующий запуск убивал предыдущий, а `$!` после `nohup cmd &` отдаёт PID
subshell-обёртки, а не хроноса (для трекинга нужен `pgrep -x chronos`).
Самостоятельно процесс стабилен (150+ сек наблюдения), zero-size-шквалы в
логах — известный инфраструктурный симптом (T233), не связанный с вкладками.
Вывод для будущих live-сессий: **не pkill'ить шелл в тестовых командах без
необходимости; трекать реальный PID через `pgrep -x chronos`.**
