## 1. Откуда берётся корень проекта

Не из `current_dir()`. В дереве уже есть понятие активного проекта:

`crates/app/src/project_switcher/mod.rs`
- `ProjectsConfig::load()` — читает `~/.config/chronos/projects.toml`
- `ProjectEntry { name: String, path: String }` (`:57`)
- `ProjectsConfig::active_entry() -> Option<&ProjectEntry>` (`:98`)

Задачи запускаются в `active_entry().path`. **Активного проекта нет —
вкладка честно об этом говорит** и не запускает ничего («no active project»
плюс что сделать, чтобы появился). Никаких молчаливых фолбэков на
`current_dir()`.

К сведению, но **чинить не в этой задаче**: `FilesTab::new` (`files.rs:40`)
берёт как раз `current_dir()`. Расхождение известно, отдельная задача.

## 2. Движок — `crates/services/src/tasks/`

Без единого GPUI-типа, как `services/src/terminal/` в T177 (проверяется
грепом: `grep -rn gpui crates/services/src/tasks/` обязан быть пуст).

Что нужно:

- **Список задач.** Два источника, в этом порядке:
  1. `~/.config/chronos/tasks.toml` — если есть, он главный;
  2. автодетект по корню проекта: увидел `Cargo.toml` → `cargo build`,
     `cargo test`, `cargo clippy`, `cargo run`. Ни `Cargo.toml`, ни
     конфига — пустой список и честное состояние.

  Формат `tasks.toml` придумываешь ты, но по образцу `projects.toml`
  (`serde` + `toml`, мягкий разбор: битый файл → warn в лог и пустой
  список, **не паника**). Формат опиши в отчёте — я занесу в доки.

- **Запуск.** `std::process::Command` с `stdout`/`stderr` в пайпы, чтение
  построчно, обе ленты в один поток вывода с пометкой источника. **Не PTY** —
  здесь не нужен интерактив, и движок T177 сюда тащить не надо.

- **Отмена.** Задача бежит — её можно остановить. Убивать процесс, а не
  «переставать читать».

- **Состояние.** `idle` / `running` / `ok` / `failed` с кодом возврата и
  длительностью. §41 спеки: **никогда не выдумывать статус сборки.** Не
  запускали — состояние неизвестно, а не «ok».

- **Буфер вывода.** Кольцевой, с потолком (тысячи строк, не безграничный —
  `cargo build` на холодную выдаёт десятки тысяч). Потолок в константу,
  обрезание — видимое пользователю, как `truncated` в T176.

Тики и UI — на GPUI-экзекьюторе, `tokio` тут не нужен
(`docs/DECISIONS.log`, «Runtime split»).

## 3. Вьюха — `tab/build.rs`

По образцу `tab/system.rs` и `tab/files.rs`: своя сущность, свой `Render`,
создаётся лениво через `TabContent::create`, живёт в кэше.

Сверху — список задач с кнопкой запуска и текущим состоянием. Снизу — вывод
с прокруткой и автоскроллом вниз, пока пользователь не проскроллил вверх
сам. Строки `stderr` отличимы от `stdout`.

**Ленивость важна:** до открытия вкладки ничего не запускается и конфиг не
читается. Проверяется в живом прогоне.

## 4. Ширина

Сейчас `Build` в группе пустых вкладок — **320 px** (`tabs.rs`,
`preferred_content_width`). Для вывода компилятора этого мало.

Замерь и обоснуй **числом**: сколько нужно, чтобы типичная строка
`cargo build` (путь + `-->` + позиция) не ломалась. Механика ширины уже
готова (T171), от тебя — только значение в `match`. Ориентир — как у
Terminal (560), но это ориентир, а не ответ: **спека и замер выше моего
ориентира**, расхождение с обоснованием — плюс тебе, а не минус.

## 5. Честные состояния (§13, §41)

- нет активного проекта — сказать это и что сделать;
- задач не нашлось — сказать, где искались (`tasks.toml`, `Cargo.toml`);
- задача упала — код возврата и вывод, а не «failed» без деталей;
- бинаря нет в `PATH` (`cargo` не установлен) — точная ошибка;
- никаких «coming soon», никаких выдуманных зелёных галок.

## Тесты

- разбор `tasks.toml`: валидный, битый, отсутствующий — чистыми функциями;
- автодетект по корню: с `Cargo.toml` и без;
- кольцевой буфер: потолок соблюдается, обрезание отмечается;
- разбор строк вывода / разделение `stdout`/`stderr`;
- вьюха: `#[gpui::test]` с `TestAppContext` — ленивое создание и кэш, как
  для System/Files/Terminal в `tab/mod.rs`;
- запуск процесса в тестах — на заведомо безопасном (`true`, `echo`), не на
  `cargo build`.

Тест, воспроизводящий логику продукта внутри себя, тестом не считается —
этим отличились T164 и T168.

## Верификация

```
cargo test -p chronos
cargo test -p chronos-services tasks
cargo clippy -p chronos --all-targets
cargo build --release -p chronos
```

**Внимание, ловушка T177:** `cargo test -p chronos` **не гоняет** тесты
`chronos-services` — это отдельная команда. Приведи в отчёт обе.

Самодостаточность коммита — обязательна:

```bash
git stash push --include-untracked
cargo check -p chronos
git stash pop
```

Вывод — в отчёт.

**Живой прогон обязателен.** Релиз, `RUST_LOG=info`, лог в файл.

1. Старт — вкладка не открыта, в логе ни чтения конфига, ни запуска.
2. `set-workspace-mode:developer` (в Gamer-рейле Build нет), открыть панель
   (`toggle-side-panel-right`), перейти на Build — список задач виден.
3. Запустить задачу — вывод течёт живьём, статус меняется, по завершении
   код возврата и длительность. Кадр.
4. Запустить длинную (`cargo build`) и **отменить** — процесс умер,
   проверить `pgrep`. Кадр.
5. Провальная задача (`cargo test` на заведомо падающем или `false`) —
   состояние `failed` с кодом. Кадр.
6. Нет активного проекта (временно убрать `active` из `projects.toml`,
   **потом вернуть**) — честное состояние. Кадр.
7. Лог целиком: `grep -n "panicked at" лог`.

IPC-сокет `$XDG_RUNTIME_DIR/chronos.sock`, рестарты не нужны.

Рейл — крайние 54 px справа (`x = 2506…2560`), иконки от `y ≈ 57` шагом
≈ 40. `ydotool` берёт **половинные** координаты (подтверждено восемь раз),
сокет `YDOTOOL_SOCKET=/run/user/1000/.ydotool_socket`.

**Кадры открывать глазами и подписывать тем, что на них.** В T177 два кадра
были подписаны не своим содержимым — при приёмке это вскрывается сразу.
Мелкое вырезать и увеличивать:

```
magick кадр.png -crop 560x1410+2000+30 +repage -filter point -resize 200% out.png
```

**Если инструмент не смог что-то проверить — пиши «не смог проверить
инструментом», а не «функция не работает».** В T177 исполнитель объявил
сломанной работающую клавиатуру, потому что `ydotool` не доставил ввод.
Занижать свою работу так же вредно, как приукрашивать.

Пультовый вывод бывает занят фуллскрин-игрой — занят, пиши «не проверено» с
причиной, в игру не лезь. Это засчитывается.
