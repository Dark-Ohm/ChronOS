# T240 — Явный визуальный сигнал "offline/local by design" (тест доверия)

**Роль:** BRAINSTORM сначала, потом FRONTEND — это продуктовое решение,
не механическая правка, начинать с обсуждения с пользователем, не с кода.
**Источник:** `docs/orchestration/tasks/report/T223-design-audit-report.md`,
раздел "Тест доверия", топ-10 п.10.
**Приоритет:** P2/продуктовый — не баг, отсутствующая фича-сигнал.

## Находка (дословно)

"Тест доверия. Ничего тревожного не видно (нет 'войди в аккаунт'/
облачных элементов на видимых кадрах), но и подтверждения 'мы оффлайн
by design' тоже нет — нигде не читается явный визуальный сигнал вроде
'no network' бейджа. ACP settings показывает локальный процесс-спавн
(`hermes acp --accept-hooks`), что косвенно в пользу локальности, но
это не то же самое, что явное визуальное заявление доверия. Нейтрально:
не проваливает тест, но и не выигрывает его явно."

**Канон:** `docs/PRODUCT.md` §1 "Тест доверия" — "у проекта нет сети по
дизайну — это преимущество, и оно должно читаться".

## Что нужно (обсудить перед реализацией)

Не очевидно, ГДЕ и КАК показывать этот сигнал без превращения в
навязчивый бейдж/иконку, которая сама станет визуальным шумом
(потенциально противоречит находке T234 про и без того плотный бар).
Варианты для обсуждения с пользователем, не решать самостоятельно:

- Строка в System settings ("About"/"Build info" секция уже существует,
  `bar_settings.rs:279-283` — можно дополнить явной строкой про
  отсутствие сети/телеметрии).
- Tooltip или подпись на ACP settings рядом с локальным процессом.
- Что-то в первом запуске/onboarding (если такой существует).

**Не заводить как P0/P1 механическую правку** — это продуктовое решение
about тона и места, использовать `brainstorming`-скилл перед тем как
писать код.

## Решение (брейншторм, 2026-08-05 — предложение на утверждение, код не писан)

**Принцип:** сигнал читается, но не шумит. Бар не трогаем (плотность T234),
onboarding нет — отпадает. Значит — два точечных текстовых места, оба muted
mono-подпись (язык уже есть в `section_header`/`setting_label` из T231), без
бейджей и иконок:

1. **ACP settings** — под шапкой, рядом с локальным процессом: подпись
   `local only · no network · no telemetry` (или RU «локально · без сети ·
   без телеметрии»). Это поверхность, где пользователь видит агента —
   главный объект доверия; там уже косвенно читается локальный спавн
   (`hermes acp --accept-hooks`) — делаем явным.
2. **About / Build info** (`bar_settings.rs`, секция уже есть) — одна строка
   в mono: `offline by design — no network · no telemetry`. Статично, дёшево,
   вторит уже существующей секции.

Отклонено: бейдж/иконка в баре (противоречит T234), onboarding (не
существует), tooltip-only (нечитаемо без ховера — а тест доверия это
статичный кадр).
