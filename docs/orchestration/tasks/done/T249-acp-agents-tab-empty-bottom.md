# T249 — пустой низ ACP agents-вкладки (контент кончается на ~35% высоты)

**Приоритет:** P1.
**Роль:** FRONTEND (Rust, GPUI) — дизайн-решение + код.
**Источник:** `docs/orchestration/tasks/report-log/T223-design-audit-report-v4-reshoot.md`
находка #3 (табл. §3), топ-10 п.4.

## Контекст

`crates/app/src/side_panel_right/tab/acp_settings.rs` — контент
(карточка «Configured agents» + «Actions» + example-entry блок, см.
хвост файла) занимает верхние ~35% высоты панели на кадре
`11-tab-acpsettings-dark.png` (панель 1164px высотой, контент кончается
около 400px). Ниже — голая пустота до низа. Структура рендера: `header`
+ scroll-контейнер (`#acp-settings-scroll`, `flex_1().overflow_y_scroll()`)
с одной `card` внутри — контейнер растягивается на всю высоту, но карточка
внутри не растягивается вместе с ним, оставляя визуальный "воздух", не
воспринимаемый как дизайн-решение (в отличие от намеренного вертикального
ритма на Files/Editor settings, которые аудит отмечает как "плотные,
честные, к месту").

## Что нужно (выбрать один путь, решение за исполнителем/архитектором
при приёмке — не оба сразу)

**Вариант А — контент.** Добавить реально полезный блок ниже
"Configured agents": последние ACP-действия/лог/статус подключения —
если для этого уже есть данные в `AppState`/сервисе ACP (проверить,
есть ли уже канал состояния соединения агента, не выдумывать backend с
нуля в рамках этого тикета — если данных нет, это вариант Б).

**Вариант Б — layout.** `justify_content: flex-start` на скролл-
контейнере (уже, вероятно, поведение по умолчанию — если контент и так
прижат к верху, проблема не в justify, а в том, что карточка не растёт)
+ компактизировать карточку (убрать лишние отступы/padding) так, чтобы
пустота внизу читалась меньше. Честно: аудит сам называет это
полумерой, не настоящим фиксом — приемлемо только если вариант А
нереалистичен в разумный объём работы.

## Резолюция (2026-08-05) — закрыт, вариант Б (layout)

Вариант А отклонён: данных в AppState/сервисе ACP нет (AgentStatus —
локальный стейт левой панели, не сервисный канал), а тикет запрещает
выдумывать backend. Выбран Б: elevated-карточка растягивается до низа
скролл-вьюпорта.

Находка форка: `min_h_full`/flex-grow внутри скролла не работают (GPUI
меряет контент overflow на unbounded-высоте) — применён явный пол
`min_h(px(window.bounds().height − HEADER_H_PX − SCROLL_PADDING_TOTAL))`.

Верификация (обе темы, панель 320px): карточка до y=1428 (дно ~1439),
до фикса ~400. 167/167 тестов, сборка чистая.
