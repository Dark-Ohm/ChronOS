## Что не так сегодня — измерено, не предположено

`side_panel_right/mod.rs:37-43`:

```rust
pub(crate) const RAIL_WIDTH: f32 = 44.;
pub(crate) const HANDLE_WIDTH: f32 = 10.;
pub(crate) const RAIL_ONLY_WIDTH: f32 = RAIL_WIDTH + HANDLE_WIDTH; // 54
/// Default full-content width when docked or user-resized.
pub(crate) const DEFAULT_CONTENT_WIDTH: f32 = 560.;
pub(crate) const MAX_WIDTH: f32 = 960.;
```

**Одна константа на все вкладки.** Живой замер архитектора 2026-07-31
(улики `/tmp/t168-live/`, кадры смотрел глазами):

```
hyprctl layers → side_panel_right x=2003 y=30 w=557 h=1410
```

а карточки System внутри занимают около **390 px**. Слева остаётся ~110 px
сквозной пустоты сверх `HANDLE_WIDTH = 10` — панель резервирует у
компоновщика экран, которым не пользуется. На 2560 это пятая часть
пультового вывода, отъедаемая зря.

Причина названа архитектором прямо: **560 задан под самую широкую вкладку**
(редактор/блокнот), а платят за это все остальные. Растягивание нужно
Editor'у, а не System.

## Решение

**Ширина — свойство вкладки, а не панели.**

Контракт вкладки (`tab/mod.rs`, сделан в T168) получает предпочитаемую
ширину. Форму выбираешь ты, но свойства обязательны:

- у каждой вкладки своя предпочитаемая ширина контента;
- при переключении вкладки панель просит у компоновщика ровно столько,
  сколько нужно активной;
- ширина остаётся в пределах `RAIL_ONLY_WIDTH … MAX_WIDTH`;
- `DEFAULT_CONTENT_WIDTH` остаётся **фолбэком** для вкладки, которая ничего
  не объявила, а не общим значением для всех.

Ориентировочные значения (это **ориентир**, не требование — меряй по
кадру и поправь, расхождение с обоснованием засчитывается в плюс):

| Вкладка | Ширина | Почему |
|---|---|---|
| System | ~400 | измерено: карточки занимают ~390 |
| Editor | 560+ | ради неё константа и была задрана |
| Terminal | 560+ | 80 колонок моноширинного не влезут в 400 |
| Files, SourceControl | ~440 | дерево и список путей |
| Пустые состояния | ~320 | иконка, название, строка описания |

### Пользовательский ресайз

Сегодня `resize()` (`mod.rs:98`) пишет одно глобальное `width`. С шириной по
вкладке возникает вопрос, на который **отвечаю я, а не ты**:

**Ресайз запоминается на вкладку.** Подстроил ширину под Editor — она
запомнилась для Editor; вернулся на System — System своей ширины не
потеряла. Это единственное поведение, которое не выглядит поломкой:
иначе пользователь тянет край один раз и ломает раскладку всем
четырнадцати вкладкам.

**Персист на диск в этой задаче НЕ делаем.** Хранение — в памяти, на
сессию. Место для персиста уже спроектировано (`scenes.toml`, слайс 2), но
писать туда должен `SceneManager`, которого ещё нет. Заведи это отдельным
пунктом «техдолг» в отчёте, не изобретай второй формат конфига.

## Ловушки

1. **`ensure_content_width()`** (`mod.rs:102-108`) сегодня расширяет до
   `DEFAULT_CONTENT_WIDTH` безусловно. Он зовётся из dock-переключения
   (`mod.rs:308`) и из `view.rs`. После правки он обязан расширять до
   ширины **активной вкладки**.
2. **Ресайз окна стоит дорого.** `window.resize()` дёргает компоновщика;
   переключение вкладок не должно ресайзить окно, если ширина не изменилась.
   В коде уже есть `last_resized_width` и `last_exclusive_zone` ровно для
   этого — используй их, не заводи третий счётчик.
3. **Не ломай rail-only.** Когда `dock_content == false`, панель остаётся
   `RAIL_ONLY_WIDTH` независимо от активной вкладки. Ширина вкладки
   применяется только когда контент виден.
4. **Тест `resize_clamps`** (`mod.rs:350`) и `ensure_content_width_from_rail_only`
   (`mod.rs:362`) существуют. Меняешь поведение — меняй и тесты **осознанно**,
   с объяснением в отчёте. Ослабить тест, чтобы он прошёл, — не починка.

## Тесты

- у каждой вкладки ширина в диапазоне `RAIL_ONLY_WIDTH … MAX_WIDTH`
  (обход по всему набору — защита от опечатки в одной строке);
- переключение вкладок меняет запрашиваемую ширину на объявленную;
- ресайз, потом уход на другую вкладку и возврат — ширина сохранилась
  **для той вкладки**, а у соседней осталась своя;
- `dock_content == false` → ширина `RAIL_ONLY_WIDTH` при любой активной
  вкладке;
- повторное применение той же вкладки не приводит к новому `resize`
  (проверяемо через `last_resized_width`).

Тесты — настоящие, на реальном состоянии. `#[gpui::test]` с
`TestAppContext` в форке **есть** (`Source/gpui/src/test.rs`, используется в
самом gpui) — этим уже ошиблись в T168, не повторяй. Тест, воспроизводящий
логику продукта внутри себя, тестом не считается (этим ошиблись в T164).

## Верификация

```
cargo test -p chronos
cargo clippy -p chronos --all-targets
cargo build --release -p chronos
```

**Живой прогон обязателен.** Релиз, `RUST_LOG=info`, лог в файл.
Панель и режим — по IPC, без рестартов:

```python
import socket
s = socket.socket(socket.AF_UNIX); s.connect("/run/user/1000/chronos.sock")
s.sendall(b"toggle-side-panel-right")
s.close()
```

Что снять и **чем доказать**:

1. `hyprctl layers -j` на вкладке System — ширина слоя ощутимо меньше 557 и
   соответствует объявленной. Приложи строку целиком.
2. Тот же вывод на широкой вкладке (Editor или Terminal) — ширина выросла.
3. Кадры обеих: контент занимает панель **без сквозной полосы слева**. Это
   главный визуальный критерий задачи.
4. Ресайз перетаскиванием на одной вкладке → уход → возврат: ширина та же.
5. Лог целиком без паник: `grep -n "panicked at" лог` — **по всему файлу**,
   не по своему модулю.

Переключать вкладки — кликом по иконке рейла. `ydotool` на этой машине:
**absolute-координаты = экран / 2** (подтверждено пять раз: T157, T158,
T162, T167, T168). Сокет `YDOTOOL_SOCKET=/run/user/1000/.ydotool_socket`.
Рейл — крайняя правая колонка панели, иконки идут сверху вниз с шагом ~40 px
от `y ≈ 57`.

**Кадры открывать глазами**, мелкое — вырезать и увеличить:

```
magick кадр.png -crop 60x900+2500+30 +repage -filter point -resize 300% rail.png
```

Не «визуально стало уже» — приложи два числа из `hyprctl layers` и два
кадра. Если пультовый вывод занят фуллскрин-приложением, живой прогон
невозможен: **остановись и напиши «не проверено»** с причиной. Это
засчитывается. Выдумывать вместо этого нельзя.
