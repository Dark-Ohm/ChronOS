# T260 — редизайн Context Menu по новому эталону

**Приоритет:** P2 — визуальный редизайн, независимая зона.
**Роль:** FRONTEND.
**Эталон:** `docs/design/Chronos-Context-Menu.dc (1).html` — это КАНОН,
не путать с соседним `Chronos-Context-Menu.dc.html` (без `(1)`) — тот
старее на 5 минут и без доработок ниже, игнорировать/можно удалить после
приёмки.

## Контекст

Эталон рисует единый паттерн контекст-меню ChronOS: заголовок с иконкой
(`head`/`headIcon`), пункты с иконкой/лейблом/шорткатом, чекбоксы (`check`),
disabled-состояние, разделители, подменю (`sub`), скролл при переполнении.
Примеры сценариев в эталоне: файл (`quarterly-report.pdf`), tray-виджет
(network), окно приложения (music player), десктоп.

Живой код реализует этот паттерн в двух местах, оба входят в зону:

1. **`crates/app/src/tray_menu/view.rs`** — рендерит дерево `MenuNode`:
   лист/сепаратор/toggle(✓/○)/подменю инлайном с отступом. Structurally
   ближе к эталону (уже умеет submenu, checkmarks, disabled) — сюда
   переносится основной визуальный язык: отступы (`ROW_PAD_Y`/`ROW_PAD_X`
   сейчас 6/12, сверить с эталоном `.ci` padding), левый акцент-бар на
   hover/nav (`.ci::before` в эталоне — 2px полоска, `border-radius 0 2px
   2px 0`, `background: var(--accent)`, opacity/scaleY переход), sticky
   заголовок с иконкой при наличии `head`/`headIcon` (сейчас заголовок,
   похоже, не рендерится вовсе — сверить), моно-шрифт для шорткатов
   (`ci-short`, `JetBrains Mono`, `letter-spacing .04em`), max-height +
   скролл при переполнении (эталон: `calc(100vh - 16px)`, кастомный
   тонкий скроллбар 6px).
2. **`crates/app/src/dock/context_menu.rs`** — сейчас тривиальный попап
   с одним пунктом «Unpin» (`MENU_WIDTH=140`, `MENU_HEIGHT=40`). Контент
   не меняется (это не задача на фичи), но визуальная оболочка (радиус
   угла, тень/blur, паддинги строки, hover-акцент) должна получить ту же
   отделку, что и tray_menu — это тот же паттерн попапа, должен выглядеть
   как один компонент, а не два разных.

## Что нужно

1. Открыть эталон в браузере (или прочитать HTML+CSS), выписать точные
   значения: цвета через переменные `--surface`/`--border`/`--accent`/
   `--faint` (сверить с текущей `Theme` в `chronos_ui` — какие токены
   существуют, какие нужно завести), радиусы, паддинги, тени,
   тайминги transition (`.12s ease`).
2. Применить к `tray_menu/view.rs`: акцент-бар на nav/hover, sticky-header
   с иконкой если `head` задан, моно-шрифт шорткатов, max-height+scroll
   guard (сейчас окно, вероятно, без верхнего предела — если список
   длинный, уходит за экран; см. `WindowOptions`/`window.resize` в этом
   файле или в `mod.rs`).
3. Применить к `dock/context_menu.rs` ту же оболочку (радиус/тень/паддинг/
   hover-акцент), без изменения контента (только «Unpin»).
4. Оба места используют `chronos_ui::Theme` — если эталон использует
   цвет, которого нет в текущей палитре, ЗАВЕСТИ токен в теме (не хардкод
   hex прямо в файле попапа), både dark и light.

## Зона файлов

`crates/app/src/tray_menu/**`, `crates/app/src/dock/context_menu.rs`,
при необходимости нового токена — `crates/ui/src` (theme). Не трогать
`crates/app/src/launcher/**`, `crates/app/src/osd/**` — это T261/T262,
параллельные задачи, файлы не пересекаются.

## Верификация

- Живой прогон: открыть tray-меню (правый клик по иконке в трее) и
  dock-контекст-меню (правый клик по закреплённой иконке дока), оба
  сценария — короткое и длинное меню (submenu раскрыт), обе темы.
- `grim -g` по геометрии из `hyprctl layers` (не полноэкранный кроп) —
  4 кадра минимум (tray short, tray+submenu, dock, любая тема на выбор
  для dock раз контента там мало).
- Сверить визуально с эталоном (открыть `.dc.html` в браузере рядом).

## Коммит

`tray_menu : редизайн по Chronos-Context-Menu эталону` /
`dock/context_menu : та же визуальная оболочка`. Без AI-трейлеров.
