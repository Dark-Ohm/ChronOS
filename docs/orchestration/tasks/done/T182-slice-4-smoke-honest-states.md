## Правило номер один в этой задаче

**Перед тем как класть скриншот в отчёт — открой файл и посмотри, что на
нём.** Не полагайся на код возврата `grim`, не полагайся на собственный лог
своего инструмента. Открытый файл должен показывать ChronOS: панель,
рейл, вкладку. Если на нём что-то другое (твой терминал, пустой рабочий
стол, чужое окно) — это не доказательство, начни заново. Это ровно то, на
чём спалились оба предыдущих захода.

Плюс: если делаешь несколько кадров подряд для разных состояний —
**сравни их `md5sum` между собой** перед тем как писать отчёт. Одинаковые
суммы для «разных» состояний = ты не сделал того, что думаешь, что сделал.

## Механика панели (обязательно, без этого кадры будут пустыми)

Панель раскрывается в **два приёма**. Клик по иконке в рейле только
*выбирает* вкладку — ширина остаётся 54 px. Контент раскрывает отдельная
кнопка `⊞`/`⊟` **в самом низу рейла**. Признак в логе, что раскрытия не
произошло: `apply per-tab width … content_open=false`.

Координаты на пульте (DP-1, 2560×1440), `ydotool` берёт **половинные**
(экран/2 на этой машине, подтверждено многократно), сокет
`YDOTOOL_SOCKET=/run/user/1000/.ydotool_socket`:

| элемент | реальные | ydotool (половина) |
|---|---|---|
| рейл, колонка иконок | `x ≈ 2537` | `x = 1268` |
| первая иконка (System) | `y ≈ 55` | `y = 27` |
| шаг между иконками | `40` | `20` |
| Files (2-я) | `y ≈ 95` | `y = 47` |
| Build (3-я) | `y ≈ 135` | `y = 67` |
| Terminal (4-я) | `y ≈ 175` | `y = 87` |
| Preview (5-я) | `y ≈ 215` | `y = 107` |
| кнопка раскрытия контента | `x ≈ 2539, y ≈ 1414` | `1269 707` |

Координаты строк **внутри** Files (README.md, бинарь, .html) — плавают при
навигации, снятые заранее не годятся. Сними кадр, открой его, прочитай
координаты нужной строки с него, потом кликай.

IPC без рестартов, сокет `/run/user/1000/chronos.sock`, `socat` в системе
нет — шли через python:
```python
import socket, sys
s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
s.connect("/run/user/1000/chronos.sock")
s.sendall(sys.argv[1].encode()); s.shutdown(socket.SHUT_WR); s.close()
```
Команды: `set-workspace-mode:developer`, `set-workspace-mode:gamer`,
`toggle-workspace-mode`, `toggle-side-panel-right`.

Запуск шелла со своим логом (не трогай `~/.local/state/chronos/chronos.log`
— общий, засоришь параллельным контекстом):
```bash
pkill -9 -x chronos; rm -f /run/user/1000/chronos.sock; sleep 1
RUST_LOG=info nohup ./target/release/chronos > /tmp/t182/run-<пункт>.log 2>&1 &
```
Отдельный лог-файл на каждый проверяемый пункт, не один общий — так проще
доказать, какая строка от какого прогона.

## Что проверить

### §5.1 — Build без активного проекта

Временно убрать `active = "..."` из `~/.config/chronos/projects.toml`
(бэкап в `/tmp/t182/`, **обязательно вернуть после**, `diff` до/после в
отчёт). Перезапустить ChronOS со своим логом. Открыть панель → Build.
Кадр. Открыть кадр глазами — на нём должна быть панель ChronOS с Build
вкладкой в состоянии «нет проекта», не что-то другое.

### §5.2 — Build: провальная задача

Игрушечный cargo-проект в `/tmp/` (НЕ в дереве ChronOS) с умышленной
ошибкой типа в `main.rs`. `active` в `projects.toml` временно указывает
туда. Перезапуск, Build вкладка, кадр — код ошибки виден. Конфиг вернуть,
`diff` в отчёт.

### §5.4 / §5.5 — Preview: бинарь / .html

Открой Files, сними кадр, **прочитай координаты нужной строки с этого
кадра** (не бери из таблицы выше — они там нет, только для рейла).
Клик по `target/release/chronos` — Preview должен показать отказ с типом
файла и размером, не крэш и не пустое. Повтори для `.html` (создай мелкий
`test.html` где-нибудь в дереве, если рядом нет готового) — ожидание:
`unavailable` с причиной.

### §5.7 — Files: /root

Тем же приёмом (кадр → координаты с кадра → навигация) зайти в `/root`.
Ожидание: честная ошибка прав, не крэш, не тихий пустой список.

### §6.1 — Отмена задачи в Build через UI

Запусти реальный `cargo build` на достаточно медленном проекте (сам
ChronOS подойдёт, `cargo clean` перед этим, если нужно время на клик),
через UI. Сними кадр с кнопкой Cancel, прочитай координаты с кадра, клик.
`pgrep cargo`/`pgrep rustc` до и после — процесс должен умереть, не
осиротеть.

### §6.3 — Дельта размера бинаря без фичи `markdown`

`gpui-component` в воркспейс-Cargo.toml — временно `markdown = []` вместо
дефолта. Сборка **release**. Предыдущие попытки упирались в 5-минутный
таймаут на инкрементальной сборке с грязным `target/` — в этот раз либо
`cargo clean -p gpui-component` перед сборкой без фичи (не весь workspace),
либо фоновый nohup с большим таймаутом и доказательством, что процесс
реально шёл (растущий лог компиляции, не мгновенный обрыв). Два `ls -la`
(с фичей / без), разница в отчёт. Ориентир для сравнения: T157 мерил
`Input` +1.84 MiB, `Table` +199 KB. **Cargo.toml вернуть после замера**,
`git diff` пуст в отчёте.

## Как отчитываться

- каждый пункт — **PASS / FAIL / НЕ ПРОВЕРЕНО с причиной**; «не проверено»
  с честной причиной — законный и принимаемый ответ, цена ноль;
- команда и её вывод целиком, не «проверено ✅»;
- **кадр — только тот, что ты сам открыл и посмотрел, что на нём.** Если
  не уверен, что на кадре ChronOS, а не что-то другое — не клади его в
  отчёт, пиши «не проверено, кадр не подтверждён»;
- если делаешь несколько кадров для разных состояний — их `md5sum` в
  отчёт, разные суммы явно;
- лог целиком: `grep -n "panicked at"`;
- любой временный конфиг/файл — откатить, `diff`/`git status` в отчёте.
