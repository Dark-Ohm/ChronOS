# T251 — Hyprland binds: консистентное визуальное разделение групп

**Приоритет:** P2.
**Роль:** FRONTEND (Rust, GPUI), мелкая правка.
**Источник:** `docs/orchestration/tasks/report-log/T223-design-audit-report-v4-reshoot.md`
находка #4 (табл. §3), топ-10 п.6.

## Контекст

`crates/app/src/side_panel_right/tab/hypr_binds.rs` уже частично
использует паттерн `ui::section_header()`
(`crates/app/src/side_panel_right/tab/ui.rs:54`) — строка 209:
`card = card.child(ui::section_header(theme, &group, &file));`. Группы
без явных метаданных (`-- # group = "..."` комментария в конфиге)
получают fallback `"Custom"` (`parse_group()`, строка 305-318).

Аудит: на кадре `10-tab-hyprlandbinds-dark.png` список биндов —
плоская стена строк, между секциями (конкретно `Custom`) нет
визуального разделения кроме заголовка. Панель открывается на 320px
(< `GRID_BREAKPOINT=720`), так что 1-колоночный список — ожидаемое
поведение, находка не про grid, а именно про то, что `section_header`
для `Custom`-группы визуально не выделяется так же чётко, как для
именованных групп (нужно сравнить живьём, чем `Custom`-рендер
отличается от именованной группы — возможно, дело не в самом
`section_header`, а в том, что несколько `Custom`-групп из разных
файлов визуально сливаются друг с другом, раз у всех одна и та же
метка).

## Что нужно

1. Живым grim/чтением кода разобраться, ПОЧЕМУ конкретно `Custom`-секции
   визуально не разделены (не гадать — открыть кадр
   `10-tab-hyprlandbinds-dark.png`, если сохранился в evidence pack,
   иначе переснять `select-tab:hyprlandbinds`).
2. Вероятные фиксы (выбрать по факту находки): (а) добавить
   разделитель/отступ между последовательными `elevated_card`-блоками
   разных `Custom`-групп, если сейчас они визуально сцеплены; (б) если
   несколько `Custom`-групп из разных модулей — включить имя файла в
   подпись (`section_header` уже принимает `subtitle` — передаётся ли
   туда имя файла сейчас? проверить строку 209 контекст).
