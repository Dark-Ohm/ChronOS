# T218 — Ресайз только у Editor и System settings, остальные вкладки фиксированы

**Статус:** код в дереве (архитектор, некоммичен), **ждёт приёмки**  
**Источник:** live dogfood 2026-08-03 — «отменить ресайз во всех вкладках кроме
настроек и блокнота, чтоб у вкладок была своя НАТУРАЛЬНАЯ ширина»  
**Зависимость:** поверх T216 (абсолютная модель drag'а), те же файлы

## Правило

Тянуть ширину можно только там, где полезная ширина — дело вкуса:

| вкладка | `PanelTab` | натуральная | ресайз |
|---|---|---|---|
| Editor (блокнот) | `Preview` | 560 | **да** |
| System settings | `EditorSettings` | 320 | **да** |
| System | `System` | 400 | нет |
| Files | `Files` | 440 | нет |
| Hyprland binds | `HyprlandBinds` | 320 | нет |
| ACP agents | `AcpSettings` | 320 | нет |
| остальные из `ALL` | — | по `preferred_content_width` | нет |

## Что сделано

- `tabs.rs` — `PanelTab::resizable()`: `matches!(self, Preview | EditorSettings)`.
- `view.rs::active_tab_width` — фиксированная вкладка **игнорирует**
  `tab_resize_memory` целиком, чтобы ширина, записанная до заморозки или случайным
  drag'ом, не могла удержать её не на своём размере.
- `view.rs::start_resize` — раскрытие rail → content по-прежнему работает для
  **всех** вкладок (это то, чем открывается контент), но якоря drag'а взводятся
  только для ресайзных; фиксированные пишут в лог `tab is fixed width, drag ignored`
  и выходят.
- `view.rs` render — у ручки на фиксированной вкладке нет ни `cursor_col_resize`,
  ни `on_drag`/`on_drag_move`. Сама 4px-колонка остаётся в раскладке всегда:
  rail-only ширина = rail + handle, и mouse-down по ней открывает контент.
- `view.rs::sim_resize` — тестовый хелпер повторяет отказ, чтобы тест не мог
  записать ширину, которой UI никогда бы не произвёл.

## Приёмка

```bash
cargo test -p chronos --lib side_panel_right     # 142 passed
```

Тесты, закрывающие правило (зовут настоящий код, не переписывают логику в себе):

- `tab::tests::fixed_width_tab_keeps_its_natural_width` — drag не двигает Files,
  уход и возврат сажают её ровно на `preferred_content_width`;
- `tab::tests::switch_tab_restores_per_tab_resize_memory` — перенацелен на Preview:
  память ширины по-прежнему работает там, где ресайз разрешён;
- `view::tests::mode_fallback_applies_fixed_system_width` — переименован из
  `..._restores_system_resize_memory`, потому что System теперь фиксирована и
  обязана игнорировать записанную ширину.

**Остаточное:** прогон делался синтетическим `ydotool`, который телепортирует

Модель их не накапливает — следующее событие возвращает верную ширину, — но
подтверждение живой рукой за пользователем.
