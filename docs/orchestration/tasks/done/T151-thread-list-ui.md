## Сейчас

`sessions_list.rs` — 18 строк: `SessionItem { id, title, active }` и четыре
константы ширины. Список живёт в памяти (`SidePanelLeft::sessions`),
заголовки генерируются как `format!("Session {}", len + 1)`
(`mod.rs:237`), при перезапуске всё исчезает, переключение между записями
не восстанавливает разговор — потому что восстанавливать неоткуда.

После T150 появляется хранилище (SQLite, `~/.local/share/chronos/threads/`)
и две ACP-команды: список сессий агента и загрузка сессии с реплеем истории
потоком событий.

## Что сделать

1. **Список тредов из хранилища.** Сайдбар показывает реальные треды:
   заголовок, время последнего обновления, значок агента-владельца
   (у нас несколько агентов — `agents.toml`). Порядок: закреплённые сверху,
   дальше по `updated_at` убыванию. Архивные — скрыты за переключателем.
2. **Открытие треда восстанавливает разговор.** Клик по треду →
   `load_session` у агента-владельца → события реплея наполняют транскрипт
   ровно тем же путём, которым идёт обычный стрим (`StreamingEvent`,
   обработчик в `composer.rs`). Пока реплей идёт — видимое состояние
   загрузки, а не пустой экран.
   **Кэш из хранилища показывается сразу**, реплей его замещает. При
   расхождении прав агент — так решено в `docs/DECISIONS.log`.
3. **Автозаголовок.** Первый промпт пользователя даёт имя треду (первая
   строка / ~60 символов, без переносов). `Session 3` как имя — то, от чего
   уходим.
4. **Переименование, пин, архив, удаление** — контекстное меню или кнопки
   на строке. Переименование пишет `title_override`, он побеждает
   автозаголовок.
5. **Поиск по тредам** — поле над списком: фильтрует по заголовку и по
   содержимому (в T150 для этого предусмотрен поиск в хранилище). Показывай,
   что именно совпало, если совпадение в теле, а не в заголовке.
6. **«+» создаёт тред явно** — новая запись в хранилище + новая ACP-сессия,
   без потери текущей: старая остаётся в списке и открывается обратно.

## Приёмка — только живьём, кадрами

1. Перезапуск шелла: `chronos-stop && chronos-start` — треды на месте,
   заголовки настоящие. **Кадр `grim` до и после перезапуска.**
2. Открытие старого треда: разговор восстановлен (видно прошлые сообщения),
   в логе — `session/load` и поток событий реплея. Кадр + строки лога.
3. Переименование переживает перезапуск. Кадр.
4. Поиск: запрос, попадающий в тело сообщения, находит тред. Кадр.
5. «+» при живом треде: старый не исчез, переключение туда-обратно
   работает. Кадр.

Геометрия слоя для кадра — `hyprctl layers`, namespace `side_panel_left`
(`grim -g "0,30 352x1410"` при текущей раскладке). Нет доступа к живому
сеансу — пиши «за архитектором», это принимается.

## СРОЧНО (2026-07-29, ночь): твоя миграция сломала сборку всего шелла

`sessions_list.rs` в рабочем дереве уже переписан на

```rust
pub struct ThreadListItem {
    pub record: ThreadRecord,
    pub active: bool,
}
```

а `panel.rs` остался в состоянии HEAD и читает снятые поля:

```
panel.rs:53   .map(|s| s.title.clone())
panel.rs:636  let title = s.title.clone();
```

Итог — `cargo build -p chronos` падает: 4 × `E0609` (нет полей
`title`/`id`) плюс 2 × `E0502` в `mod.rs`. **Это блокирует не только тебя:
на этом встал замер T157**, который собирает тот же бинарь.

### Что сделать в первую очередь, до остальной работы

1. Довести миграцию до конца в `panel.rs`: `s.title` → `s.record.title`
   (или через хелпер отображаемого заголовка, который ты уже завёл —
   `title_override` должен побеждать), `s.id` → `s.record.id`.
2. Разобрать `E0502` в `mod.rs` — `*self` заимствуется изменяемо при живом
   неизменяемом заимствовании. Предыдущий заход T157 пробовал лечить это
   через `+ use<>` и получил каскад `E0521`/`E0499`; вероятно, нужен
   рефактор `build_sessions_sidebar`: вынести `cx.listener(...)` в
   `render_panel` и передавать готовые обработчики параметрами.
3. `cargo build -p chronos` должен стать зелёным **до** того, как ты
   продолжишь UI. Незелёное дерево — общий ресурс, в нём работают другие.

Правило на будущее: миграция типа, затрагивающая соседние модули, делается
одним заходом до зелёной сборки, а не оставляется на ночь в рабочем дереве.
Если нужен промежуточный сон — коммить в свою ветку или уходи в worktree.
