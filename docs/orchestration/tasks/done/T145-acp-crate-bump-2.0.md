# T145 — ACP: перейти с альфы 0.11.1 на релиз 2.0.0

**Статус:** active, агент не назначен
**Блокировка:** **не начинать, пока T143 не закрыт** — зоны файлов те же
(`crates/services/src/hermes_acp/`), там сейчас Hermes с заходом 2.
**Порядок:** T143 → **T145 (эта)** → T144 (модели поверх новой версии).

---

## Зачем

Мы сидим на `agent-client-protocol` / `agent-client-protocol-tokio`
**0.11.1** — это предрелизная ветка. На crates.io с 2026-07-23 доступен
**2.0.0**, первый стабильный мажор; между нами и им 1.0 → 1.6 плюс сам
мажор. Деп-политика проекта (CLAUDE.md, «bleeding edge, чужие пины не
наследовать») прямо требует свежести, и весь ACP-фронт сейчас активно
строится — чем дольше тянем, тем дороже миграция.

**Важно понимать, чего этот бамп НЕ даёт.** Он не чинит пустой список
моделей (T144): в 2.0.0 `ActiveSession` так же не хранит `models`, а
`response()` так же собирает `NewSessionResponse` без них — проверено по
исходникам 2.0.0 на docs.rs. Не завышай ожидания в отчёте.

## Что известно про изменения (из release notes)

Проверять по факту, это только ориентир:

- **1.3.0** — стабилизированы boolean session config options; `session/load`
  и `session/resume` объединены; переименования ID-типов ради
  консистентности; ужесточены требования к session-методам; более гибкая
  обработка permission-запросов; контент-типы выровнены под MCP.
- **1.4.0** — описания в enum элиситаций.
- **1.5.0** — v2 semantic string types (unstable); diff-payload `patch`
  переименован в `text`; v2 terminal output; гейтинг auth-методов.
- **1.6.0** — capability на именование тул-коллов (unstable); вариант
  `cancelled` у тул-коллов и пунктов плана.
- **2.0.0** — мажор; полный список изменений снять самому.

Наши точки касания, которые почти наверняка зацепит:
`transport.rs` (`InitializeRequest`, `ClientCapabilities`,
`FileSystemCapabilities`, `Implementation`, `on_receive_request`,
`AcpAgent::with_debug`/`LineDirection`), `client.rs` (`ActiveSession`,
`SessionMessage`, `MatchDispatch`, `SessionUpdate`, `ToolCallStatus`,
`SetSessionModelRequest`), `session.rs`, `crates/services/Cargo.toml`
(фичефлаги `unstable_session_model`, `unstable_session_usage` — проверить,
не стабилизировались ли и не переименовались).

## Что сделать

1. Поднять обе зависимости (`agent-client-protocol`,
   `agent-client-protocol-tokio`) до 2.0.0, снять/переименовать
   фичефлаги по факту.
2. Починить компиляцию **по-честному**: если API исчез — найти замену в
   новой версии, а не глушить `#[allow]`, `let _ =` или заглушкой.
   Каждое неочевидное решение — строкой в отчёт.
3. Не менять поведение. Эта задача — миграция, не улучшение. Любой
   соблазн «заодно поправить» — в отчёт как предложение, не в код.
4. Отдельно проверить, что `unstable_session_usage` (без него чат
   умирал на десериализации — см. комментарий в `Cargo.toml`) имеет
   аналог в 2.0.0. Если он стабилизировался — убрать флаг, оставив
   комментарий-историю.

## Приёмка

1. `cargo build --release -p chronos --bin chronos` — зелёный.
2. `cargo test -p chronos --lib` — не хуже, чем было (42 passed на
   2026-07-27).
3. **Живой прогон** релизного бинаря, `RUST_LOG=info`: коннект к Hermes,
   создание сессии, turn с тулом (создать файл), стриминг текста и
   reasoning, автоапрув пермишенов, тул-карточки, отмена по Stop.
   Всё, что работало до бампа, обязано работать после — это регрессионный
   чек-лист, а не формальность.
4. Кусок живого лога в отчёт: `ACP connection initialized`,
   `ACP session started`, `ACP raw: ToolCall`, `turn END`.

Компиляция без живого прогона по этой задаче не принимается: половина
изменений 1.x — это протокольная семантика, компилятор её не ловит.
