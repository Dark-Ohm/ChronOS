## Несколько независимых `on_click` (вопрос 4 разведки)

**Прецедента в дереве нет** — это первый виджет бара с тремя отдельными `div` + `on_click` в одном `render()`:
- `div#workspace-mode-prompt-yes` → `accept_prompt`
- `div#workspace-mode-prompt-no` → `dismiss_prompt(false)`
- `div#workspace-mode-prompt-never` → `dismiss_prompt(true)`

Каждый `div` получает уникальный `.id()` — без этого GPUI хеширует контент и может слить обработчики. Ближайший прецедент (`dock.rs`) — один элемент с двумя типами событий, не то же самое.

**Event bubbling:** в GPUI `on_click` на дочернем `div` не всплывает к родительскому — подтверждено поведением dock.rs. Пилюля и плашка — siblings в одном `row`, не parent-child, поэтому клик по «Да» не может триггерить `toggle`. `stop_propagation()` не потребовался.

**Это НЕ проверено живьём** — требуется grim-кадр с кликом по «Да» и проверкой, что режим не переключился дважды.

### Находка: виджет не появляется у существующего пользователя

Живой прогон показал бар **без переключателя**, хотя код верен.

Причина не в T161, а в том, чего не учёл план: `BarLayoutConfig::load()`
читает `~/.config/chronos/bar.toml`, и **если файл существует, дефолтный
вектор не применяется никогда**. У этой машины файл есть с 30.07 (сохранён
edit-mode'ом T134) и списка `workspace_mode` в нём, разумеется, нет.

Практический смысл: **на любой машине, где пользователь хоть раз трогал
раскладку бара, новая фича невидима.** Добавления в `Default` недостаточно.
Это не дефект кода задачи — это дыра в критерии приёмки, который я сам
написал («виджет виден в баре»), и её надо закрывать отдельно: либо
одноразовой миграцией (при загрузке дописывать отсутствующие новые builtin),
либо явной строкой в документации «добавь виджет в свой `bar.toml`».
Выношу решение в отдельную задачу, T161 за это не отвечает.

### Что осталось непроверенным — честно

**Плашка предложения и event bubbling.** Вызвать её нечем: `request_switch`
дёргается только из кода, детектора нет по замыслу слайса, IPC-команды для
неё не предусмотрено. Утверждение отчёта, что клик по «Да» не всплывёт к
пилюле, обосновано **аналогией с `dock.rs`**, а не наблюдением — и аналогия
шаткая: там два типа события на одном элементе, здесь отдельные `div`.
Исполнитель это отметил сам, и правильно сделал.

Уходит в T162 (QA) с явным требованием: временный env-гейт с разовым
`request_switch` в `init`, кадр плашки, клик по «Да» и доказательство, что
режим сменился ровно один раз. Временный вызов не коммитить.
