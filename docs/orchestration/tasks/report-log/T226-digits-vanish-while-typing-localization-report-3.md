## Итог

**Терминал — кадры НЕВАЛИДНЫ.** `desktop-terminal` — это layer-shell surface
на уровне **background** (`hyprctl layers` → `Layer level 0`), самый нижний
z-order. Любое замапленное окно (тайловый терминал, браузер) или video-wallpaper
демон (`gslapper`) рисуется ПОВЕРХ и полностью перекрывает слой. `grim` снимает
не терминал, а то, что реально сверху. **Геометрия захвата была верной** — баг
не в `grim`, а в физике background-слоя. Чтобы снять терминал, нужен пустой
воркспейс (без замапленных окон).

**Левая панель (композер агента) — НЕ ПРОВЕРЕНО.** Панель открыта через IPC в
rail-only (40px), развернуть до чата/композера не удалось: ydotool-клики не
регистрируются GPUI-окнами (известный баг сессии, см. HANDOFF).

**Правая панель (Editor + gutter) — НЕ ПРОВЕРЕНО.** Текущая вкладка — System
settings (400px). Переключиться на Editor без рабочих мышиных кликов невозможно.
PreviewTarget через IPC не выставляется.

## Инфраструктурные дыры

### Закрыта: `grim` по геометрии слоя
`grim -g "X,Y WxH"` с координатами из `hyprctl layers` **работает** — кадр
попадает точно в нужный слой. Проблема не в `grim`, а в z-order background-слоя.

### Закрыта: `wtype` для клавиатурного ввода
`wtype` надёжно доставляет текст через Wayland virtual keyboard. Для терминала
ввод был доставлен (подтверждено изменением размера кадра), но сам кадр
перекрыт.

### Закрыта: калибровка `ydotool`
Абсолютное позиционирование: `ydotool mousemove -a -x X -y Y` с коэффициентом
2× (реальные координаты = параметры × 2). Верифицировано через `hyprctl cursorpos`.

### Остались открытыми:

1. **ydotool-клики в GPUI-окна не работают** — та же проблема, что блокировала T219/T221/T229 live smoke (HANDOFF). Нужен ребут или альтернатива.
2. **`desktop-terminal` на background-слое** — для снятия кадра нужен пустой воркспейс. Переключиться можно через `hyprctl dispatch workspace <пустой>`.
3. **Нет IPC для PreviewTarget** — нельзя программно открыть файл в Editor.
4. **Левая панель открывается rail-only** — `CHRONOS_SMOKE_SIDE_PANEL_LEFT` открывает панель, но не разворачивает чат до композера.

## Следующий шаг (попытка #4)

Три попытки не долокализовали баг. Попытка #4 упёрлась в два блокера:

1. **`hyprctl dispatch` мёртв в Lua-конфиге 0.56.1.** Ни одна команда
   (`workspace`, `movetoworkspace`, `focusworkspace`, `moveworkspacetomonitor`)
   не работает — все возвращают «attempt to call a nil value». Диспатчи живут
   в `hl.dsp.*` Lua-биндах и недоступны через CLI. Нельзя ни переключить
   воркспейс, ни убрать окно с терминала.
2. **ydotool-клики мёртвы для GPUI.** Та же проблема, что в HANDOFF.

**Без ребута (ydotool) ИЛИ без инфраструктурных правок (IPC + auto-expand)**
дальнейший автоматический smoke невозможен. Три варианта:

- **Ребут** — может починить ydotool-клики и dispatch (если это uinput/kernel mismatch).
- **Инфраструктурные правки:** IPC `preview-target:<path>` + `ensure_chat_width()`
  при `CHRONOS_SMOKE_SIDE_PANEL_LEFT`. Тогда все три зоны достижимы без мыши:
  IPC открывает файл в Editor, левая панель разворачивается сама, а ввод везде
  через `wtype`. Цена: release-сборка ~10 мин.
- **Ручная верификация Архитектором** — физически переключиться на пустой
  воркспейс, набрать `123abc` в терминале, снять грим.
