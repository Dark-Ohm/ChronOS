## Находка подтверждена — на уровне кода, до grim

Мандатный «первый шаг» — живой `grim` вкладки binds крупным планом — я
выполнить не смог: у меня нет доступа к живому layer-shell окну шелла (нет
сессии/дисплея). **Не стал чинить вслепую по одному отчёту** — вместо этого
сверил исходник, и находка T223 подтверждается кодом напрямую:

`crates/app/src/side_panel_right/tab/hypr_binds.rs`, `load_all()` (до правки):

```rust
for (label, name) in [
    ("ChronOS", "25-binds-chronos.lua"),
    ("Kitchen", "20-binds-kitchen.lua"),
] { ... }
```

Заголовки секций в UI = `row.source`, который брался из этого хардкода — то
есть **ровно из имён/«стемов» файлов модулей**, а не из продуктовых категорий.
`Kitchen` — личное имя модуля автора. `TEXT-UNVERIFIED` в T223 снят: это
подтверждено по коду, не по кадру.

## Что изменено (только UI-отображение, конфиг не тронут)

`crates/app/src/side_panel_right/tab/hypr_binds.rs`:

1. **Метаданные вместо имени файла.** Новая чистая функция `parse_group(src)`:
   ищет в `--`-комментарии модуля `group = "Label"` и возвращает `Label`;
   фолбэк — `"Custom"`. Никогда не возвращает имя/стем файла.
2. **`load_all()` переписан.** Читает **все** `*.lua` под `~/.config/hypr/modules/`
   (не хардкод двух), сортирует по имени для стабильного порядка, группу каждой
   строки берёт из `parse_group`. Не-bind модули (monitors/autostart/windowrules)
   дают 0 строк естественным образом. Monolith-фолбэк (`hyprland.lua`) тоже
   отдаёт `"Custom"` — не сырое имя файла.
3. Группировка в `render` работает по этим категориям (как раньше по `source`).

**Канон соблюдён:** сами `.lua`-модули пользователя не переименовывались и не
правились. Маппинг имя-файла→категория — только на уровне отображения.

> **Следствие для текущего конфига автора:** ни в одном из `~/.config/hypr/modules/*.lua`
> сейчас нет комментария `group =` → обе группы биндов сольются в один заголовок
> `"Custom"`. Это честный фолбэк по ТЗ: `Kitchen`/сырые имена больше не светятся.
> Чтобы вернуть продуктовые категории (например `"ChronOS"` / `"Apps & Media"`),
> автору достаточно добавить `-- # group = "..."` в нужный модуль — это его конфиг,
> сам я его не трогал.

## Тесты

`cargo test -p chronos --lib hypr_binds` → **11/11 ok** (7 старых + 4 новых):

- `group_metadata_comment_is_used_as_source_label` — `-- # group = "Apps & Media"`
  становится заголовком секции.
- `missing_metadata_falls_back_to_custom` — без метаданных → `"Custom"`,
  имя/стем файла (`kitchen`) в label не протекает.
- `group_ignored_in_code_but_read_in_comment` — `group =` вне комментария не читается.
- `group_missing_when_unquoted` — незакавыченное значение → `"Custom"`.
