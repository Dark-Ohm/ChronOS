## 1. Вердикт

**Полуфабрикат с одним настоящим продуктовым пятном обмана.** Визуальная
система (токены, grid, elevation, T231-редизайн) — уже честный, консистентный
язык на уровне отдельных карточек. Но дефолтный, самый первый экран
(System-таб) показывает **фейковый диалог разрешений**, который ничего не
делает — это не «недоделанная фича», это активно вводящий в заблуждение
элемент интерфейса, и он на первом экране, не спрятан. Это решает исход
теста доверия против продукта раньше, чем начнётся разговор про grid и
отступы.

## 2. Четыре теста аудитории

**Тест первого кадра.** Кадр `07-tab-system-dark.png` (System-таб,
дефолтный экран после открытия правой панели) не пойдёт в пост на
r/unixporn — верхняя треть кадра занята диалогом «Claude Code / Allow /
Deny», который выглядит как реальный system-permission popup (рамка, две
кнопки с hover-стилями, синий акцент на «Allow»), но architecturally
статичен (`permission.rs:1` — «no backend wiring»). Человек либо решит, что
скриншот демонстрирует баг («приложение спрашивает разрешение на
произвольную команду от лица Claude Code» — это ещё и просто пугающе для
незнакомого зрителя), либо кликнет и ничего не произойдёт — оба исхода
роняют доверие быстрее, чем плохой отступ. `01-bar-full-dark.png` (просто
бар) — наоборот, годный первый кадр: чистый, минималистичный, тёмная
Catppuccin-палитра читается сразу.

**Тест первого комментария.** «Зачем это вместо Waybar+rofi+dunst?» — ответ
частично следует из кадров: конфиг-центричность видна (`12-tab-
editorsettings-*` — bar.toml с live-apply пресетами, Hypr modules с прямым
редактированием), агент слева (`13-left-panel-open-*`) — это то, чего у
Waybar нет в принципе. Но ответ **не закрыт полностью**: левая панель на
кадрах пуста («No messages yet»), сам факт «агент слева отвечает» —
недоказан ни одним кадром этой волны (см. §6, попытка снять живой ответ не
удалась). Пока это на слово, не на скриншоте.

**Тест рицера.** Читается хорошо: `bar.toml` с пресетами и live-apply
(`Presets`/`Appearance`/`Hypr modules` карточки на `12-tab-editorsettings`),
mono-подписи путей конфигов (`appearance.edge`, `~/.config/hypr/modules/`)
— явный сигнал «это текстовый конфиг, не чёрный ящик». Годно.

**Тест доверия.** Формально — да (нет сети/телеметрии по архитектуре,
`docs/PRODUCT.md` §«Кто судит»). **Но именно здесь фейковый permission-мок
бьёт больнее всего** — он ИМИТИРУЕТ ровно то, чего продукт обещает не
делать (спрашивать разрешение на выполнение произвольных команд от лица
стороннего AI-агента). Пользователь, не знающий, что это мок, увидит
надпись «Claude needs your permission to run a command» на дефолтном
экране своего десктопного шелла и обоснованно испугается. Это П0 по
дефолту теста доверия, не полировка.

## 4. Системные проблемы

- **Непоследовательная плотность контента между вкладками правой панели.**
  System (перегружен фейковым моком + пустой mpris-карточкой) vs ACP agents
  (голая пустота внизу) vs Files/Editor settings (плотно, честно, к месту)
  — три разных подхода к «что показывать, когда нечего показывать» на трёх
  соседних вкладках одной панели. `T231`-паттерн (`elevated_card` +
  `section_header`) уже унифицировал ВИЗУАЛЬНЫЙ язык карточек, но не унифицировал
  РЕШЕНИЕ «пусто ли содержимое достаточно ценное, чтобы занимать место».
- **Динамическое расположение бара между мониторами без явного индикатора.**
  Между рестартами `chronos` бар/панели могут оказаться на другом мониторе
  (в этой сессии — переехали с DP-1 на HDMI-A-1 без пользовательского
  действия, «pult display» логика). Не тестировал специально, но раз это
  случилось дважды за одну ночь без моего участия — стоит поверхностной
  проверки: детерминирован ли выбор монитора, и объясняет ли UI, почему
  шелл «переехал», или это выглядит как случайный баг для пользователя с
  несколькими мониторами.

## 5. Топ-10 «если есть один день»

1. **Убрать/заменить фейковый permission-мок в System-табе** (находка 1) —
   P0, самый быстрый и самый дорогой по ущербу фикс за минимум работы
   (буквально удалить один `render_permission_card()` вызов или обернуть
   честной надписью «demo card, not wired»).
2. Свернуть пустую `No player` mpris-карточку в компактное состояние
   (находка 2).
3. Разобраться с `compose-and-send` не-сабмитом + width-desync левой
   панели (находка 5) — это блокирует буквально единственное
   продуктовое доказательство «агент отвечает».
4. Заполнить или сжать пустой низ ACP agents-вкладки (находка 3).
5. Убрать голый zsh-wizard из desktop-terminal (находка 6).
6. Применить `section_header`-паттерн к группам Hyprland binds
   консистентно (находка 4).
7. Досъёмка оставшихся 8 пунктов брифа (клавиатурный виджет, редактор
   edit mode, dropdown модели, OSD, трей, drag-ручка, hover-strip peek,
   Gamer-рейл) — требует починки синтетического ввода (`ydotool`), но пока
   этого нет — реального продукта в этих зонах никто не видел, включая
   меня.
8. Разобраться, детерминирован ли выбор монитора для бара при рестарте,
   и если нет — либо зафиксировать поведение, либо явно спросить
   пользователя/запомнить прошлый выбор.
9. Кадр `07-tab-system` (после фикса находки 1) — переснять и заново
   оценить, держит ли он тест первого кадра сам по себе (CPU/RAM/GPU
   виджеты + диски — контент прилично выглядит, вероятно да).
10. Пройтись по всем вкладкам правой панели единым чек-листом «что
    показываем, когда нечего показывать» — не точечно чинить пустоты, а
    решить один раз на уровне паттерна (см. §4).
