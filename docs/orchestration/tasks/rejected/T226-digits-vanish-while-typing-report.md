## Что анализировалось

Три кодовых пути, три кандидата:

### 1. Слой ввода — композер агента (левая панель)

**Файл:** `crates/app/src/side_panel_left/text_input.rs`
**Класс:** `TextInputState`, `TextInputElement`
**Ключевой метод:** `replace_range()` (line 78)

```
self.content = (self.content[..range.start].to_owned()
    + new_text + &self.content[range.end..]).into();
```

**Гарды:** `replace_text_in_range` и `replace_and_mark_text_in_range` в `mod.rs:233-267` блокируют ввод при `search_focused || composer_model_dropdown_open`.

**Вердикт:** Маловероятен. Если `replace_range` ломался бы, цифры физически удалялись бы из буфера — а не просто исчезали визуально. Тот же баг не воспроизводится в композере (по условию задачи).

### 2. Шрифт/шейпинг/атлас (T215)

**Файл:** `crates/app/src/theme_config.rs:130-136`
**Настройка:** JetBrains Mono в `font_family` + `mono_font_family`
**Статус шрифта:** Установлен (`/usr/share/fonts/TTF/JetBrainsMono-*.ttf`)

```
gpui_theme.font_family = mono.clone();
gpui_theme.mono_font_family = mono;
```

**Вердикт:** Семейство на месте, фолбэк отпадает. Но если шейпинг-движок GPUI криво обрабатывает смешанные раны (digits + letters), цифры могут рендериться с нулевой шириной или за пределами контейнера. Это объясняет «исчезают после буквы» — буква запускает новый шейп, цифры в нём «схлопываются».

### 3. Гуттер vs буфер (T214)

**Файл:** `crates/app/src/theme_config.rs:121-139`
**Покраска:** Активная строка `interactive.hover.opacity(0.5/0.4)`, номер `accent.primary`

```
let active_line = shell.interactive.hover.opacity(if dark { 0.5 } else { 0.4 });
highlight.style.editor_active_line = Some(active_line);
highlight.style.editor_active_line_number = Some(active_num);
```

**Вердикт:** Активная полоса рисуется **поверх** номеров строк. Если она также ложится поверх текста (z-order), то на строке с кареткой цифры блёкнут — и выглядит как «исчезают, когда печатаю». Это самый правдоподобный кандидат, потому что:
- Баг описан как «исчезают **после** буквы» → каретка на строке с цифрами
- Полоса T214 рисуется на той же строке, где стоит каретка
- Гуттерные цифры были покрашены в `accent.primary` / `text.primary` —但如果 полоса лежит поверх, они становятся невидимы

## Дополнительные уточнения

1. **Раскладка:** Повторить на EN и RU. Если ломается только при переключении — это IME/preedit.
2. **Цифры где именно:** Исчезают цифры **в тексте** или **номера строк в гуттере**? Снять кадр с явно видимым гуттером.
3. **Как именно исчезают:** Становятся невидимыми (цвет фона = цвет текста) или физически удаляются из буфера? Проверить Ctrl+A → копировать → вставить в терминал.

## Гипотезы по приоритету

1. **[Наиболее вероятная]** Гуттер/активная полоса T214 — z-order: полоса рисуется поверх текста на строке с кареткой. Цифры на этой строке блёкнут.
2. **[Возможная]** Шейпинг смешанных ранов в gpui-component Input — цифры рендерятся с нулевой шириной при смене шрифтового рана.
3. **[Маловероятная]** Коррупция данных в `TextInputState::replace_range` — но тогда цифры были бы физически удалены из буфера.
